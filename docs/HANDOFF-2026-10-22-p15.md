## 2. 三个必须先知道的纠错（不改这三点，后面全是白工）

| # | 上一轮的说法 | 实测事实 |
|---|---|---|
| 1 | 关键路径在 `pangoriscv.v` 的 `rr_rs1/hold_ex/br_miss` | **错一半**：`soc_config.vh` 默认 `define CORE_RV32`，`pangoriscv_axi_top.v` 用 `ifdef` 选 **`rtl/core/rv32/rv32_top.v`**。`pangoriscv.v` 不进综合。改它对位流零影响 |
| 2 | fmax = 40.6 MHz（= 24.65 ns 路径） | 这是 **40 MHz 约束**下的结果，placer 有 16 ns 松弛，根本不优化。换成 8.333 ns 约束做 place-only，工具能把最差路径摆到 **19.4 ns**（−11.055 ns）。真实结构上限 ≈ **51 MHz** |
| 3 | 拆流水 +1 拍 = 88k ticks/20it（2.3%） | 实测 **mispredict 68,827/20it = 3,441/迭代** ⇒ +1 拍 = **+1.8%** ⇒ 5.12 < 5.2。量级不同，**结论相同**：任何 +1 拍都不可接受 |

## 3. 本轮已落地（提交 `76b98cf`）

**S2：`br_miss` 去掉 `!hold_ex`**（`rv32_top.v`）。原来这条 lane-0 误预测重定向被
`hold_ex` 门控，而 `hold_ex ⊃ mem_wait ⊃ dcache early_req ⊃ mem_addr ⊃ ALU`，
于是 **D-cache 的请求路径被塞进了通往 I-cache 读出的同一个周期**（5 跳 / 4.4 ns）。

为什么可以摘：`ex_is_mem` 需要 `rr_load/rr_store`（与 `is_ctrl` 互斥译码）；
`ex_is_mem_h` 自带 `!ctrl_miss_now`，而 `ctrl_miss_now = rr_valid && is_ctrl && ctrl_miss_w`
**正是 `br_miss` 的触发条件**——所以该重定向能拉高的每一个周期里 `mem_wait` 恒为 0。
只保留 `trap_wait`（trap 优先级）和 `div_wait`（防御）。

验证：CoreMark 20it `Total ticks 3,833,976`、cycles 5,716,551、retires 7,025,687、
mispredict 68,827、CRC 0x4983 —— **与交付镜像逐位一致**；ISA e2e 20/21（case 21 基线即红）。

**踩过的坑（mistakes-log §50）**：先加了一个 `lane1_mem_raw` 的"防御项"，结果它反向生效，
在冻结周期挡住了合法重定向，CoreMark 在 retire 2855 处丢重定向、错路指令被退休。
**教训：给"去掉门控"打补丁时，别再加"看起来更安全"的与项。**

## 4. 120 MHz 的判决（三条硬数据，plan v10 §9）

1. **摆放上限 19.4 ns**（8.333 ns 约束、`-place_only`、无区域、seed 3）：
   工具从 post-GP 的 −23.1 ns 收到 −11.055 ns，已经用尽摆放手段。
2. **区域约束三种形状全部负优化**：横带 −11.0 / 竖带 −11.0 / **紧凑 2D 方块 −13.8**（本轮新做）。
   **这条路封死，不要试第四种形状。**
3. **CPI 预算只剩 0.32%**（608 ticks/iter），+1 拍要 3,441 ticks/iter。

⇒ 要 120 MHz 只能重写微架构（深流水 + 强预测 + 大 BTB），分数会掉到 3.5~4.0。

## 5. 工具用法（上一轮只用了 3 个参数，实际有一整套）

`pds_shell` 里 `puts [help pnr]` 直接导出完整选项表。可用的关键项：
`-dc_duplication`、`-logic_optimize_enable`、`-logic_optimize_lut6d_combing_strategy`、
`-dispose_dram_prior`、`-dispose_carrychain_prior`、`-place_worst_slack`、
`-refineplacement_mode/-iteration/-cluster`、`-slack_weight`、`-pin_cost_increasing_speed`。
**`-parallel`/`-gplace_times` 多种子并行需要多份 fabric license，单 license 下 8/8 全失败**
（`I: Running PnR with seed 21 failed`，无 `E:` 行，极易漏看）。

## 6. 环境坑（本轮踩到，会浪费半小时）

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `build_native_software.py` 报 `Missing tool` | 默认工具链路径指向不存在的 `firmware/toolchains/openisa-1.0.0` | 用 `--toolchain-bin D:/FPGA_Project/zi_guang_tong_chuang/toolchains/xpack-riscv-none-elf-gcc-15.2.0-1/bin --prefix riscv-none-elf-` |
| `tc1: unrecognized opcode csrr` | 新 binutils 把 Zicsr 拆出 | 加 `--extra-flag=-march=rv32im_zicsr`（必须用 `=` 形式，否则 argparse 当成选项） |
| `run_isa_e2e.py` 报 ModelSim 找不到 | 默认 `E:\donwload\win64` | `--modelsim "D:/FPGA_Project/Modelism/win64"` |
| `.sim_runs` 删不掉 / `Move-Item` 报"另一个进程在用" | 上一轮遗留的 6 个 `vsimk` 僵尸进程占句柄 | 先 `Stop-Process -Name vsimk`，还活着就重启后清 |

## 8. 下一步（按性价比）

1. **别再去碰 120 MHz**，除非准备重写微架构；先把"5.2 + 能路由的最高频率"钉死。
2. 若还要提频率：把 `-dispose_dram_prior TRUE` / `-plc_decongestion 2` 这条线走完
   （本轮最后一次实验），它针对的是"LUTRAM 阵列的 WADDR/CE 巨型交叉"。
3. 分数侧若要动：**只能动零 CPI 的东西**（扇出复制、组合逻辑重排），
   改完必须 `Total ticks` 逐位一致。
4. 报告用的三项口径（必须同源）：分数由 `Total ticks` 反推、频率用"约束通过 + 板上实跑"、
   LUT 取同一份 `device_map`。
