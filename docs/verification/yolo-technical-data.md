## 识别准确率：只有 18 张小样本实测，不能当整机准确率

**2026-11-04 补测**：在真实 v3 27 MHz 位流（SHA256 `2b98f90f…`）上跑了一组 18 张图的验证子集，结果落盘在
`evidence/records/validation_20261104/dataset_metrics/metrics.json`（`complete: true`）。

| 指标 | 实测值 | 说明 |
| --- | --- | --- |
| 样本量 | 18 张，127 个 GT 框，52 个预测框 | 预先固定的分层子集，`subset_sha256 = dc027b64…` |
| 工作点 | conf ≥ 0.25、NMS IoU 0.45、评测 IoU 0.50 | 类内、按分数降序、贪心一对一匹配 |
| AP@0.5（COCO 口径） | **32.78%** | `coco.ap50 = 0.3278327832783279` |
| AP@0.5:0.95 | 23.86% | `coco.ap50_95` |
| Precision（micro） | **42.31%**（TP 22 / FP 30） | 分母为 0 时按 0 计 |
| Recall（micro） | **17.32%**（TP 22 / FN 105） | 同上 |
| F1（micro） | 24.58% | |
| 各类 AP@0.5 | cardboard 66.34、metal 66.34、glass 51.49、biodegradable 12.54、**paper 0、plastic 0** | 六类物体标签；paper/plastic 在该子集上完全漏检 |

**引用时必须带这三个限定**：

1. **18 张、127 框是小样本**，只能说明"部署链路能出正确格式的检测框、且部分类别可检出"，不能外推成"整机识别准确率 32.78%"。
2. 子集与训练集同源，**未做训练/验证重叠审计**，存在乐观偏置的可能。
3. 模型是六类**物体**标签（biodegradable/cardboard/glass/metal/paper/plastic），不是四类**垃圾**标签。业务上只把第 0 类映射到厨余、第 1~5 类映射到可回收，所以"四类垃圾分类准确率"这个指标**不存在**，不要写。

**可以这样写**："在 18 张固定验证子集上，部署后 AP@0.5 为 32.8%、micro Precision 42.3%、micro Recall 17.3%；样本量有限且未做数据泄漏审计，不作为整机识别率对外承诺。"

**不能这样写**："识别准确率 32.78%"、"识别率达成 90%"、把单帧置信度 0.26 当成 26% 准确率。

> 2026-11-03 版此处写的是"mAP/Precision/Recall 全部未测得"。当时确实没有落盘的评测结果，说法没错；11-04 补测之后以本节为准。旧说法保留在 Git 历史里。

## 同位流 A/B：摄像头预处理优化

条件：同一 yolo120-006 位流、同一模型、运行选项 flags=63。UART 命令 10 切换旧/新预处理；每种模式先预热 1 帧，再统计 10 帧。端到端口径采用逐帧 `max(主机请求到回复耗时, 板端取图+推理+解码+显示提交周期/频率)`，之后对 10 帧取平均。包含取图及显示提交，不含一次性模型上传/CRC。显示提交耗时不等于屏幕完整刷新延迟。

| 指标 | 旧预处理 | 快速预处理 |
| --- | --- | --- |
| 测量样本 | 10 帧 | 10 帧 |
| 端到端平均 | 1.057596 s/帧 | 1.017300 s/帧 |
| 端到端中位数 | 1.058628 s/帧 | 1.016000 s/帧 |
| 端到端最小~最大 | 1.050516~1.063000 s/帧 | 1.015000~1.031000 s/帧 |
| 平均延迟对应吞吐率 | 0.9455 FPS | 0.9830 FPS |
| 板端取图/预处理平均 | 151.572 ms | 109.818 ms |
| 完整网络前向平均 | 887.912 ms | 887.598 ms |
| 解码平均 | 13.855 ms | 13.839 ms |
| 显示提交平均 | 2.687 µs | 2.676 µs |

- **端到端加速比：1.0396×**；平均耗时降低 **3.81%**。
- **取图/预处理阶段加速比：1.3802×**；阶段耗时降低 **27.55%**。
- 加速比=优化前平均耗时÷优化后平均耗时。两组为顺序测试，样本量小，未提供统计置信区间；不是纯 CPU 与 FPGA 卷积加速器的对照实验。

“约 1 秒识别一次”可作为实验刷新延迟描述。此前引用的 1.016~1.031 s 中 1.016 s 是该组中位数；原始 10 帧实际最小值是 **1.015 s**。本报告保留重算值，不重复把中位数当最小值。

## 硬件加速与资源

当前有 FPGA 卷积/MAC 阵列及 CPU 调度源码，但没有同模型同输入的“纯 CPU 完整推理”耗时基线，因此 **不能给出纯 CPU→FPGA 的整体硬件加速倍数**。120.461538/27 的时钟频率比也不等于算法加速比。

同一 yolo120-006 的 Device Map：LUT 25,683 / 66,600；FF 21,654 / 133,200；DRM 107.5 / 155；APM 124 / 240；Distributed RAM 290 / 19,900。这些是整个 AI 应用的映射资源，不是单个 CPU 或卷积模块的独立资源，更不能直接换算为 GOPS 或 CoreMark/LUT。

## 时序与长期运行限制

该实验候选 `timing_pass=false`、`release_accepted=false`。最终汇总 Setup(Slow) WNS=**−1.540 ns**，总失败端点 **1533**；细分 ai_clk 1530、DDR 3。因此表中速度为真实实验观察值，但不具备正式时序通过的发布条件。

历史状态记录提到约 189 帧后超时；后续独立 live 记录的状态快照分别计到 353、6187 帧。不能只引用最早 189 帧，也不能把计数快照当作完整无故障稳定性验收。文档写“长期稳定性待验收”更准确。
