# 5.2 CoreMark/MHz × 120 MHz：大胆架构冲刺计划

状态：**第一批 RTL 已提交，未测试、未综合、未上板**。用户要求停止反复测试，采用可回退的大胆实现；本轮先改架构。以下目标不是已取得的成绩。

## 1. 硬目标与起点

| 项目 | E2 可靠交付 | 目标 |
|---|---:|---:|
| CoreMark/MHz | 3.8557，板测 | ≥5.2 |
| 实际时钟 | 27 MHz | ≥120 MHz |
| 周期/迭代 | 约 259,358 | ≤192,307.69 |
| 时钟周期 | 37.037 ns | ≤8.333 ns |
| 资源 | 17,534 LUT / 7,153 FF / 3,684 LUTRAM | 首批组合逻辑投入控制在既有 LUT/FF 总预算内 |

E2：1152 迭代、298,780,717 ticks、11.066 s、五项 CRC 全对；setup +7.816 ns，hold +0.025/+0.014 ns。交付位流 `bitstream/pangoriscv_i1152_e2.sbit`，SHA256 `D7BF5E41B708F893DF57F5E049BA8A0168BE39BABB4773E3BFFEA5C0C25D3137`。

性能需减少约 **25.9% 周期**；频率需提高约 **4.44 倍**。两项必须在同一实现同时成立。仅延长流水线、提高 PLL 频率都不能保证 5.2。

## 2. 证据决定主攻顺序

已有 20 迭代诊断窗口为 5,212,477 cycles，retired 记录为 5,782,437。若退休数与计分窗口口径一致，则现有 IPC 约 1.11，5.2 所需平均 IPC 约 **1.50**。这是容量估算，不是新测量。恰好覆盖 20 个计分迭代时，周期上限约 3,846,154；初始化等窗口差异不能混算。

已有阻塞桶：RAW 720,997、lane1 memory 664,135、lane0 branch 444,391、WAW 190,096、非相邻 140,300。重定向 137,926 次，平均恢复约 3.5 拍；store queue 拒绝只有 12,310 次。

**阻塞桶不是可直接相加的周期收益。** `docs/lessons/mistakes-log.md` §13.5 记载 WAW 放行曾几乎无收益，§19 记载 lane0 branch 配对仅改善约 0.13%。修正早期交接建议：

- 不把删除 WAW 条件当主攻动作；WAR/WAW 本批保留。
- 不重做普通 lane0 branch + fall-through ALU 配对。
- 不先加深 store FIFO、不扩大 I-Cache、不做种子扫描。
- 优先第二槽访存，然后切断串联运算、缩短分支恢复、重叠访存等待。

单独回收 lane1-memory 桶不足以解释整个周期差距，必须有后续架构动作。

## 3. 第一批已实现：任一槽可使用同一个 LSU

增加 `ALU + load/store`，保留既有 `load/store + ALU/branch` 与 ALU 配对。每包最多一个访存，复用 LSU/D-Cache/AXI。

| 模块 | 已写入的行为 | 独立提交 |
|---|---|---|
| `retire_ctrl` | 正常老槽退休与年轻槽同步异常同拍发生；trap 反压时保持 | `f51c5f8` |
| `id_alu` | 译码合法 LB/LH/LW/LBU/LHU、SB/SH/SW | `8c6485d` |
| `pangoriscv` | 第二槽 LSU 路由、地址/存数 RAW 前递、load 写回旁路、整包等待、异常归属 | `a6186d1` |

设计不变量（静态推演，尚未由测试证明）：

1. 第二槽访存的老槽只能是 ALU，不能是未决分支、CSR 或除法。
2. LSU 所有者取 EX 锁存指令；等待时两槽保持，地址和存数不会被下一包覆盖。
3. `issued` 记录请求握手，整包离开才清除；年轻请求不会因老槽提前退休而重复。
4. 正常完成退休两槽；年轻 fault 只退休老槽，异常 PC/地址/原因属于年轻槽。
5. 老槽 fault 清除年轻槽；`trap_ready=0` 时不丢异常、不提前写回。
6. `retire_order/minstret` 按真正退休条数累加；IRQ 只在整包边界接收。
7. lane1 load 进入四条 EX→ID 旁路；store 的 rs2 前递只改存数，不覆盖地址立即数。
8. 数据前递不依赖总线 fault，避免“地址→fault→前递→地址”的组合反馈。

**当前局限**：仍是整包阻塞式退休，尚未与下一包计算重叠；ALU→地址→Cache 长路径尚未切分，本批不是 120 MHz 版本。

## 4. 下一批：错开执行槽，切断串联 ALU

选定下一版结构：

`取指队列 → 译码/读寄存器 → X0（老槽）→ X1（年轻槽）→ M（Cache 返回）→ W（按序提交）`

X0/X1 可同时处理相邻包，不是一包走完才接下一包。结构目标仍是每拍接收一包、最多退休两条。

### 数据通路

- X0 算老槽 ALU/分支/地址，把老槽结果与年轻槽操作数寄存。
- X1 算年轻槽；同包 RAW 使用上一拍锁存的老槽结果。第二槽访存在 X1 生成地址与存数。
- 旁路只从已寄存结果取值；禁止 X1 组合输出再穿过下一包 X0。跨包年轻槽→下一包老槽的依赖必须停顿，不能为零气泡重新串两个 ALU。
- 译码按 opcode/funct3 产生真实源寄存器使用位，不能把立即数字段当 rs2，也不能直接用当前恒零的 lane1 `uses_rs*` 做 scoreboard。
- 每槽携带 valid、PC、目的寄存器、写使能、fault/cause/tval、预测后继；按包序号/槽序确定年龄。先用小深度顺序完成队列，不上重命名或通用乱序执行。
- CSR/FENCE/MRET/异常/MMIO 作为串行边界。乘法从组合大运算中分离，完成握手进入同一套依赖规则。

### IPC 代价与补偿

错开发射会增加部分跨包 RAW 等待，不能只看 Fmax。依靠第二槽访存、多包重叠补偿；若吞吐不足，先改实际依赖链上的旁路级数与发射压缩，再考虑“独立年轻 ALU 在 X0 提前执行”的快速路径。提前结果必须寄存，不能串联另一 ALU。

**不采用所有指令统一多等一拍的假流水化**，那会直接损失 CoreMark/MHz。

### 面积

复用 ALU、LSU、Cache，新增级间 payload 与完成状态。新增模块前补齐 11 字段合同。当前 CSV 的 32/64/800 LUT 与 64 FF 是模块增量预留，不是测量；后续流水预算按实际 payload 位数单独登记，不把未综合增量填成 0。

## 5. 随后两个吞吐突破口

### 分支恢复与预测

当前约 3.5 拍/redirect，设计目标先减少约 1–2 拍，不能把全部开销计为收益。

- 执行槽完成分支时产生恢复请求，不等 W 才启动取指；若老指令尚未结束，记录 pending redirect 并保留异常优先级。
- IFU 接收明确 redirect PC，清年轻队列，省掉等 `pc_reg` 更新后才请求目标的串行步骤。
- 保留 `stale_cnt_q` 的应答归属保障。若新目标与旧应答重叠，增加请求 epoch/描述符追踪；不能只删 `stale_cnt_q==0` 守卫。
- 当前是 32 项直接映射 BTB，旧 64/128 项实验收益有限。后续候选是小返回地址栈与独立方向表，分别处理返回目标和方向误预测，不盲目复制大 BTB。
- 训练与退休一致；若采用推测 RAS，必须有恢复点。

### 命中访存与下一包执行重叠

- 地址寄存与 Cache tag/data 访问分开；命中结果在 M 寄存，再进入旁路。
- 先允许一个未完成访存加小完成队列，后继独立 ALU 可执行，load 消费者等待 scoreboard。
- store 取得顺序提交资格后才进入已有 store queue；MMIO 不推测，访存错误不得越过已提交年轻指令。
- 若仍无法达到周期预算，再考虑双 bank Cache 命中端口与同包双访存；必须处理 bank 冲突、字节写合并、同址顺序、双 fault，不能只放开 opcode。

## 6. 120 MHz 的完整实现范围

首要切点：串联 ALU、ALU→AGU→Cache→旁路、EX→ID 的寄存器读/译码长链。还需处理乘法、Cache 返回、全局 ready/flush 扇出和预测查表链；切一个点不保证 8.333 ns。

核心与现有 SoC 优先保持单时钟域，第一版避免同时引入 AXI CDC。用 27 MHz 晶振经合法 PLL 配置产生 120 MHz，锁定后同步释放复位；UART、timer 和 CoreMark tick 换算随实际时钟更新。PLL 参数必须满足器件 VCO/分频限制。

FDC 约束真实输入/生成时钟和 I/O，不用 false path 隐藏数据路径。E2 的 +7.816 ns slack 只能证明原设计在原约束收敛，不能报为新架构 Fmax。

分支 `exp/score-5.2-120mhz`，开始点 `f08d186`，可靠交付标签 `score-3.8557-e2`。一次提交一个 RTL 模块；回退时考虑模块依赖，不能只回退译码而保留顶层访存发射许可。

最终同一位流须满足：120 MHz 实际运行、≥10 s、五项 CRC 全对、setup/hold 无失败端点，保存资源、时序、镜像载入证据和位流哈希。120 MHz × 5.2 下 7000 迭代约 11.22 s；若实际更快则继续增加迭代数以保证时长。

板测公式：`CoreMark/MHz = iterations × 1e6 / total_ticks`。120 MHz、5.2 对应约 624 次迭代/秒。仿真与架构预算不能冒充板测成绩。
