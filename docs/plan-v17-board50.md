# v17 —— 本轮计划：先在"不加宽发射"的前提下把频率再推一档（P48）

日期：2026-10-23
状态：执行中（50 MHz 满实现 `build/p48r50` 已启动）
上游：`plan-v16-120mhz-spec.md`（用静态 ILP 定标，取代 v13/v14/v15 的"不可能"结论）

---

## 0. 本轮要回答的问题

用户目标：**CoreMark/MHz ≥ 5.2 且 最高时钟频率 120 MHz**，两者都要。

v16 已经把这件事算清楚了，本轮不再重新推导，只照它的结论执行：

| 结论 | 依据 | 对本轮的含义 |
|---|---|---|
| 120 MHz + ≥5.2 **可以**同时满足 | `ilp_bound.py` 定标后 4w/2mp/取指4 = 5.86 @120 MHz | 方向没错，可以做到 |
| 但前提是 **4 发射 + 16 B/拍取指 + 双端口 D$ + 3 级流水** | v16 §4 | 这是一次**换核级**重构（v16 估计 ≥5 周，M1~M6） |
| 触发 M1 的成本闸门 | v16 §7：M1 判据 `ticks ≤ 2.90M` | M1 本身就是 1~2 周的工作量 |

⇒ **本轮（单次会话）不可能把 120 MHz 做出来**。能做、且必须做的是两件事：

1. **不赌架构、只赌频率**：在现有 2 发射核上把交付频点从 48 MHz 往上推一档，
   分数保持 ≥5.2（分数与频率无关，提频不损失分数）。
2. **把"为什么本轮不做 120 MHz、下一步怎么开始"写成可执行的判据**，
   让后续任何一轮接手都不用重新论证。

## 3. 判据（满足才算成功，否则整轮回退）

1. `report_timing` 的 **`core_clk` 行**（50 MHz / 20.000 ns）：**setup WNS ≥ 0、失败端点 0**；
   hold 同样 0 失败端点。`core_clk_pnr` 行不计入合规（它是给摆放器的鞭子）。
2. 详细布线**0 未布通**（`Unrouted nets = 0`）。
3. 上板 `Total ticks` 与仿真同迭代数一致（±0.1%），五项 CRC 全对、`Correct operation validated`。
4. 综合日志必须出现 `Loading memory data from file .../program.hex`（第一铁律）。

## 6. 结果（50 MHz 探测：失败，已归档）

`build/p48r50` 完整实现 1 h 19 m，**详细布线第 707 轮收敛（Unrouted 0）**，但

| 时钟 | WNS | 失败端点 |
|---|---|---|
| `core_clk` 50 MHz | **−1.595 ns** | 3,202 / 58,154 |
| `core_clk_pnr` 52 MHz | −2.365 ns | 8,729 |
| hold | **+0.009 ns** | **0** |

布线后最差路径 ≈ **21.6 ns**，与 P33a/P37a/P45a/P46a 的"主导摆放吸引子 21.633 ns"一致
—— 这是第 6 个样本。而且这一轮的最差路径是 **load 数据返回**
（`rfile → ALU → AGU → ls_req_addr(233) → tag → hit_way(38) → way mux → extend_load`），
**不是** 48 MHz 那轮的 store 写使能。⇒ 瓶颈在同一条 20 ns 通路上来回漂移，
单点摘除对下一次摆放无效。

证据：`evidence/records/optimization/p48-freq-probe/`（rtr + 时序摘要 + pnr 日志 + 位流 sha256，
位流不合规，不发布）。

**结论（修订）：50 MHz 在第三次尝试拿到了 —— 靠的是把鞭子时钟去掉。**

### 6.0.3 第三次尝试（`p48r50e`，单时钟 20.000 ns）—— **通过**

前两次都用了 `core_clk_pnr` 52 MHz（19.231 ns）当"鞭子"。第三次把鞭子去掉，只声明
**单时钟 20.000 ns**（正好是 50 MHz 的周期），其余完全不变：

| 构建 | 最紧声明时钟 | 摆放 WNS | 布线后 | 结果 |
|---|---|---|---|---|
| `p48r48d`（48 M） | 20.000 ns（鞭子 50）| +1683 ps | 19.355 ns | ✓ |
| `p48r50` | **19.231 ns**（鞭子 52）| +1072 ps | 21.600 ns | ✗ −1.595 |
| `p48r50b` | **19.231 ns**（鞭子 52）| +1217 ps | 21.120 ns | ✗ −1.120 |
| **`p48r50e`** | **20.000 ns（单时钟）** | **+1683 ps** | **19.355 ns** | **✓ +0.645** |

`All Constraints Met`：`core_clk` 50 MHz setup WNS **+0.645 / 失败端点 0**、hold **+0.010 / 0**、
0 未布通 @ 114 轮、LUT 17,174 / FF 8,693 / LUTRAM 2,274 / DRM 12。
位流 `bitstream/pangoriscv_board50_i2800_5p248.sbit`（sha256 `5e1969fc…`），
镜像 `hw_i2800_50v17`（2800 迭代 → 10.67 s）。

⇒ **19.231 ns 是这条网表的坏点**：目标压得越紧，布出来越差（21.1~21.6 ns），
20.000 ns 反而是最优解。§68 的"鞭子时钟"经验**只在 20.000 ns 这一档成立**，
在它下面（19.23）必须关掉。这也解释了历史上"50 MHz 摆放更好却布不通"的怪现象（§70）。

**所以交付频点从 48 MHz 提到 50 MHz（+4.2%），分数与面积不变。**

## 6.1 本轮真正落地的改动：只有一处（中断边界），旁路被摆放否掉

### (a) 进了树：`irq_trap` 的中断注入边界补上 lane 1

```verilog
wire w_ctrl_any = w_ctrl || (w_v1 && w_ctrl_h);
wire irq_trap   = csr_irq_pending && w_valid && w_ctrl_any && !w_trap && ...
```

这是**真 bug**：交付 RTL 的配对规则允许 `addi; beq`（beq 在 lane1），
这样一个"控制流只出现在 lane1"的循环永远等不到中断边界 ⇒ 定时器中断进不来（挂死，不是延迟）。
`w_next_eff` 早就写了 `w_ctrl_h ? w_next_h : ...`，说明 lane1 控制流是正常情况，只有这条条件漏了。

| 判据 | 结果 |
|---|---|
| CoreMark `Total ticks`（20 it）| **3,810,700，与交付逐位一致**（性能模式不取中断，行为不变）|
| CRC | `0x4983` 全对 |
| ISA e2e | **20/21**（case 21 基线红）|
| 摆放 WNS @48 MHz | **+1,683 ps**（基线同日复跑 +1,068 ps，差异在 0.6 ns 波动内）|
| 面积 | 与交付一致 |

### (b) 未进树：lane0-load → lane1 旁路（存为 `docs/patches/lduse-pair.patch`）

仿真收益是真的，但**满实现否掉了它**：

| 项 | 值 |
|---|---|
| `Total ticks` | 3,810,700 → **3,784,335**（−1,318 拍/迭代）|
| 分数 | 5.2484 → **5.2850**（+0.7%）|
| 面积 | LUT 17,103 / FF 8,693 / LUTRAM 2,274（Δ 0/0/0）|
| CRC / ISA / halt-reset | 0x4983 全对 / 20-21 / 5-5 PASS |
| **摆放 WNS @48 MHz** | **−2,227 ps**（对照：同树去掉它 +1,683 ps）⇒ **差 3.9 ns，交付不了** |

⇒ 结论：**收益 <1% 的 RTL 改动必须先用 `place_only`（7 min）筛摆放，再决定要不要占满实现**。
完整的判据链与门槛（48 MHz 摆放要 ≈+1.8 ns 起才有戏）写进 `docs/lessons/mistakes-log.md` §80。

## 7. 下一轮（不在本轮范围）

按 v16 的 M1 起步，**先不加流水、不提频**，只在现有 4/5 级核上做"4 条/拍取指 + 4 槽退休"：

- 判据：20 迭代仿真 `ticks ≤ 2.90M`（≥6.90 分）、CRC 全对、ISA 20/21；
- 依据：v16 §3 显示"取指 2 条/拍"时 4 发射的 IPC 被钉在 2.000，分数只有 5.46 ⇒
  **加宽发射必须同时加宽取指**，这两件事必须一起做；
- 面积代价：v16 §6 预计 17.1k → 26.6k LUT，40% 利用率下 120 MHz 可布线性是本项目零先例的未知数，
  所以 M5（可布线性）要单独设一次真实实现，失败就先落 100 MHz。
