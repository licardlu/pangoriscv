# P30 —— D$ 关键路径的结构性压制与 120 MHz 的硬边界

日期：2026-10-23
RTL 基线：`f5fb342` + 本轮三处改动（字节通道 / LRU 延后 / PLL 与约束同频）
镜像：`sim20_O2`（20 迭代）、`hw_i2700_48`、`hw_i3000_50`、`hw_i3600_60`

## 1. 结论速览

| # | 结论 | 证据 |
|---|---|---|
| 1 | **D$ 不能改成寄存读**：load 命中 29,850 次/迭代，+1 拍 = +29,850 拍，是 5.2 余量（1,772）的 17 倍 | §2 |
| 2 | **字节通道拆分是零 CPI 的路径缩短**：50 MHz 处缺口 −0.613 → −0.135 ns，失败端点 417 → 3 | §3 |
| 3 | **LRU 位延后一拍写**：切断 `m_inst → AGU → tag → lru_mem/D` 整锥，`ticks` 逐位不变 | §4 |

| 5 | **约束有最优值，不是越紧越好**：45/50/55 MHz 约束 → 布线后 22.94 / 20.14 / 24.14 ns | §6 |

## 2. 为什么"寄存读 D$"永久关闭

`--define DC_DBG` 打开的计数器（`rtl/core/dcache_axi.v` 内已有）在 20 迭代后打印：

```
# DCDBG rd_new=720813 hit=596992 miss=123821 reload=122282 wr_new=143921
```

| 量 | 20 迭代 | 每迭代 |
|---|---|---|
| 读请求（新呈现） | 720,813 | 36,041 |
| **读命中** | **596,992** | **29,850** |
| 读缺失 | 123,821 | 6,191 |
| 写请求 | 143,921 | 7,196 |

`reload/miss = 98.8%` 是"同一行被连续呈现两次"的呈现口径，不是缺陷
（唯一缺失数 ≈ 3,100/迭代，与 `memwait` 10,390 拍吻合）。

**判据**：5.2 的预算是 192,307 拍/迭代；含重定向切断的版本已用 190,535，**余量 1,772**。
任何"命中多一拍"≥ 29,850 ≫ 1,772 ⇒ 不可行，且不是"再优化一下"能解决的量级问题。

⇒ 120 MHz（8.3014 ns）要求关键路径 ≤ 8.3 ns，而单周期异步 4 KB LUTRAM 读
（1024 字 = 5 级 mux，且 LUTRAM 物理摊开）在 PG2L100H 上的实测下限是 **15~20 ns**。
**在这个微架构里 120 MHz 不可达**，这是量化结论，不是放弃。

## 3. 字节通道拆分（零 CPI）

### 3.1 改法

`reg [31:0] data_mem [0:1023]` → `reg [7:0] data_mem_b0..b3 [0:1023]`：

```verilog
// 旧：异步读旧字 + 掩码合并 + 写回，全在接受拍内完成
merged = (data_mem[idx] & ~mask) | (w_data & mask);
// 新：只写被 strobe 的字节 —— 这就是合并
if (strb[0]) data_mem_b0[idx] <= w_data[7:0];
```

删掉 5 个 `merged_*`（3 个 32 位异步读 + 掩码锥）。读侧由 `dread()` 函数拼装四通道。

### 3.2 等价性验证

```
Total ticks : 3,810,700      （与改动前逐位相同）
crclist 0xe714  crcmatrix 0x1fd7  crcstate 0x8e3a  crcfinal 0x4983
ISA e2e     : 20 / 21 PASS（case 21 为基线即红，非回归）
```

### 3.3 面积

| 版本 | LUT | LUTRAM |
|---|---|---|
| 单 32 位阵列（同规模） | 17,288 | 2,274 |
| 4 个字节通道 | 17,306 | 2,274 |

⇒ **面积中性**（+18 LUT），收益只在路径上。

### 3.4 布线后效果

| 构建 | RTL | 约束 | 布线后路径 | WNS | 失败端点 |
|---|---|---|---|---|---|
| P30b | 单阵列 | 45 MHz | 22.684 | −0.462 | 125 |
| P31a | 字节通道 | 45 MHz | 22.943 | −0.721 | 232 |
| 同族 | 单阵列 | 50 MHz | 20.613 | −0.613 | 417 |
| **P31b** | **字节通道** | **50 MHz** | **20.135** | **−0.135** | **3** |

## 4. LRU 位延后一拍

### 4.1 P31b 的最差路径

```
Startpoint : soc/core/cpu/m_inst[11]/opit_0_inv/CLK
Endpoint   : soc/core/data_cache/lru_mem[30]/opit_0_inv_L6Q_perm/I5
最大单网   : data_cache/_N77740   fanout=16   1.627 ns
Slack      : −0.135
```

即"指令译码 → AGU → tag 比较 → 替换策略位的 D 输入"。LRU 是纯启发式，
**没有任何逻辑在同一拍读它**。

### 4.2 改法

```verilog
lru_pend_q <= 1'b0;                                  // 一次性
if (lru_pend_q) lru_mem[lru_pend_set_q] <= ~lru_pend_way_q;   // 放在 case 之前
case (state_q) ... ST_IDLE 命中: lru_pend_q<=1; lru_pend_set_q<=req_set; lru_pend_way_q<=hit_way;
```

放在 FSM `case` **之前**，让"本来也写这一位"的状态（ST_HIT / 填充完成）保持优先级。

### 4.3 验证

```
Total ticks : 3,810,700      （逐位不变 —— 替换决策完全一致）
五项 CRC    : 全对
ISA e2e     : 20 / 21 PASS
```

## 5. 关键发现：LRU 锥遮住了整个设计

`P31b.rtr` 里全部 6 条已报路径的起点/终点/slack：

| # | 起点 → 终点 | slack |
|---|---|---|
| 1 | `m_inst[11]` → `lru_mem[30]/I5` | **−0.135** |
| 2 | `m_inst[11]` → `lru_mem[22]/I3` | −0.132 |
| 3 | `m_inst[11]` → `lru_mem[18]/I3` | −0.029 |
| 4 | `set_di_q[1]` → `tag_mem_13/ram64x1d/WADDR[1]` | **+6.438** |
| 5 | `set_di_q[1]` → `tag_mem_14/ram64x1d/WADDR[1]` | +6.544 |
| 6 | `set_di_q[1]` → `tag_mem_18/ram64x1d/WADDR[1]` | +6.587 |

⇒ 前 3 条违例全是同一根 LRU 锥；切掉它之后，第 4 条路径的 slack 是 **+6.438 ns**，
即路径只有 **约 13.6 ns（Fmax ≈ 73 MHz）**。
**这根"策略位"路径把真实上限压掉了 6.5 ns**，此前所有关于"布线是抽签"的结论都被它污染。

## 6. 约束扫描：存在最优值，且抽签方差很大

同一份 RTL（D$4KB + 切断 + 字节通道），只改 `.fdc` 周期：

| 约束 | 摆放估计 | 布线后路径 | Estimated Fmax | 失败端点 |
|---|---|---|---|---|
| 45 MHz | 20.49 ns | 22.943 | 43.59 | 232 |
| **50 MHz** | 17.78 ns | **20.135** | **49.66** | 3 |
| 52 MHz | 18.16 ns | （未完成） | — | — |
| 55 MHz | 17.13 ns | 24.139 | 41.43 | 大量 |
| 50 MHz（+LRU 修复） | 18.93 ns | 21.633 | 46.23 | 2,219 |

两个 50 MHz 的抽签（20.135 与 21.633）差 **1.5 ns**，说明**方差 > 结构性改动的收益**。
55 MHz 摆放最好、布线最差（+4 ns），说明过约束会把逻辑压进过小面积导致拥塞绕线。

⇒ 最高可交付频率的现实区间是 **46~49.7 MHz**，不可能更高。

## 7. 两个工具/流程事实

### 7.1 `--freq` 不会改 PLL（已加硬检查）

`P31a/P31b` 用 `--freq 45/50` 跑，RTL 里 PLL 仍是 `F=58/O=13`（120.46 MHz）。
分析有效（`.fdc` 声明时钟），但位流会跑 120 MHz ⇒ 两份构建不可用。
`tools/run_pds_flow.py` 现在有 `pll_check()`：解析 4 个 PLL 参数、算 `27/I*F/(M*O)`、
校验 VCO、差 >1% 直接 `SystemExit`；`--pll-freq` 只用于过约束探针。

### 7.2 不能事后重报时序

`open_db` / `load_db` 在本 PDS 版本**不存在**（`help` 仍打印 successfully —— 与 §47 同坑）。
⇒ 每个频率主张都必须有"约束中的时钟周期 = PLL 实际频率 = 目标频率"的独立构建。
48 MHz 采用双时钟写法解决"摆放器偷懒"：`core_clk` 20.8333 ns（真实、用于合规报告）
+ `core_clk_pnr` 20.0 ns `-add`（只用于 P&R 加密目标）。
