# area-M3：BTB 缩位宽 —— 实测 LUT −1,309 / FF −1,152（A/B 逐项一致）

日期：2026-10-21
阶段：`module-area-plan.md` 的 **M3**
性质：**纯位宽改动**（不动预测算法、不动计数器、不动训练时机）

---

## 1. 做了什么

`rtl/core/branch_predictor.v`：

| 项 | 改前 | 改后 |
|---|---|---|
| tag 位宽 | `32 - IDX_BITS - 2` = **25** | `ADDR_BITS - IDX_BITS - 2` = **7**（`ADDR_BITS = $clog2(PGM_BYTES)`） |
| 目标存储 | `reg [31:0] target_q` | `reg [ADDR_BITS-1:0] target_q` = **14** |
| 新增参数 | — | `PGM_BYTES = 16384`（= `EXEC_BYTES`，程序区 16 KB） |
| 范围守卫 | 无 | 三个查表口 + 训练口都加 `in_range()`；越界 target 直接**置 entry 无效**，不截断 |

**为什么安全**：BTB 只会记录程序区内的控制转移，`PC < 0x4000` 时
`PC[13:7]` + `PC[6:2]` 与 `PC[31:2]` 的判别力等价；越界 PC/target 由 `in_range()` 拒绝，
不会别名到区内条目（否则会把"越界取指"从 fault 变成"命中错行"）。

## 2. 功能回归

| 检查 | 结果 |
|---|---|
| `tb/unit/tb_branch_predictor.sv` | **PASS**（含新增用例：P11 越界 target 被拒绝、P12 越界 PC 不别名） |
| 测试台改动 | P4/P5 的 5 个越界 target（`0x1111_0000` 等）改成区内地址（`0x0000_1100` 等）；这是**测试跟随参数**，不是放宽断言 |
| 20 迭代 CoreMark A/B（同一 `area20` 镜像） | **逐项完全一致**，见下 |

### A/B 原始数字（`run_coremark_ab.py --switch CACHE --sides on`）

| 项 | 改前（M1 后基线） | 改后（M3） | Δ |
|---|---:|---:|---:|
| cycles | 7,681,846 | **7,681,846** | **0** |
| retires | 6,779,785 | 6,779,785 | 0 |
| IPC | 0.8826 | 0.8826 | 0 |
| 控制流退休 | 1,190,946 | 1,190,946 | 0 |

`mispred` 与 cycles **一位不差**，说明缩位宽对程序区内代码是架构透明的。

## 3. 面积结果（交付 profile：PERF off，`compile+synthesize+dev_map`）

| 指标 | M1 后 | M3 后 | Δ |
|---|---:|---:|---:|
| LUT | 20,422 | **19,113** | **−1,309** |
| FF | 12,335 | **11,183** | **−1,152** |
| LUTRAM | 3,628 | 3,628 | 0 |
| DRM | 4 | 4 | 0 |
| **站点 S** | 36,385 | **33,924** | **−2,461** |

- FF −1,152 与预算完全吻合（32 项 ×(25−7 + 32−14) = 32×36 = 1,152 位）。
- **LUT −1,309 远超原估 −100**：三个查表口的 25 位 tag 比较 + 32 位目标多路选择
  换成 7 位比较 + 14 位选择后，比较器/多路器的 LUT 一起塌下来了。
