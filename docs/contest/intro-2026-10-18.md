# pangoriscv 作品简介

RV32IM 处理器 + 片上系统，紫光同创 PG2L100H。本页只讲**优化到什么程度**和**改了什么**。

## 一、优化程度

| 指标 | 优化前 | 优化后 | 变化 |
|---|---|---|---|
| 综合效率（CoreMark/MHz） | 1.3054 | **2.6740** | **+104.8%** |
| 每迭代周期数 | 766,039 | 373,973 | **−51.2%** |
| 每周期完成指令数（IPC） | 0.376 | 0.769 | +104.5% |
| 逻辑单元（LUT） | 12,572 | 13,574 | +8.0% |
| 单位资源产出（CoreMark/kLUT） | 0.1038 | **0.1970** | **+89.7%** |
| 时钟约束 | 27 MHz 零失败 | 27 MHz、50 MHz **均零失败** | — |

**一句话**：速度提升 105%，面积只增加 8%，所以"单位资源产出的效率"也涨了 90%。

提升分七步完成，每一步都用同一份镜像做过对照：

| 步骤 | 做法 | 贡献 |
|---|---|---|
| 第一步 | 访存写路径不再死等总线确认 | **+9.9%** |
| 第二步 | 取指通道拓宽（一次可等两条指令） | **+17.2%** |
| 第三步 | 访存请求在受理当拍就发出 | **+10.8%** |
| 第四步 | 访存完成在拿到数据的当拍就报出 | **+11.9%** |
| 第五步 | 缓存命中在受理当拍就给出数据 | **+13.8%** |
| 第六步 | 写内存在进行时，读内存照样能当拍完成 | **+8.3%** |
| 第七步 | 写内存的结果不必再等一拍才交回 | **+1.7%** |
| 第八步（本版） | 内存控制器读数据时不再白等两个节拍 | **+2.4%** |

因为不断变快，迭代数必须跟着重算（赛题要求单次运行不少于 10 秒），
本版是 **768 次迭代、实测 10.64 秒**，五项校验值全部正确。

## 二、修改点（本版）

本版只动**一个文件**（内存控制器 `axi_ram.v`，9 行），**面积反而少了 2 个逻辑单元、2 个触发器**：

**读内存的连续取数，每个数原来要 3 个节拍，现在只要 2 个**

内存控制器交出一个数之后，会多走两个内部状态：先读下一个数，再"空等一拍"。那个"空等"本来是给"慢速内存建模"留的开关，可实际硬件上这个开关是关的——也就是说它白等了一整拍。去掉之后，一次取 8 个数的连续读从 26 拍降到 18 拍。

**为什么这是安全的**：数据在同一拍就已经装进寄存器，下一拍本来就是有效数据；只是状态机多绕了一步。RAM 自带的 40 项随机用例全部通过。

**一个试过但没留下的改动**：把下一个数也提前取好（能再省 2%，从 18 拍降到 11 拍），但它改变了"慢速内存建模"那条路径上的取指行为，让一个暂停/复位可靠性用例无法注入。这条路径我没能解释清楚，所以**主动回退了**——不把看不懂的改动放进交付。

> 上一版（P14）的修改点——写内存结果当拍交回——保留如下备查：

上一版动了两个文件（数据缓存 + 访存单元），**面积多 18 个逻辑单元、触发器零增量**：

**写内存的结果原本要"寄存一拍"才交回 CPU，现在当拍就交**

数据区的写内存在设计上本来就是"先应答、后台等总线确认"（第二步就做了）。
但那个"应答"信号要多绕一拍寄存器才交出去。现在在总线收下写数据的那一拍就交给 CPU，
CPU 立刻退休、缓存立刻转入后台排空。写通合并改用当拍的原始数据与字节掩码，
因为寄存版本正好在这一拍才更新。

**为什么安全**：只有"已经决定早应答"的数据区写照走这条路；外设（MMIO）写、
写失败、CPU 没准备好的情况全部保留原来的寄存保持路径，反压语义一个字没改。

**一个必须同步修的测试台假设**：有个"写进行中时暂停/复位"的可靠性测试，
原本靠"访存单元停在等写确认"来抓时机。本版之后数据区写不再停在那里，于是把抓取点改成
**总线地址握手（AW）那一刻**——这其实比原来更贴近测试本意（"写已上总线、确认还没回"），
而且不依赖缓存是否被实例化。测试断言一个字没动，5 项全过。

## 三、效果验证

| 检查 | 结果 |
|---|---|
| 内存连续读的填充拍数（8 个数） | **26 → 18 拍**（每缺失） |
| 取指饥饿（等指令）拍数 | **−134,008 拍** |
| 整体周期 | **−1.90%**；跑分 ticks **−2.43%** |
| 分支预测失败 | **未变差**（153,686 → 153,694，噪声级） |
| 逻辑单元 / 触发器 | **−2 LUT / −2 FF（中性）** |
| 跑分五项校验值 | 与优化前**逐项一致** |
| 指令集功能测试 | **15 项全过** |
| 其他回归 | 单元、中断/复位、访存单元、数据引擎、缓存等**全部通过** |

## 四、口径说明

- 以上跑分数据来自**周期精确的 RTL 仿真**，不是板上实测（目前没有物理开发板）。
  固件按 27 MHz 把周期数换算成秒，所以在 27 MHz 板卡上即为 10.64 秒。
- 时钟频率一栏的 27 MHz 是**板载晶振的交付约束**，setup 余量 +15.4 ns、hold 余量 +0.025 ns；
  50 MHz 是**过约束压力测试**（setup 余量 +0.862 ns、hold +0.087 ns，是全设计最紧的一处），
  证明时序余量，不等同于板上实测最高频率。两者口径分开，不混称。
- **如实说明**：50 MHz 的收敛对布局布线种子是敏感的；本版 27 MHz 也试了三个种子，
  其中一个路由器甚至不收敛。换一次实现可能就不收敛。**27 MHz 的 hold 余量只有 +0.025 ns**，上板前需重点复核。
- 位流、资源报告、时序报告出自**同一份实现**，可互相校对。
