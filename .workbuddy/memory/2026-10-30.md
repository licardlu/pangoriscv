## 踩过并已修的坑（下次别再犯）
1. **RVC 允许 32 位指令落在 2 字节边界** → 会跨 4 字节取指块，必须用队列里的下一块拼接，
   且必须校验 `fb_tag[rd+1] == head+1`，否则静默产生非法指令（mcause=2）。
2. **取指口被 store 抢走** → 取指拿到别的地址的数据并当成指令缓存。改为 store 优先 +
   `imem_rvalid` 告知，对齐器丢弃无效响应并按同一块号重发。
3. **前递使能不能挂 `wb_commit`**：多周期单元冻结流水线时 WB 也被冻结，前递跟着关掉会让
   紧接的除法拿到旧操作数。前递只看"写回数据有效"。
4. **EX/MEM 前递源必须是最终写回值**，不是 `exmem_result`（ALU 结果）：CSR 指令的写回值在
   `exmem_csr_rdata`，PC4 类在 `pc+len`。
5. **除法器的 `done` 必须和 `result` 同拍**：早先在 done 那一拍才寄存 result，每条 DIV 都拿到
   上一条的结果。
6. **UART 队列必须 32 深**：固件流控是 `while((status&0x00ff0000)==0)`，靠 32−occupancy
   返回 0 来阻塞；8 深会被写穿，输出变乱码。
7. **LOAD/STORE 译码必须置 `alu_addsub=1` 且 `src2_sel=imm`**，否则地址恒为 0。
8. **同步 RAM 下 store→load 只隔 1 条时有真实冒险**，用一级 store 记录做字节合并。
9. 全局 `freeze` 与 `hold_front` 是两条不同路径，合并会死锁（Load 必须能进 MEM）。

## 追加（同日）：CoreMark 跑通 + PDS 全流程跑通

### 又修掉 3 个 bug（smoke 过不了、CoreMark 才暴露）
10. **`MMIO(0x10003000)=1` 把指令覆盖成 1** — RAM 写使能没按地址范围门控，
    MMIO 写在写外设的同时按 `waddr[15:2]` 截断写进了 RAM（mem[0xC00]=1），
    pc 走到 0x80003002 取到非法指令。修法：`ram_wen = dmem_wen & is_ram_w`。
11. **printf 数字全变 0/乱码** — 载入在 MEM 级遇到除法 34 拍冻结时，`dmem_rdata`
    只在那一拍有效，冻结后 `dmem_raddr` 被 EX 级新操作数覆盖，数据永久丢失。
    修法：进入 MEM 第一拍无条件锁存 `load_q`，`aged` 时 `memwb_data` 取 `load_q`。
12. **乘法器是关键路径** — 32x32 写成单表达式，PDS 用 3 级 APM 级联，
    路径 13.873 ns（旁路 mux → APM → APM → APM → FF）。改成 4 拍流水
    （S0 寄存操作数 / S1 四个 16x16 / S2 部分和 / S3 合成+符号修正），
    只用无符号 16x16 部分积推导四种结果。代价：ticks 8.95M→9.51M（-6%）。

## 追加（当日深夜）：P08 双发射尝试 → 未通过门禁，已回退

### 做了什么
把取指改成 64 位块、对齐器改成每拍双输出、加 4 项分发缓冲、4 读 2 写寄存器堆、
两份译码器、双通道执行（lane0 全能 / lane1 仅 ALU+移位+分支）、双槽 EX/MEM 与
MEM/WB、双写回。smoke 自检通过，CoreMark 配对率实测 10.5%。
源码全部保留在 `wip/v2_dual/`（`core/` + `ram_tdp.v` + `pango_soc.v` + `tb_soc_v2.v`
+ `elf2hex64.py`），问题登记写在 `docs/verification/v2-dual-issue-wip.md`。

### 为什么回退
CoreMark / 最小 printf 用例在 `number()` 里跑飞：`mv t6,a6` 没有把 a6 写进 t6，
t6 留着 `digits` 表地址，于是"搬数字"循环变成地址回绕死循环。
已排除配对逻辑（`+define+CFG_NO_DUAL` 纯单发射同样失败）、写回使能、分支自毁、前递地址错位。
未排除的重点：**mdu_stall 冻结期间寄存器堆读仍在更新、而 idex_* 冻结**，
若冻结期间分发缓冲头部变化就会错位一像素 —— 这是 V2 新引入的结构风险。

### V2 里修掉的 5 个真 bug（教训）
13. **分支/跳转自己不能被杀**：`exmem_v <= idex_v & ~redirect_ex0` 会让正在重定向的
    `jal` 进不了 EX/MEM，`ra` 不写，`ret` 跳回 `_start+0x46` 死循环。分支必须退休。
    同理 lane1 的 `jal` 不能被 `redirect_ex1` 杀；lane1 只在"lane0 是分支"时才被杀。
14. **写回使能不能用合并 valid**：`wb_commit=(v0|v1)` 会让 lane1 无效的那一拍
    拿残值写寄存器（实测把 a5 反复覆盖成 -91）。必须 `we0=v0&...`、`we1=v1&...`。
15. **前递比较的寄存器号必须是 ID/EX 级**（`idex_rs1q`），不能用译码级（`d_rs1`），
    否则差一条instruction，前递到错误的源。
16. **`wire [1:0] len = 2'd4` 等于 0**：2 位放不下 4。位宽不够会静默截断，
    pc 永不前进、同一条指令反复重发。凡是"长度/计数"先检查位宽。
17. **64 位取指窗口**：`{blk1,blk0} >> (pc[2:0]*8)` 后至少剩 9 字节，
    两条 32 位指令（最多 10 字节）够用；跨块必须校验 tag 连续。

### 结论
交付基线仍是 V1（`rtl/core` 已按 `build/replica_pds/run-002/sources` 原样还原，
md5 一致）。V1 复跑确认：`Total ticks 9,506,237`、四项 CRC 全对、`crcfinal 0x4983`。
下一步做 P08 的顺序：先只改 64 位取指（保持单发射）跑通 CoreMark → 再加分发缓冲
（`pop_n` 恒 1）并加"连续两次发射 pc 连续"断言 → 最后才开 `pop_n=2`。

## ★ 10-30 早间续：V2 双发射跑通（P08 功能完成）

### 根因：寄存器堆读输出没跟着 freeze 冻结
V2 只有一处结构差异要命：**读地址接的是分发缓冲头部（下一条要发射的指令）**，

### 本轮又踩的坑（都是真 bug，已修）
21. **freeze 期间 store 被重复执行**：`dmem_wen` 是组合的，freeze 冻住 MEM 级后
    一个 UART 字节被写 34 次（输出变 `SSMMOOKE PASS`）。V1 有同一隐患未修。
    修法：`st_written` + `st_pc_q`（用 pc 认身份），实测 ticks/CRC 逐位不变。
22. **固件 UART 分频写死 130**（= 焊死 120 MHz）：90 MHz 下波特率 85.9 k，

## ★ 10-30 上午续四：P10 分支预测找到真根因并跑通

### 根因（一处，但是结构性错误）
**预测信息是"逐条"的，不能按 lane 分配。**
`pred_jump` 那拍只发 1 条（正确），但这条指令进分发缓冲后，可能和**它前面**的
指令打包成 (lane0, lane1) 弹出 —— 而我把 `idex_predq[1]` 硬接成 `1'b0`，
预测标记丢了。于是 EX 不知道这条被预测过，`pred_bad` 不触发，前端一直留在
预测目标上，循环多跑一轮 → 多打印一个前导 0（`CPU_HZ=0120461538`）。
修：`dispatch_buffer` 补 `q1_pred/q1_predtgt`，`idex_predq[1] <= db_q1_pred`。

### 顺带补的两个洞
30. **预测纠错不完备**：原来 `pred_ok`/`pred_bad` 都要求 `iscf`，
    "预测命中但这条根本不是分支"（BTB 误命中）无人纠正 → 前端留在假目标上。
    改成 `pred_fix = predq & ~pred_ok`，覆盖三类（不跳/目标不同/非控制流）；
    目标改成 `taken ? target : pc_next`（原来目标不符时会错送 pc4）。
31. **前端互锁（死锁）**：队头 tag 对得上、但下一条要跨块而队里第二块是假块
    （不连续）→ `avail` 不够；同时 `head_ok=1` 不清队、`cnt=3` 不取指 → 谁都不动。
    实测 `nofeed` 一直涨、卡在 commit=126805。修：加 `stuck_head`，视同队头不可用，
    清队重取；**必须放过"下一块已在路上"那一拍**，否则会抖。

### 对账方法的两个坑（很重要，别再踩）
32. **必须截断到第一次碰外设之前**：`uart_send_char` 轮询的 status 是随时间变化的量，
    两遍快慢不同必然读出不同值 → 之后指令流合法分叉。`trace_diff.py` 默认
    `--stop-pc 800037aa`。
33. **`+fastuart`**（调试 TB）：`force dut.u_uart.status = 0x00010000`，
    打印不再限速，整个程序变纯确定性，可逐条比到底。
    另一个反直觉点：**不加 fastuart 时 `chars` 少不代表跑飞**，只代表还在打印
    （115200 8N1 @120MHz 每字节约 10400 拍）—— 这个骗过我一次。

### 结果
- smoke / pair / CoreMark 全 PASS，五项 CRC 全对。
- **7,654,154 → 7,311,975 拍（−4.5%）**，2.6130 → **2.7352 CoreMark/MHz**。
- **架构对账 300 万条退休指令逐条完全一致**（唯一差异是 `mcycle` 读值，
  那是周期计数，两遍本来就该不同）。这是目前最强的功能证据。

### 代价（关键）

WNS −1.660→**−2.578**（推算 100.4→**91.9 MHz**），最差路径变成 BTB 的 128:1 读 mux。

## ★ 10-30 下午：P09（Load-use 零停顿 + 早期地址）+ 第二个位流复验上板

### 做了什么
36. **Load-use 那一拍停顿是白停的**：地址由 ID/EX 在 T 拍给出，RAM 在 T 拍末尾
    就把数据打回来了，所以 T+1（Load 在 EX/MEM、消费者在 EX）`ls_rdata` 已有效。

37. **只加旁路会把 RAM 地址脚变最长路径**：17.233 ns（布线 85%）⇒ 67 MHz。

38. **早期地址通路**：地址单独一条旁路（不含 Load 数据）+ 专用加法器
    `addr_alu = a_rs1_0 + imm`；只有"Load 紧跟 Load 地址"停一拍。
