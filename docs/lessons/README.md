## 项目是什么

紫光同创 PG2L100H 上的 RV32IM 处理器 + 原生 AXI4 SoC，用 CoreMark v1.0 测评。
三级流水 + 2 路组相联 I/D Cache（2 KB）+ 32 项 BTB + 完整 trap/中断。

## 三条铁律（其余都是展开）

1. **只贴工具原文，不填自己算的数。** 标"原始输出"的块，每行都必须是工具/固件
   一次产出的原文；推导值放正文并注明算法；百分比写清是哪个量的比值。
2. **一个实现 = 一个证据目录。** 位流 SHA、`multiseed_summary.csv`、
   `report_timing.rtr`、各阶段 log 全套同源。同一构建目录**不许跑第二次实现**。
3. **先量后改；改不动就退回。** 改前用探针把账算准，一次只动一个变量，
   基线取改动前的提交，收益 <1% 而风险不低就不做，解释不清的差异不上线。

## 这个目录怎么维护

**只收可复用的经验。** 判断标准一句话：

> 下一次遇到**同样的现象**，这一条能不能直接告诉他"查什么、怎么办"？
> 能 → 收；只是"某年某月某文件坏了"这类一次性事实 → **不收**，
> 放 `issue-register` 或交接报告。

- 新坑按"现象 / 查什么 / 原因 / 怎么办"四段写，**别写成时间线流水账**。
- 同类坑合并进已有小节，不要为每条开新标题。
- 引数口径变了就改 `rules.md`，别另开文件。
- 这个目录**就 3 个文件**（本页 + 经验 + 规则），够了，不要加。
