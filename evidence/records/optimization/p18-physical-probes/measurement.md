## 5. 异常推送寄存化：零代价，−2.9 ns（本轮唯一有效改动）

`local_push = ... && local_fault`，而 `local_fault = |fetch_ptr[1:0] || !exec_ok(fetch_ptr)`。
重定向拍 `fetch_ptr == redirect_pc`，于是**整个 EX 重定向锥被拖进指令队列写使能**，
正是 §2 里那两根 1.111 / 1.833 ns 的网。

改法（`rtl/core/ifu_axi.v`）：`local_push_q <= local_push && !redirect_valid`，
`fetch_ptr_q` 同步寄存，`push_cnt` 与队列写入改用它。

**实测（`sim20_O2`，20 迭代）**：

```
# Total ticks : 3833976      <- 与未改动版本逐位相同
crclist 0xe714  crcmatrix 0x1fd7  crcstate 0x8e3a  crcfinal 0x4983   （全对）
ISA e2e: 20 / 21 PASS（case 21 基线即红）
```

**为什么免费**：异常推送只在取指指针越界/未对齐时发生，CoreMark 一次都没有；
`stop_q` 在检测当拍就已停掉新请求，延迟一拍没有可观测差异。

### 5.1 一次严重的量测错误（已记入 mistakes-log §58）

第一次测这个改动时，我拿 `run_coremark_sim.py` 打印的
`cycles/iter=285,827` 去比 `Total ticks/20 = 191,699`，得出"回归 50%"并回退了改动。
**这两个数不是一回事**：runner 的 `cycles` 是仿真周期（含约 190 万拍的启动/UART
轮询窗口），分数只认固件自己打印的 `Total ticks`。
同一个 `cycles=5,716,551` 在三份 transcript 里都出现（改动前 / 改动后 / 回退后），
而 `Total ticks` 也三次都是 3,833,976。
