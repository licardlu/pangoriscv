# P2' · store 路径优化：后台排空 B 响应（2026-10-17）

> 结论：**总周期 −8.98%**，store 等待从 2,638,797 拍降到 867,550 拍（−67%），
> 5 项 CRC 与基线逐项一致，ISA 15/15 通过（含 store 故障陷入）。
> 证据等级：仿真实测（20 迭代，同一镜像 A/B）+ 单元测试 + ISA 端到端。

---

## 1. 先量准，再动手

在改任何 RTL 之前，用测试台对 `dcache_axi` 的三个写状态分别计数（基线）：

```
STORE_PATH st_wr_req=575828 st_wr_resp=1775055 st_wr_hold=287914 st_total=2638797
```

| 状态 | 含义 | 拍数 | 每次写 |
|---|---|---|---|
| `ST_WR_REQ` | 等 AXI 写引擎收下 AW/W | 575,828 | 2.00 |
| **`ST_WR_RESP`** | **等 AXI 的 B 响应** | **1,775,055** | **6.16** |
| `ST_WR_HOLD` | 等 CPU 取走结果 | 287,914 | 1.00 |
| 合计 | | **2,638,797** | **9.16** |

store 共 287,914 次，占全部周期（17,256,182）的 **15.3%**，其中 **67% 在等 B**。
→ 等 B 确实是最大的一块，值得改。

## 2. 改动（`rtl/core/dcache_axi.v`）

新增状态 `ST_WR_DRAIN` 与两个标志 `early_q` / `drain_q` / `b_seen_q`：

1. **受理时判定能否提前释放**：`early_q <= (req_addr >= 32'h1000_0000) && (req_addr < CACHED_LIMIT)`。
   —— 只有在**片上数据 RAM 窗口**内的写才提前释放，那里的写不会 fault，
   所以 store 故障精确性不受影响（ISA 用例 11 仍按原路径同步等 B）。
2. **`ST_WR_REQ`**：AW/W 被收下后，若 `early_q` 则立刻给 CPU OKAY（`resp_q<=OKAY`），
   `drain_q<=1`，直接进 `ST_WR_HOLD`；否则维持原来的 `ST_WR_RESP` 同步路径。
3. **`ST_WR_HOLD`**：CPU 取走响应后，若 `drain_q` 则补做写通合并（此时 `wstrb_q` 才有效）
   并进 `ST_WR_DRAIN`；B 若已在同拍被引擎交出（`b_seen_q|i_b_valid`）则直接回 IDLE。
4. **`ST_WR_DRAIN`**：无条件接收 B（`i_b_ready = (state_q==ST_WR_DRAIN) || ...`），
   等到即回 IDLE。该状态**不服务新请求**，但 CPU 已经放行，所以这段时间与后续非访存指令重叠。

### 调试中修掉的两个死锁

| 现象 | 根因 | 修法 |
|---|---|---|
| 只退休 17 条即 `STALL_DETECT`（PC=0x30） | B 可能在 `ST_WR_HOLD` 当拍就被引擎交出并被消费，进 drain 后永远等不到 | 增加 `b_seen_q` 锁存"B 已交过" |
| 仍死锁 | `i_b_ready` 被 CPU 侧 `b_ready` 门控；CPU 取走响应后 `b_ready` 变低，drain 永远收不到 B | drain 状态**无条件**接收 B |

## 3. 实测（20 迭代，镜像 `perf_on` 不变）

| 指标 | 基线 | 优化后 | 变化 |
|---|---|---|---|
| **Total ticks** | 15,316,450 | **13,940,928** | **−8.98%** |
| cycles | 17,256,182 | 15,866,750 | −8.05% |
| `st_wr_resp`（等 B） | 1,775,055 | **3,808** | **−99.8%** |
| store 三段合计 | 2,638,797 | **867,550** | **−67%** |
| 5 项 CRC | 0xe714 / 0x1fd7 / 0x8e3a / 0x4983 | **完全一致** | 架构等价 |
| traps / faults | 0 / 0 | 0 / 0 | — |

按 400 迭代折算：ticks 306,415,752 → 约 278,900,000，
**CoreMark/MHz 1.3054 → 约 1.434（+9.9%）**（折算值，最终以整机 400 迭代实测为准）。

## 4. 正确性证据（三重门）

| 门 | 结果 |
|---|---|
| `run_dcache_tests.py` | **PASS** |
| `run_isa_e2e.py --cases all` | **15 / 15 PASS**（含用例 11 store access fault trap） |
| CoreMark 5 项 CRC | 与基线逐项相同 |

**为什么故障精确性没被破坏**：提前释放只对 `0x1000_0000 ≤ addr < 0x2000_0000` 生效，
该窗口在本 SoC 里只有片上数据 RAM，写不可能 fault。窗口外的写（含程序 ROM、
未映射地址）仍走原来的同步等 B 路径，出错照常进 trap。

---

## 5. 资源影响

改动只增加 3 个触发器（`early_q`/`drain_q`/`b_seen_q`）和一个 4 位状态码，
饱和器与数据通路未动。PDS 资源需在最终位流里复核。
