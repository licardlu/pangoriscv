# MS7210 音频初始化与来源

`rtl/ms7210_audio_init.v` 是独立的补充初始化控制器，放在原视频初始化之后。`rstn` 应由原视频 `init_over` 门控，`ENABLE=1` 默认启用，`ENABLE=0` 立即完成且不发送 I2C 事务。接口遵循原 `ms7210_ctl`：写为 `w_r=1`、读为 `w_r=0`；`iic_trig` 单周期；一次事务必须看见 `busy` 拉高再拉低后才完成。控制器不把较早出现的 `byte_over` 当成总线空闲。

部分字段均以读改写更新：`new=(old & ~mask)|(value & mask)`，保留未覆盖位。InfoFrame 头与 FIFO 字节直接写。总计 30 项操作、16 次读改写、46 次 I2C 事务，配置 PCM/I2S 输入、16 位双声道、48 kHz 采样率族并解除音频静音。Audio InfoFrame 为 type `84`、version `01`、length `0A`、checksum `70`、channel-count-minus-one `01` 和其余九个零字节。最后只置 `0x050E` 的 bit 5，保留已有 AVI bit 6。

地址和位掩码来源为原作者代码，不是猜测的芯片寄存器：

- 仓库：`https://github.com/avmwww/ms7210-linux-driver`
- 固定提交：`d7632336b5369c3241256108e336310d018f8259`
- `ms7210.h` Git blob SHA-1：`17af576bd469a95c1ddd75583a1eb9d6b7606a7d`
- `ms7210.c` Git blob SHA-1：`e67672d40301e4784c38d9269ccff5655613b98f`
- 未修改源码与 `LICENSE` 快照位于 `evidence/ms7210_reference/`，来源 URL、Git blob 和 SHA-256 位于其 `provenance.json`。

许可描述按原文件保留：C 源码开头写 `Licensed under the GPL-2.`，但仓库 `LICENSE` 实际为 GNU GPL Version 3 文本，二者存在版本标注差异。本 RTL 的总线状态机独立编写，参考的是寄存器事实，没有移植该 C 驱动实现。

`tools/test_ms7210_register_contract.py` 递归计算原 header 的宏地址，并从对应 C 函数的调用表达式求掩码和值，结合已选的 channel=0、I2S、16 位、双声道条件生成 `evidence/ms7210_audio_register_contract.json`，逐项与 RTL 比较。该检查不从 testbench 的常数生成期望值。源码中的 reset 函数在 `0x000B` 掩码 `11` 内以 `00` 置复位、以 `11` 释放；InfoFrame 在写 FIFO 前清 bit 5、写完后置 bit 5；`0x050A` 是 type、`0x0509` 是 version。2026-11-03 运行通过 17 个地址和 30 项 address/mask/value 的独立比较；修正后 ModelSim RMW、握手、Audio InfoFrame 校验和与禁用旁路测试也通过。

本地 100HP 硬件手册的 HDMI 输出表明确列出：`HD_TX_SC_MC=T23`、`HD_TX_I2S0=P26`、`HD_TX_I2S1=R26`、`HD_TX_WS=B25`。P26 是数据通道，不是 WS。手册是本地配套资料版本，不能仅据此宣称已验证照片上 V1.4 的全部实体连接。本文件未改引脚约束。

所选原驱动没有给出 I2S slot 位数、BCLK/fs 比例或额外 MCLK/fs 比例，因此这里不伪造芯片对 32-slot/64fs 的时钟验收结论。串行音频端输出是否被 MS7210 正确接收、显示器是否播放，仍由后续上板验证。控制器没有 ACK/error 输入，`init_over` 只证明总线事务序列走完，不等于芯片确认、HDMI 解码或扬声器实测通过。
