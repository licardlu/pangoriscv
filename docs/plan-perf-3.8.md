# 3.8 性能计划（P37）：配对内 RAW 前递 → 写引擎 2 outstanding

日期：2026-10-21 06:20　起点：**3.6345**（`bitstream/pangoriscv_i1024_p36.sbit`，hold +0.002、失败端点 0）
目标：**3.80 CoreMark/MHz**（不牺牲时序与资源效率，三项指标仍出自同一份实现）

## 2. 杠杆排序（按"实测上限 ÷ 结构风险"）

| 步 | 改动 | 实测上限 | 现实预期 | 风险 |
|---|---|---:|---:|---|
| **A** | 配对内 **RAW EX→EX 前递**（lane0 ALU 结果直接进 lane1 操作数），放开 `pair_ok` 里的 RAW 项 | 895,937 拒绝周期 | **250k~380k** | 中低（单模块、单 mux） |
| **B** | 写引擎 **2 outstanding**（AW/W 与上一笔 B 重叠） | 244,753 停顿 | 120k~180k | 中（B 计数 + resp 队列 + `dc_idle`） |
| C | 返回地址栈 / 重定向气泡 | 345k | 60k~120k | 中（预测器） |

**判定**：A 拿下 ≥240k 即直接到 3.8；不足则 A+B 组合。C 只作后备，不与 A/B 同轮。

## 3. 步 A 设计（P37a，只动 `pangoriscv.v`）

### 3.1 为什么现在才敢放开
现有 `pair_ok` 有三条依赖项：

```verilog
(drd ==0 || (drd !=rs1h && drd !=rs2h)) &&   // lane0 写、lane1 读 —— 本次放开
(drdh==0 || (drdh!=rs1  && drdh!=rs2 )) &&   // lane1 写、lane0 读 —— 不动
(drd ==0 || drdh==0 || drd!=drdh)            // WAW —— 实测收益≈0，不动
```

lane0 与 lane1 在**同一拍**进 EX，lane1 的操作数在 ID/EX 锁存，因此 lane0 的 ALU 结果
在 lane1 看来"还没写回"。但两者都是组合逻辑：`er1/er2 → alu_result` 与本拍 lane1 的
`er1_h/er2_h → alu_result_h` 并行，**把 `alu_result` 组合前递进 lane1 的操作数输入即可**，
不需要加流水级、不需要改退休语义。

### 3.2 实现
```verilog
// lane0 ALU 结果 → lane1 操作数（同拍前递）
wire fwd0_alu = ex_valid && ex_valid_h && alu0 && !mem0 && ewe && erd != 5'd0;
wire [31:0] ex1_r1 = (fwd0_alu && erd==rs1h) ? alu_result : er1_h;
wire [31:0] ex1_r2 = (fwd0_alu && erd==rs2h) ? alu_result : er2_h;
```
`u_ex_h` 的 `.reg1_rdata_i(ex1_r1) .reg2_rdata_i(ex1_r2)`。

`pair_ok` 的 RAW 项改为"仅当 lane0 是**访存**时才禁止"：

```verilog
(drd==5'd0 || !mem0 || (drd!=rs1h && drd!=rs2h))
```

**为什么访存必须留**：`wdata` 对 load 是 `load_value`（多拍后才回来），对 store 无写回；
`alu_result` 对 load 只是地址，前递它会算错。

### 3.3 必须守住的边界（逐条核对）
1. `alu0` 已排除 M 扩展（`funct7!=1`）与所有访存，因此 `is_div`/`is_load` 不可能被前递；
2. `erd!=0`：x0 不写回，`regs.v` 也不因 `erd==0` 而改变行为，前递条件必须显式排除；
3. 前递只看 `erd==rs1h/rs2h`，与 `regs` 的写口无关（lane1 的读在 ID 阶段已完成）；
4. **不得**顺手放开 `drdh==rs1/rs2`（lane1 写、lane0 读）—— 那条涉及 ID 阶段
   `rv1f/rv1hf` 的写透优先级，属另一类改动，本轮不做；
5. 组合路径变长：`er → alu0 → mux → alu1`，27 MHz 下余量极大（setup 现为 +10.041），
   但 PDS 后必须复核 `report_timing` 前 10 条不含 `u_ex_h` 的新路径。

### 3.4 测试先行
- 新增 **ISA case 17**：`addi` 后紧跟使用该寄存器的 `add/xor/branch`，编译器会自然形成
  相邻的依赖对；期望值由 Ref 模型现场生成，不手算。
- 现有 16 例全跑（RAW 前递错误会直接改变寄存器值，Ref 模型必抓）。
- `run_pipeline_tests.py` / `run_unit_tests.py` 保留全绿。
- A/B：窗口必须下降且**五项 CRC 逐项相同**。

## 4. 步 B 设计（P37b，`axi_data_engine` + `dcache_axi` 握手）

仅在 A 不足 3.8 时启用。

1. `SEND` 完成（AW+W 都 fire）后直接回 `IDLE`，B 由 `b_out[1:0]` 在后台等：
   `m_bready = (b_out != 0)`，收到 B 就压入 1 项 resp 队列（id 恒为 1，B 天然按序）。
2. `b_valid`（给 CPU）从 resp 队列头部产生，仍在原 `WR_HOLD` 位置；队列空则无效。
3. 接受条件 `b_out < 2 && !resp_full`；`dc_idle` 追加 `b_out==0`。
4. 契约不变：**B 未被取走前 `req_ready` 必须为低**（`tb_axi_read_engine` 的
   `WRITE_OWNERSHIP` / `EARLY_STORE_COMPLETION` 原样通过，不得改判据）。
5. 面积预算 +约 40 FF（resp 2 项 + 计数），无新阵列。

## 5. 每步之后必做（用户要求，固定顺序）

1. **面积/布线复核**：`device_map` 的 `Used`、`multiseed_summary.csv` 的 `single,OK,OK`、
   `report_timing` 前 10 条；跨区宽总线不新增（新逻辑留在 `R_CORE` / `R_IO`）。
2. **删冗余**：临时探针、被综合合并的寄存器、无用信号/状态；保留有复用价值的探针。
3. **查 bug**：ISA 17/17、dcache、engine 64/64、pipeline/unit、A/B 五项 CRC 逐项相同。
4. **同步文档**：模块卡（M19/M21/M01 视改动）+ `area-budget.csv` + `mistakes-log.md`。

## 8. 执行结果（2026-10-21 07:35）—— **3.8557 已交付**

| 项 | P36a（上一版） | **P37（交付）** | Δ |
|---|---:|---:|---:|
| 板上 ticks | 281,741,495 / 1024 迭代 | **298,780,717 / 1152 迭代** | — |
| 每迭代 ticks | 275,138 | **259,358** | −5.74% |
| **CoreMark/MHz** | 3.6345 | **3.8557** | **+6.09%** |
| 运行时间 | 10.435 s | **11.066 s** | ≥10 s 合规 |
| 五项 CRC | 全对 | 全对，`Correct operation validated` | 架构等价 |
| setup / hold | +10.041 / +0.002 | **+4.484 / +0.032** | 失败端点 0，`single,OK,OK` |
| LUT / FF / LUTRAM | 18,099 / 9,931 / 3,628 | **18,333 / 9,836 / 3,664** | 站点 +0.55% |
| **CoreMark/kLUT** | 0.2008 | **0.2103** | **+4.7%** |

**检查点**：G1 ISA 17/17（新增 case 17 + `pairs=` 覆盖计数）、dcache、engine 64/64、ram 40/40、
interconnect 20/20；G2 A/B 窗口 5,498,599 → **5,212,477**，五项 CRC 逐项相同；
G3 PDS `single,OK,OK`（hold +0.032、失败端点 0）；G4 上板 1152 迭代 / 11.066 s / CRC 全对。

### 8.1 三个可复用的结论
1. **配对的 RAW 不是"必须等一拍"**：lane0 是 ALU 时它的结果本来就是组合的，加两条 mux 就能同拍用，
   换来 99,347 个额外配对（窗口 −1.76%），面积只有 130 LUT。
2. **`WR_HOLD` 是纯浪费**：它的唯一职责是把 B 交给消费者。消费者在 drain 期恒 ready，
   在 `WR_RESP` 直接交（`b_take_now`）就省掉一整拍，store 停顿 246k → 110k。
3. **队列"满"要看同拍 pop**：`!q_full || q_pop` 是免费的一笔，且不会越过容量。

### 8.2 镜像迭代数（容易踩的坑）
P37 之后 1024 迭代只需 **9.83 s**，CoreMark 直接判 `ERROR! Must execute for at least 10 secs`。
**成绩与迭代数无关，但"≥10 s"是有效性硬条件**，所以交付镜像改为 **1152 迭代**（11.07 s）。
以后每次提速都要重算：`迭代数 ≥ 10 s × 迭代/秒`，并在 PDS 前用 `build_native_software.py --iterations` 重建。

## 9. 3.8 之后：效率专项的下一步（按"零分数风险"排序）

1. **时钟效率**：setup +4.484 ns（27 MHz 周期 37.04 ns，余量 12%）。最紧的一级是 P37a 引入的
   `er1/er2 → u_ex（lane0 ALU）→ fwd mux → u_ex_h → 写回`。若要把 Fmax 抬到 40 MHz 以上，
   这一级必须切分（例如 lane1 的加法器改成进位选择，或把前递并入 ALU 的输入选择）。
   **27 MHz 评分下不改分数，属可选**。
2. **资源效率**：`data_mem`/`data_mem_1`/`data_mem_3` 是 3 份 512×32（M19 卡片已标注"疑似副本"），
   而 2 路 × 32 组 × 8 字只有 512 字。若把 3 个读口改成"2 个真口 + 1 个时分割"，可省约 1/3 LUTRAM，
   但读写时序要重排，**必须先有 D-Cache 定向用例覆盖三条同拍读路径**才能动手。
3. **继续提分（可选）**：`PAIR_BLOCK` 还剩 `l1=664,136`（lane1 是访存，需双存储口）与
   `l0=444,410`（lane0 是分支）。前者要改 LSU，后者要改退休/重定向语义，风险都高于本轮。
