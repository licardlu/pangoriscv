# 白色分屏与提示语音

## 页面

1280×720 显示器左侧 x=0..639 为白色、浅绿操作区，包含四类垃圾桶、模式、本次运行积分和音乐状态；右侧 x=640..1279、y=0..719 全部用于摄像头画面和识别框。右侧没有积分栏、音乐卡片或其他占位面板。

右侧是 640×720 竖向视口。为了铺满并保持物体比例，原 1280×720 摄像头画面取中间 x=320..959，保持像素 1:1，不拉伸、不先缩成缩略图。放置物体时请放在镜头中央；两侧各 320 像素不在显示范围内。摄像头输入分辨率和 YOLO 模型没有改变，不能把这项显示修改当成模型准确率提升。

新版 YOLO 的 `portable/052_yolo_camera_top.v` 已在 `osd_px` 后接入 `light_split_video`，输入源仍是原 DDR 帧缓存实时视频。YOLO 框与画面作为同一路 RGB565 像素一起裁剪/延迟，不会进行第二次框坐标变换。模块统一延迟 HS/VS/DE 和像素两拍，顶层保留原输出寄存器再延迟一拍，总延迟三拍。

无目标时保持固定绿色引导框；检测框仍由用户提供的新 YOLO 工程产生。有检测但目标完全位于中央裁剪区域外时，该目标框也会在屏幕外，此时显示区域恢复固定引导框；画面裁剪不会改变推理范围。

`ui_rgb.sv` 的通用应用显示同样使用白色布局；它的 vision MMIO 输入仍是缩略快照接口，不应冒称实时高清链路。实板源代码使用上述 native RGB565 路径。

## 三句提示音

| 文件 | 文案 | 时长 |
| --- | --- | --- |
| PROMPT.WAV | 请选择垃圾桶。 | 约 2.33 秒 |
| CORRECT.WAV | 恭喜你，答对了！ | 约 2.53 秒 |
| WRONG.WAV | 哎呀，答错了。 | 约 2.37 秒 |

均已生成，使用本机 Microsoft Huihui Desktop 离线合成，格式为 48 kHz、16 位 PCM、单声道 WAV。准确文案记录在 `assets/audio/VOICE_MANIFEST.json`，可用 `tools/make_voice.ps1` 重生成。

答对后先播 CORRECT，音频驱动确认整段播完再播放 MUSIC0《晨光小径》。不会连续调用 play 直接截断正确提示。失败不会启动奖励音乐；积分仍为答对一次 +100、重复作答不重复加分、复位归零。

## 验证及交付边界

- `test_light_split_video.py`：两帧变化、跨行、右区 source x320..959 的逐像素匹配、同步信号延迟，通过。
- `test_light_live_frame.py`：真实 frontend OSD + 原生视频分屏 + 白色 renderer，检查 921600 个有效像素、边界采样和完整帧，生成 `assets/白色布局_实时视频链路_RTL仿真.png`。
- `light_panel`、`vision_display`、UI 像素/完整帧及 C 行为测试通过。
- `tb_bbox_osd` 同时验证：目标完全在可视范围外时，引导框不会消失。
- 语音文件测试核对采样格式、时长、非空波形和文案清单。

预览使用合成瓶子图像与已知矩形测试向量；1200 分、模式和就绪状态是仿真输入，既不是摄像头实拍，也不是模型推理结果截图。

**当前依然没有新位流，未执行 PnR 或上板测试，FDC 和物理接线未改。** 本次已接入新版顶层的是显示分屏路径。新版 YOLO 顶层中的积分和音频状态快照暂接零，显示实际启动默认值；外接音箱所需的应用 MMIO、按键与音频时钟/输出适配仍未完成。因此不能仅靠本源码包直接验收实板积分与播音。

`build_pre_pnr.tcl` 使用包内 `portable/052_yolo_camera_top.v` 并引用 `../extensions/business/application/rtl/` 的共享模块，ROM 相对路径也指向共享 assets；请保留整个 ZIP 目录结构。`sources/052_yolo_camera_top.v` 为输入源快照，不是该 TCL 选择的顶层，避免直接编译 `sources/*.v` 引入重名模块。
