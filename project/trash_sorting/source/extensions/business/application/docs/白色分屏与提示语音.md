# 白色上下布局与提示语音

> 2026-11-03：外围 RTL 闭环已接入实际顶层。固定答案 1、正确桶开盖五秒、关盖后重复提示、HDMI 音频初始化与引脚边界以工程根 `docs/外围测试闭环完成记录.md` 为准。下文保留早期布局/素材记录，其中外接 I²S 功放和奖励音乐的描述不是当前默认外围测试模式。

## 当前页面

1280×720 屏幕改为上下布局，维持白色、浅绿与深绿配色：

- 顶部 y=0..111（1280×112）：左侧“青禾 · 垃圾分类”和“看见绿色，让每一次选择都有意义”；右侧仅有“当前状态”卡片。
- 启动和等待选择时显示“请按板载按键 1 至 4 选择分类”。已有状态快照接入后，继续显示答对、答错、移走垃圾等实际状态。
- 下方 y=112..719（1280×608）：全宽摄像头与识别框。
- 原积分、四类分类卡片、自动识别/分类答题模式栏、音乐奖励与播放状态、底部提示文字均已从当前界面删除。固件积分与音频行为保持原样。

## 视频与资源

`portable/052_yolo_camera_top.v` 在 `osd_px` 后接入 `light_split_video`。下方直接显示原生 RGB565 的 source x=0..1279、y=112..719，画面与 OSD 一起经过两拍寄存器。保持 1:1、不拉伸，不新增帧缓存；顶部信息区会遮挡原摄像头最上方的 112 行，因此不是缩放后的完整 720 行画面。原左右布局裁掉的两侧视野现在恢复。

检测框由 `sources/049_video_ai_frontend.v` 保持：每次有效检测立即替换为新框并重置空检计时；连续空检测或没有提交检测结果时，旧框继续显示。顶层 PLL 标注为 720p30，达到 `RESULT_TTL=60` 个显示帧后清除旧框并显示绿色引导框，约为 2 秒。RTL 测试将阈值缩短为 6 帧，覆盖空提交、持续显示、超时清除和恢复引导框。

HS/VS/DE 与像素两拍对齐，顶层原寄存器再增加一拍，总延迟仍为三拍。删除了原先用于横向中心裁剪的 320×16 bit 延迟 RAM。frontend 水平可视范围恢复 0..1279，识别模型、输入分辨率和检测算法不变。

背景 ROM 从 640×360×4bpp 压缩为 640×56×4bpp（28,800 → 4,480 个 32-bit 字）；状态字形 ROM 从 9,720 → 4,860 字。当前 panel 不再实例化积分 BCD 转换器或英文音乐标签逻辑。上述是源码存储规模，不是综合实测的 LUT/BRAM 节省报告。

`ui_rgb.sv` 与 `vision_overlay.sv` 的 MMIO 快照备用显示同步采用上下布局；该路径仍是低分辨率快照，板级实时路径仍直接使用原生视频。

## 三句提示音

| 文件 | 文案 | 时长 |
| --- | --- | --- |
| PROMPT.WAV | 请选择垃圾桶。 | 约 2.33 秒 |
| CORRECT.WAV | 恭喜你，答对了！ | 约 2.53 秒 |
| WRONG.WAV | 哎呀，答错了。 | 约 2.37 秒 |

均已生成，使用本机 Microsoft Huihui Desktop 离线合成，格式为 48 kHz、16 位 PCM、单声道 WAV。准确文案记录在 `assets/audio/VOICE_MANIFEST.json`，可用 `tools/make_voice.ps1` 重生成。

答对后先播 CORRECT，音频驱动确认整段播完再播放 MUSIC0《晨光小径》。不会连续调用 play 直接截断正确提示。失败不会启动奖励音乐；积分仍为答对一次 +100、重复作答不重复加分、复位归零。
