| 项 | 值 |
|---|---|
| 构建 | `firmware/code/build/p50cut2`（分支 `exp/cut2only` = `exp/pair45` + 切②）|
| 约束 / PLL | 50.000 MHz / 20.000 ns（27×50/27，VCO 1350）|
| 镜像 | `hw_i2800_50v17`：2800 迭代 = 10.67 s |
| 收敛 | **0 未布通 @ 第 673 轮** |
| Setup WNS | **−1.532 ns**，59 失败端点，TNS −33.132 |
| Hold WHS | **−0.064 ns**，2 失败端点 |
| 摆放 | After DP **+1.774 ns**（比交付的 +1.683 更好）|

## 面积目标达成、时序失败

LUT 从交付的 17,174 降到 **17,021**（−153，与预算里的预测一致），
但布线后的路径从交付的 19.355 ns 变成 **21.532 ns**（+2.18 ns）。

## 最差路径：变坏的是**逻辑**，不是布线

```
Startpoint : soc/core/cpu/rr_pred[0]/...
Endpoint   : soc/core/cpu/ex_value_h[18]/...
Logic: 6.841 ns (32.1%)     Route: 14.448 ns (67.9%)     Slack -1.717
```

| | 布线部分 | 逻辑部分 |
|---|---|---|
| `p50r52`（52 MHz 那次）| 16.470 ns | 3.685 ns |
| **`p50cut2`（本次）** | **14.448 ns**（更好）| **6.841 ns**（更差 3.16 ns）|

也就是说：**布线这次反而更干净，但逻辑深度爆炸了**。去掉 CSR 那条路径后，
综合把 `rr_pred → 操作数选择 → ALU → ex_value_h` 这个锥合并得更深，
净效果是路径变长 2.18 ns。

## 这条结果修正了"摆线上限 19.3 ns"的说法

把同族网表所有布线后结果排在一起：

| 构建 | 摆放 | 布线后 | 判定（各自约束）|
|---|---|---|---|
| `p55max2` | 17.18 | **19.324** | ✗ @55 |
| `p48r50e`（交付）| 18.32 | **19.355** | **✓ @50 +0.645** |
| `p50r55` | 16.93 | **19.776** | ✗ @55 |
| `p50r52` | 17.33 | **20.222** | ✗ @52 |
| `p50cut2` | **17.03**（最好）| **21.532** | ✗ @50 |

**正确的说法不是一个"地板"，而是一个分布：19.32~21.53 ns，跨度 2.2 ns。**
50 MHz 需要 ≤20.0 ns，落在这个分布的中位附近 ⇒ **任何新网表能否过 50 MHz 都是五五开**，
而**已交付的 19.355 ns 是其中比较好的一次抽样**。

⇒ 由此得到两条结论：
1. **摆放余量、面积、逻辑量都不能预测布线后的结果**——`p50cut2` 三项都更好（摆放最好、
   LUT 最少），布线后却最差。
2. **已交付的 50 MHz 位流不应被任何"看起来更好"的新网表替换**，除非新网表
   满流程实测通过——而同一棵网表的摆放是确定性的（重跑同结果），
   想改善只能扰动网表，那就是抽签。
