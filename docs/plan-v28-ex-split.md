# v28：EX 三级拆分，把 50 MHz 的墙换成 120 MHz（在现有树上改，不重写）

日期：2026-10-28
前提：板载位流 `v40`（5.2599 CoreMark/MHz @ 50 MHz，17,020 LUT）已上板验证，冻结为保底交付。

---

## 0. 为什么要动结构，而不是继续调

赛题口径（`pango-riscv-contest/references`）：

```
Score = CoreMark_Iterations / (Total_Time × Frequency)   ← 即 CoreMark/MHz
三项并列：① 执行效率 CoreMark/MHz ② 最高主频 ③ CoreMark/LUT
三项必须出自同一份位流
```

现状与目标：

| 指标 | v40（现在） | 拆管道后目标 | 变化 |
|---|---:|---:|---|
| CoreMark/MHz | **5.2599** | ≥ 5.0 | −5% 以内 |
| 最高主频 | 50 MHz（布线 19.801 ns） | **≥ 110 MHz** | **2.2×** |
| CoreMark/kLUT | 0.3090 | ≥ 0.28 | −10% 以内 |

频率卡住的物理原因（`docs/performance-analysis.md` §4，v39 `report_timing`）：

- 最差路径 19.4~19.8 ns，其中 **Logic 3.5 ns / Route 16.9 ns（82.9% 是走线）**。
- 一拍里塞了：ID 译码 + 寄存器堆 32:1 读 + 旁路 mux + ALU 进位链 + AGU 加法 +
  D$ tag 阵列读 + 21 位比较 + 阵列写使能扇出。
- 器件只用 25%（17,020 / 66,600 LUT）⇒ 工具把逻辑摊开摆，一段里塞得越多、走线越长。

结论：**5.24 这个分数正是"长时钟周期"换来的**。要上 110~120 MHz，这一拍必须切成三拍。
频点扫描已经证明这条路走不通：45/48/50/52/55/60 MHz 九次满流程，地板 **19.426 ns**，
52 MHz 差 0.195 ns，55/60 MHz 布不通。**换 seed / 换布线配方是逐位相同的 no-op**（已验证三组）。

## 1. 改动范围：只动 `rv32_top.v` 的 EX 段

不动：IFU、I$、D$、分支预测器、AXI、CSR、除法器、软件。
动：RR→EX→M1 之间的组合逻辑分组，以及 LSU/重定向的握手位置。

### 现状（v40）

```
RR: rr_* 寄存器（含 lane1 的 rr_*_h）
EX: fwd1/fwd2/fwd1_h/fwd2_h → alu_a/alu_b → u_alu/u_alu_h/u_mul/u_mul_h
    mem_addr = fwd1 + imm；mem_misaln；issue_mem/op_ready/mem_wait/hold_ex
    br_taken/ctrl_target/ctrl_miss → br_miss → redirect
M1: ex_* 寄存器
```

### 目标（v28）

```
RR : rr_* 寄存器（不变）
E1 : 旁路 mux + 操作数选择      → e1_a, e1_b, e1_a_h, e1_b_h, e1_imm, e1_* 控制位
E2 : ALU / 乘法器 / AGU 地址    → e2_y, e2_y_h, e2_addr, e2_sdata, e2_y_h_w
E3 : D$ tag 比较 + 命中 + 分支判定 → ex_*（原 M1 前半）
M1 : 原 M1（结果、异常、提交信息）
```

每拍的预算（目标周期 8.33 ns）：

| 拍 | 内容 | 逻辑预算 | 关键风险 |
|---|---|---:|---|
| E1 | 32:1 读 + 4 级旁路 mux + alu_a/alu_b 选择 | 3.0 ns | 旁路比较器有 5 组，扇出大（现在 `rr_inst[21]` 单根 fanout=136，2.67 ns）|
| E2 | ALU 进位链 + 乘法器 + 地址加法 | 3.5 ns | 乘法器 4 个 APM 级联 6.14 ns，**必须留到 E1/E2 都不能碰的独立槽**，否则 120 MHz 保不住 |
| E3 | D$ tag 阵列读 + 21 位比较 + 命中 mux + 分支 eq/lt 复用 | 3.0 ns | tag 比较与 ALU 比较器不能再串联 |

**乘法器的处置**：4 个 APM 级联 6.14 ns 单独就吃掉 74% 的拍。两个选择：
(a) 保留在 E2，把 E2 的周期放宽到 ~7 ns（主频退到 ~110 MHz）；
(b) 把乘法器搬成 2 拍（`mulu` 低半在 E2、`mulh` 高半在 E3）。
**先做 (a)**：`-O3` 下乘法占 CoreMark 比例不高，而 (b) 会让 mulh 多一拍，
且 `docs/lessons/mistakes-log.md` §111 已经量过 rev2.0 两拍高半是 **+610 LUT 净亏**。

## 2. 必须付的代价（提前写清，不能事后找理由）

| 项 | 拍/迭代 | 相对 190,118 | 依据 |
|---|---:|---:|---|
| 每次重定向 +2 拍 | +13,754 | +7.2% | `docs/performance-analysis.md`：137,530 redirect / 20 迭代 ⇒ 6,877/迭代 |
| load-use 停顿 1 拍 | +9,000 ~ +18,000 | +5% ~ +9% | 读 36,041 次/迭代，命中当拍返回变成 E3 才返回 |
| **合计（不做 IPC 补课）** | | **+12% ~ +16%** | CoreMark/MHz 5.26 → **4.5 ~ 4.7** |

⇒ 拆分本身会让执行效率掉到 4.5~4.7，**低于现在的 5.26，也低于同学的 5.0**。
所以 v28 不是一步到位，必须配第 3 阶段的 IPC 补课。

### 第 3 阶段：把 CoreMark/MHz 拉回 5.0 以上的候选（按性价比排序）

| 候选 | 预期 Δ拍/迭代 | 面积 | 备注 |
|---|---:|---|---|
| BTB 64 → 256 | −1,500 ~ −2,500 | +2,400 LUT | 重定向变多后预测收益被放大，先做 |
| 异构第二发射槽（lane1 只跑访存/跳转，不跑 ALU） | 风险 | 0 | **会引入 +10.6% 的拒配代价（已实测）**，放最后 |
| D$ 4 KB → 8 KB | −1,000 | +1,140 LUTRAM | `p62` 量过：纯容量只值 +0.88%，但 E3 化以后命中率权重上升，需重测 |
| 分支预测改 TAGE-lite | −2,000 估 | ~+1,000 LUT | 工作量大，放最后 |

## 3. 分阶段执行与验收门（每一阶段都必须上板）

| 阶段 | 内容 | 验收门 | 不通过就回滚 |
|---|---|---|---|
| **S1** | 只拆到 E2（RR→E1→E2→M1，两拍） | 综合 WNS ≥ 0 @ **10.0 ns**；板测 5 项 CRC 与 `e9f5/e714/1fd7/8e3a` 相同；ticks 不劣于 205,000/迭代 | 保留 v40 |
| **S2** | 拆到 E3（三拍），LSU 握手与 `br_miss` 下移 | 综合 WNS ≥ 0 @ **8.33 ns**；板测 CRC 相同；ticks ≤ 215,000/迭代 | 回 S1 |
| **S3** | IPC 补课（BTB 256 起） | 板测 CoreMark/MHz ≥ 5.0 且主频 ≥ 110 MHz | 回 S2 |

判据统一用 `run_pds_flow.py --freq <n> --mode full` + `check_delivery.py`，
上板用 `pangoriscv-verify/measure.ps1`，CRC 期望值必须逐位对（`mistakes-log` §121：
镜像换了 CRC 最后一字会变，`2800` 迭代是 `0xbd59`、`4000` 是 `0x65c5`）。

## 4. 已知坑（不要重犯）

1. **不要在拆分的同时改配对规则**。`pair_ok` 对综合不可见，改它换不来时序，只换 IPC
   （§115：删 `lane0_raw` 分支 = +10.6% 周期）。
2. **不要用"布线后 ns"比较单次改动**。同一棵网表两次布线差 2.4 ns（§119）。
   能复现的指标只有：综合 WNS、布局后 slack、板测 ticks。
3. **不要并发跑两个 PDS 流程**（§113，单 seat license 会静默死锁）。
4. **不要用 GCC 13.2.0 构建用于对比的镜像**（§118，会让 ticks 差 4.6%）。
5. **不要改 `.fdc` 里的 PLL 参数而不核对 VCO**：`27 × F / M` 必须落在 1330~2133 MHz。
