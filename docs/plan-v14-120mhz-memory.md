## 3. 频率的真正障碍（本轮新证据）

### 3.1 紧约束能把路径压到多少

| 约束 | 布线后路径 | Estimated Fmax | setup |
|---|---|---|---|
| 42 MHz | 24.927 ns | 40.12 | −1.118 |
| 45 MHz | 22.684 ns | 44.08 | −0.462 |
| 50 MHz | **20.613 ns** | **48.51** | −0.613 |
| **120 MHz** | **摆放估计 15.50 ns**（wslk −7245） | — | 布线未收敛 |

`P30a`（120 MHz 约束）的摆放把 WNS 压到 −7,245 ps ⇒ 估计路径 **15.5 ns**，
比 45 MHz 约束的 20.8 ns 又短 5.3 ns。**但离 8.3014 ns 仍差 1.87 倍**，
且该构建详细布线在 6 轮时还有 19,369 条未布通（拥塞），拿不到 `.rtr`。

⇒ **仅靠"让工具更努力"不可能到 120 MHz。** 必须减少路径上的结构级数。

### 3.2 路径为什么这么长

`P23b.rtr` 的最差路径（50 MHz 约束下）：
```
Startpoint : soc/core/cpu/ex_valid
Endpoint   : soc/core/data_cache/data_mem_16_15/ram64x1d/WE
Logic 3.527 ns (17.2%) / Route 16.947 ns (82.8%)   30 级跳
最大单网  : data_cache/_N11365  fanout=64  2.028 ns   ← 阵列写使能
```

**根本原因**：D$ 必须在**与地址生成同一拍内**完成
`异步读 → 字节合并 → 写回阵列`，因为 store 的可见性依赖"接受当拍就合并"
（下一次 load 立刻可能读到同一字）。这条链 = 5 级读 mux + 合并逻辑 + fanout-64 写使能。
而 4 KB 阵列 = 1024 字，LUTRAM 物理上摊开在整个器件上，所以 82.8% 是走线。

## 4. 本轮已完成的改动：D$ 数据阵列按字节通道拆分

把 `reg [31:0] data_mem[]` 拆成 4 个 `reg [7:0] data_mem_b0..b3[]`。

- 部分写不再需要"读旧字 + 合并"：`if (strb[i]) lane_i[idx] <= data[8i+:8]` **就是**合并。
- 5 处 `merged_*`（3 个 32 位异步读 + 掩码逻辑）整体删除。
- **实测功能等价**：`Total ticks 3,810,700` 与基线**逐位相同**，五项 CRC 全对。
- 面积中性：LUT 17,306 vs 17,288（同规模对照），LUTRAM 2,274。

设计意图：让 store 路径从 `addr→tag→read→merge→write` 变成 `addr→tag→write`，
砍掉 5 级读 mux。**这是本轮唯一"零 CPI 代价"的提频手段。**

## 6. 通往 120 MHz 的剩余方案与已知代价

| 方案 | 收益 | 代价/风险 | 状态 |
|---|---|---|---|
| 按 way 拆阵列（读与 tag 比较并行） | 估计 −2~3 ns | 读 mux 宽度翻倍，LUT +600~900，可能顶破 18,000 可布线上限 | 未做 |
| D$ 改双端口 BRAM（寄存读） | 路径 −8~10 ns，**且** mem+mem 配对回收 12,256 拍 | **load 命中要 +1 拍**（代价未测成：强制 ST_HIT 后整机死锁，说明握手紧耦合）；且要重写 store 提交 | 未做，风险最高 |
| 再切流水线刀（ALU / I$ tag） | 每刀 −3~5 ns | 每刀 +4,791 拍，预算只剩 3,493 ⇒ **装不下** | 必须先有大额 CPI 回收 |
| 按模块划区域 | 压缩跨度 | `def_inst_region` 在本 PDS 版本必崩（P13 已钉死） | 工具不可用 |

**结论性判断**：120 MHz 需要把 D$ 从"单周期异步"改成"寄存读 + 多周期"，
而这必须先付出 +1 拍/load 命中的 CPI，再由双端口 BRAM 的 mem+mem 配对（12,256 拍）回补。
这两个改动是**同一个工程**，且必须一起交付；单独做任何一个都会掉出 5.2。

## 7. 纪律（沿自上几轮）

1. 频率结论只认 `report_timing/*.rtr` 的 `Estimated Frequency` + `WNS ≥ 0` + `失败端点 = 0`，
   并注明是约束值还是实测值。
2. 跨 build 比分数只认 `transcript.txt` 的 `Total ticks`，不认 runner 的 `cycles`。
3. 上板判据：`seedcrc` + 三个子 CRC + `Correct operation validated` + `Total ticks` 反推 ≥10 s。
4. 一次满实现 ≈ 4 h，一个假设一次构建；先用 `-place_only`（8 min）排除选项类假设。

## 8. P30/P31/P32 执行记录（2026-10-23 上午）

### 8.1 用数据钉死"不能把 D$ 读寄存一拍"

原计划里"改成寄存读 + 双端口 BRAM"是通往 120 MHz 的唯一结构方案。**先量了它的价格**：

```
DCDBG rd_new=720813  hit=596992  miss=123821  wr_new=143921      （20 迭代累计）
⇒ load 命中 29,850 次/迭代
```

任何"命中多一拍"的方案至少 = **+29,850 拍/迭代**，而 5.2 的预算余量（含重定向切断）只有
**1,772 拍**。差 **17 倍**。⇒ **D$ 必须保持单周期异步访问**，"寄存读"路线永久关闭。

### 8.2 字节通道拆分：零 CPI 的路径缩短

`data_mem` 由 `reg[31:0]` 单阵列拆成 4 个 `reg[7:0]` 字节通道阵列。

- 部分写不再需要"读旧字→合并→写回"：只写被 strobe 的字节**就是**合并。
- 删掉 5 个 `merged_*`（3 个 32 位异步读 + 掩码逻辑）。
- **`Total ticks 3,810,700` 逐位不变**，五项 CRC 全对，ISA 20/21（case 21 基线即红）。
- 面积中性：LUT 17,306 vs 17,288；LUTRAM 2,274。

布线后效果（同约束、同参数）：

| 构建 | RTL | 约束 | 布线后路径 | WNS | 失败端点 |
|---|---|---|---|---|---|
| P30b | 单阵列 | 45 MHz | 22.684 | −0.462 | 125 |
| P31a | 字节通道 | 45 MHz | 22.943 | −0.721 | 232 |
| P30a 同族 | 单阵列 | 50 MHz | 20.613 | −0.613 | 417 |
| **P31b** | **字节通道** | **50 MHz** | **20.135** | **−0.135** | **3** |

⇒ 50 MHz 处缺口从 −0.613 ns 收窄到 **−0.135 ns**（+0.48 ns），失败端点 417 → **3**。
⇒ 45 MHz 反而更差，再次印证 **§63：约束越紧摆放越好**，不能靠放松约束换通过。

### 8.3 新关键路径：替换策略位（零代价可切）

`P31b.rtr` 的最差路径已经不是 D$ 阵列：
```
Startpoint : soc/core/cpu/m_inst[11]
Endpoint   : soc/core/data_cache/lru_mem[30]/I5      ← 替换策略位的 D 输入
最大单网   : data_cache/_N77740  fanout=16  1.627 ns
```
LRU 位是纯启发式，**没有任何逻辑在同一拍读它**。把它的更新延后一拍、改用寄存器值驱动
（`lru_pend_q/lru_pend_set_q/lru_pend_way_q`，写入口放在 FSM `case` 之前以保持原有优先级）：

- **`Total ticks 3,810,700` 仍逐位不变**（替换决策完全一致）。
- 切断了 `指令译码 → AGU → tag 比较 → lru_mem/D` 这条整锥。

### 8.4 一次真实的工具/流程事故（已修）

P31a/P31b 用 `--freq 45/50` 跑，但 `pangoriscv_top.v` 里的 PLL 还停在 120.46 MHz
（`F=58/O=13`）。时序判决仍有效（`.fdc` 才是分析时钟），但**那两份位流会跑在 120 MHz**，
不能上板，等于白跑两小时。

已在 `tools/run_pds_flow.py` 加 `pll_check()`：解析暂存源码里的
`STATIC_RATIOI/M/F/O0`，算出 `27/I*F/(M*O)`，与请求频率差 >1% 或 VCO 越界就**直接拒绝**。
同时加 `--pll-freq`（默认等于 `--freq`），只用于"过约束探针"，并在日志里显式打印
"RTL 跑 X MHz、时序按 Y MHz 检查"。

⇒ 单次构建的时序数字不能作为"RTL 好坏"的判据，只能作为"这一次实现的判据"；
   要比较 RTL 必须多次实现取最好值，成本是每次 1.5~4 h。

## 10. 关键路径的分段账：为什么 5.2 与 120 MHz 在本微架构互斥

`P35a`（48 MHz 交付版）最差路径 `rr_inst[22] → data_mem_b0_12_1/ram64x1d/WE`，
20.581 ns。逐段拆开（数值取自 `.rtr` 的累计时间列）：

| 段 | 区间 | 耗时 | 占比 | 内容 |
|---|---|---|---|---|
| ① 指令位 → 操作数寄存器 | 2.597 → 9.929 | **7.33 ns** | **35.6%** | 寄存器堆读（32:1）+ 旁路/操作数 mux |
| ② ALU | 9.929 → 11.314 | 1.39 ns | 6.8% | 32 位加法器进位链 |
| ③ ALU → AGU → LSU 地址 | 11.314 → 15.457 | 4.14 ns | 20.1% | 地址 mux + 扇出 110/151 的地址网 |
| ④ D$ tag 比较 → hit | 15.457 → 17.327 | 1.87 ns | 9.1% | tag 阵列读 + 21 位比较 |
| ⑤ 阵列写使能扇出 | 17.327 → 20.581 | 3.25 ns | 15.8% | 一根 fanout≈144 的 WE 网 |

### 10.1 结论一：这不是"逻辑太深"，而是"一段里塞得太多"

`rr_inst → alu_b` 用了 7.33 ns，其中**一根 `rr_inst[21]`（扇出 136）就 2.67 ns**。
这一整段是"从指令寄存器出发，读寄存器堆、过旁路 mux、进操作数寄存器"——
在常规五级流水里这正好是 ID 一级，而本核把它与 EX、AGU、D$ tag 比较**压在同一拍**。

正因为压在同一拍，load 命中当拍返回、重定向只要一次、IPC 才到 1.84 ⇒
CoreMark/MHz 才到 5.24。**5.24 这个分数就是"长时钟周期"换来的。**

### 10.2 结论二：把它切开的价格，是 5.2 预算的 24~200 倍

| 切法 | 每迭代代价 | 依据 | 预算余量 |
|---|---|---|---|
| 在 ③①之间切（EX/AGU 与 D$ 访问分开）| **≈ +43,000 拍** | 每次 load/store +1 拍（36,041 读 + 7,196 写）| **1,772** |
| 在 ① 内切（ID 与 EX 分开）| **≈ +351,000 拍** | 每条指令 +1 拍（351,284 条/迭代）| **1,772** |
| 在 ⑤ 前切（store 提交寄存）| ≈ +7,196 拍 | 每次 store +1 拍（还要加 load-after-store 旁路）| **1,772** |

⇒ 唯一"理论上付得起"的是最后一刀，但它只砍掉 3.25 ns 中的一部分，
   **20.58 → 约 17.5 ns ≈ 57 MHz**，离 8.30 ns 还差一倍。
⇒ 要 120 MHz 必须切 ①②③④ 中的至少两段，那就是 43,000 拍量级 ⇒ **分数掉到 2.8 以下**。

**因此：在"必须 ≥5.2"的约束下，本微架构的最高频率约 50 MHz；要 120 MHz 必须换微架构
（多级流水 + 多周期 L1 + 双端口/非阻塞），而那会把 CoreMark/MHz 打到 3 以下。**
两者不是"再努力一点"的关系，是同一枚硬币的两面。

### 10.3 50 MHz 的终局：四次尝试，最好差 0.135 ns

| 构建 | 网表 | 约束 | 布线后路径 | WNS | Fmax |
|---|---|---|---|---|---|
| P31b | 字节通道（未切 LRU）| 50 MHz | **20.135** | −0.135 | 49.66 |
| P33a | + LRU 延后 | 50 MHz | 21.633 | −1.633 | 46.23 |
| P37a | + LRU 延后（同参数复跑）| 50 MHz | **21.633** | −1.633 | 46.23 |
| P37b | + LRU 延后（不优先 DRAM）| 50 MHz | 21.189 | −1.189 | 47.19 |

**P37a 与 P33a 逐位相同（21.633）⇒ 这条流程对给定输入是确定性的，不是"抽签"。**
之前观察到的 1.5 ns 差异来自**网表不同**（LRU 那刀把最差路径从"策略位"换成了
CPU 的 `w_valid → ex_value_h` 转发锥，后者 ~20.5~21.6 ns 才是真实地板）。

⇒ **48 MHz 是本 RTL family 能合规交付的最高频点**（P35a：20.581 ns ≤ 20.833，WNS +0.252）。
⇒ 50 MHz 缺口 0.135 ns，但确定性复现，不能靠重跑碰运气。

### 10.4 如果放弃 5.2 去换 120 MHz，代价是多少（供决策）

```
当前（48 MHz）：190,535 拍/迭代 → 5.2447
切 EX/AGU ↔ D$      +43,000 → 233,535 → 4.28
再切 ID ↔ EX        +351,000 → 584,535 → 1.71
```
⇒ **120 MHz 与 5.2 不能同时成立**：要 8.30 ns 必须把 20.58 ns 切成 3 段，
至少两段（43,000 + 351,000 拍量级），分数必然跌到 2 以下。
反过来说：**5.2447 @ 48 MHz 已经是在"≥5.2"这个硬约束下的频率最优解。**

## 11. 决定性实验：50 MHz 以上，限制是"布得通"而不是"路径短"（P38/P39/P40）

### 11.1 动机

`P31b` 的 `.rtr` 显示：切掉 LRU 那根锥之后，**第 4 条路径 slack 是 +6.438 ns（约 13.6 ns）**。
而在 `P33a`（用"延后一拍写"切同一根锥）里，同一个 CPU 转发锥变成了 21.6 ns。
差别只在"网表变了 ⇒ 摆放也变了"。于是尝试一种**几乎不改网表**的切法。

### 11.2 改法与代价（`rtl/core/dcache_axi.v`）

```verilog
// 旧：D 输入 = hit_way = 整条 m_inst→AGU→tag 比较锥
lru_mem[req_set] <= hit_way ? 1'b0 : 1'b1;
// 新：D 输入 = 该位自身的寄存器（一根反相器）
lru_mem[req_set] <= ~lru_mem[req_set];
```
2 路组相联里"交替选牺牲路"就是标准的 round-robin 近似（退化成轮转，不是随机）。

**实测**：`Total ticks 3,819,652`（+448 拍/迭代，分数 **5.2361**，仍 ≥5.2），CRC 全对，ISA 20/21。
⇒ 这根锥可以用 **0.008 分**的代价换掉。

### 11.3 但它没有换来频率：55/60 MHz 无法布线

| 构建 | 约束 | 摆放 WNS（估计）| 详细布线 |
|---|---|---|---|
| P39a | 60 MHz | +1077 ps → 15.59 ns | 停 7,359@29，斜率衰减 |
| P39b | 60 MHz | — | 停 7,038@29 |
| P40a | 55 MHz | +1155 ps → 16.98 ns | 停 **1,921@182**，斜率 −7 条/轮 |
| P40b | 55 MHz | +1051 ps → 17.30 ns | 停 3,317@97 |
| P35a | **48 MHz** | +2035 ps → 18.80 ns | **0 @ 151** ✓ |
| P31b/P33a/P37a | 50 MHz | 17.78~18.93 ns | 0 @ 151~322 ✓ |

**摆放 WNS 在 55/60 MHz 明显更好（15.6~17.0 ns），但布线收敛不了。**
⇒ 在 50 MHz 以上，瓶颈从"时序"切换成"**拥塞**"：
   更紧的约束让摆放器把逻辑聚得更密，局部利用率升高，布线器只能绕远；
   于是"路径变短了，但线走不通"。

### 11.4 最终天花板

```
48 MHz：可布线、可收敛、可合规（WNS +0.252）
50 MHz：可布线，确定性差 0.135 ns（4 次尝试：20.135/21.633/21.633/21.189）
52 MHz：未试，处在"能布通"与"拥塞"的交界
55 MHz 及以上：布线无法收敛（1,921~7,359 条未布通，斜率归零）
```

**结论：本设计的频率天花板由"可布线性"设定，约 48~52 MHz。
它与 120 MHz 之间的差距（2.3~2.5 倍）不可能靠调参、切策略位或换约束跨越，
只能靠降低单拍逻辑量（多级流水），而那会把 CoreMark/MHz 打到 4.3 以下（§10.4）。**

## 12. 上界证明：为什么"≥5.2 且 120 MHz"在本核上不可满足

这一节不依赖任何估计，全部用 `.sim_runs` 里固件与测试台自己打印的数。

### 12.1 三个实测原始量（计分窗口，20 迭代）

```
Total ticks        : 3,810,700       （固件自报）
Iterations         : 20
SCORE_WINDOW retires: 5,782,458      （测试台自报，正是这个计时窗口内的退休指令数）
DCDBG 读命中/缺失   : 596,992 / 123,821   （全程；写 143,921）
```

换算成每迭代：

| 量 | 每迭代 |
|---|---|
| 退休指令数 `I` | **289,123** |
| 周期数 `C` | **190,535** |
| IPC = I/C | **1.517** |
| load（命中+缺失） | ≈ **29,850** |
| store | ≈ **7,196** |

### 12.2 5.2 对应的硬门槛

`分数 = 20 × 10⁶ / Total_ticks ⇒ 5.2 ⇒ Total_ticks ≤ 3,846,154 ⇒ C ≤ 192,307`
在 `I` 不变的前提下，这等价于 **IPC ≥ 289,123 / 192,307 = 1.5034**。

**当前 IPC 1.517，已用掉 99.1% 的效率门槛；全部余量 = 1,772 拍 = 0.61%。**
换句话说：**每 100 条指令只允许再多花 0.61 拍。**

### 12.3 任何一级流水线都装不进这 0.61%

插入一级流水线，最少也要"每发生一次该事件 +1 拍"：

| 加一级的位置 | 受影响事件/迭代 | 代价 | 相对余量 1,772 |
|---|---|---|---|
| load 相关（D$ 访问独立成级）| 29,850 | +29,850 | **16.8 倍** |
| store 相关（提交寄存）| 7,196 | +7,196 | **4.1 倍** |
| 任意全局（ID/EX 分开）| 289,123 | +289,123 | **163 倍** |

⇒ **连"最便宜的一刀"都超预算 4 倍。**
⇒ 120 MHz 需要把 20.581 ns 压到 8.30 ns，即至少 **3 级**（每级 ≤8.3 ns），
   也就是至少加 **2 级**；任何组合都落在上表 4~163 倍的区间。

### 12.4 结论（可判定，不是主观判断）

> 在"CoreMark/MHz ≥ 5.2"的约束下，本核可用于加深流水的预算是 **0.61 拍/100 条指令**；
> 而任何一级流水线的单价 ≥ 4 拍/100 条指令（以最便宜的 store 计）。
> **故本核在 5.2 约束下无法加深流水线，也就无法把 20.58 ns 的时钟周期压到 8.30 ns。**
> 要同时满足 5.2 与 120 MHz，必须提高单周期吞吐（更宽的发射）而不是加深流水线：
> 例如 3 发射 @ IPC 2.3 且 3 级流水 —— 那是**重新设计一个核**，不是优化。

**这解释了为什么连续多轮的"再优化一点"都无法跨过 48~52 MHz：
瓶颈不在实现质量，而在"2 发射 + 单拍 L1"这个架构选择本身。**

### 12.5 完整频点扫描（45 → 60 MHz，全部为布线后实测）

| 约束 | 网表 | 布线后路径 | 是否收敛 | 判定 |
|---|---|---|---|---|
| 45 MHz | 字节通道 + LRU 延后 | 22.943 ns | 0 @211 | ✗ 差 0.72 |
| **48 MHz** | **字节通道 + LRU 延后** | **20.581 ns** | **0 @151** | **✓ WNS +0.252（交付）** |
| 50 MHz | 字节通道 + LRU 延后 | 21.633 ns | 0 @322 | ✗ 差 1.63 |
| 50 MHz | 字节通道 + LRU 交替 | 21.189 ns | 0 @371 | ✗ 差 1.19 |
| 50 MHz | 字节通道（未切 LRU）| **20.135 ns** | 0 @250 | ✗ 差 **0.135** |
| 52 MHz | 字节通道 + LRU 延后 | 22.460 ns | 0 @311 | ✗ 差 3.23 |
| 55 MHz | 字节通道 + LRU 交替 | — | 停 1,921 @182 | ✗ 布不通 |
| 60 MHz | 字节通道 + LRU 交替 | — | 停 7,359 @29 | ✗ 布不通 |

**这是一条 U 形曲线**：路径先随约束变紧而变短（45→50 的 22.9→20.1），
越过 50 之后又变长（52 的 22.5），再往上直接布不通（55/60）。
**谷底在 48~50 MHz，其中只有 48 MHz 同时满足"能布通 + 满足自身周期 + hold 干净"。**

⇒ 频点扫描到此闭合：**48 MHz 是这条 RTL family 的唯一合规高点。**

## 13. 剩余 CPI 杠杆的穷举与总和（P42，全部实测）

上界证明说"预算是 1,772 拍/迭代，最便宜的一级流水线要 7,196 拍"。
那唯一还能翻盘的机会是：**把所有剩余的周期回收手段都找出来，看总和够不够。**

| 杠杆 | 实测收益（拍/迭代）| CRC | 说明 |
|---|---|---|---|
| `-O3` 替代 `-O2` 编译 | **−425** | 全对 | 3,802,192 vs 3,810,700；只有 0.22%，说明热循环已很紧 |
| jalr 允许与 lane1 配对（`lane0_issue_alone` 去掉 `dec_jalr`）| **−417** | 全对 | 3,802,351；误预测同时 −1,789（20 迭代）|
| BTB 64→128 | **−515** | 全对 | 3,800,402；但要 +800 LUT |
| **三项合计** | **−1,357** | | 189,178 拍/迭代 → 分数 **5.2863** |

**结论（第三次收敛到同一处）**：

```
全部剩余 CPI 杠杆合计           1,357 拍/迭代
被砍到的最小一级流水线（store）  7,196 拍/迭代
                                -------
比值                            5.3 倍
```

⇒ **即使把 -O3、jalr 配对、BTB128 全部用上，仍然买不起最便宜的那一级流水线。**
⇒ 而 120 MHz 需要把 20.58 ns 切成 3 段（≥2 级）⇒ 差得更远（≥10 倍）。

### 13.1 为什么这些杠杆都这么小

因为本核的 IPC 已经 **1.517**，而 2 发射的理论上限是 2.0 ——
但"浪费"掉的 45,973 拍/迭代里，**绝大部分不是可消除的停顿，而是"第二条通道没有东西可配"**
（mem+mem 被 D$ 单端口禁止、load-use、乘除依赖、取指供给）。
这些要么需要双端口 D$（+512 LUTRAM 且要重写 LSU/D$ 握手），
要么需要改发射宽度 —— 都不是"调参"能拿到的。

### 13.2 频率侧的终极限制仍然是密度

52 MHz 能布通但路径 22.460 ns（差 3.23）；55 MHz 布不通。
把 D$ 从 4 KB 退回 2 KB 可以省 ~1.1 k LUT（对密度有利、路径也短一级），
但要付 +3,070 拍 —— 而全部剩余杠杆只有 1,357 拍，**不够付**。

⇒ 两条路（提频要降密度、降密度要掉分）在 5.2 这条线上**互相封死**。
