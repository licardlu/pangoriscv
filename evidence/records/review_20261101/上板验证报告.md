## 4. 120 MHz 稳定性评估

### 4.1 静态时序（PDS，约束 8.301404853 ns / 120.467 MHz）

| 检查项 | Slow 角 | Fast 角 |
|---|---:|---:|
| Setup WNS | **+0.036 ns** | +3.052 ns |
| Hold | **+0.028 ns** | **+0.016 ns** |
| Recovery | +4.369 ns | +5.764 ns |
| Removal | +0.351 ns | +0.248 ns |
| 最小脉宽 | +2.805 ns | +3.352 ns |
| 失败端点 | 0 | 0 |

推导：关键路径 8.3014 − 0.036 = 8.2654 ns → 等效 **Fmax ≈ 120.99 MHz**；
相对 120.000 MHz（8.3333 ns）的余量为 **+0.0679 ns**。

### 4.2 实板表现

- 5 次重新配置启动，全部一次成功，无卡死、无 CRC 错、无 TRAP；
- 每次结果逐位一致 → 在该板该温度该电压下**可重复**。

### 4.3 风险（必须说清）

1. **余量过薄**：setup 仅 36 ps（相对 120.000 MHz 也只有 68 ps），hold 最差 16 ps。这类量级小于板级电源噪声、时钟抖动与 PVT 漂移带来的影响，`+0.036` 属于"统计上过了"，不是"设计上有余量"。
2. **未做 PVT 扫描**：本次仅在室温、单板、单电源条件下测；未做高低温、欠压/过压、长时间老化（soak）。
3. **未覆盖 I/O 时序**：约束里没有板级 input/output delay，UART/LED 等接口的板级余量未验证。
4. **SRAM 配置**：`cfg_program` 走的是 SRAM 下载，掉电即失效；未验证从 Flash 固化上电启动的稳定性。

### 4.4 判定

- 按"工具时序闭合 + 实板可重复跑通"的口径：**120 MHz 可用，功能与分数稳定**。
- 按"工程稳健性"的口径：**不满足**，36 ps 的余量不足以支撑批量/变温场景；建议至少留 0.3–0.5 ns（对应约 116–118 MHz），或继续优化关键路径后再宣称"120 MHz 稳定"。


复现命令（本机 PDS 路径）：

```bash
# 1. 启动 JTAG 服务
D:/pango/PDS_2022.2-SP6.1/bin/cdt_js.exe -port 65420
# 2. 打开串口 COM20(115200) 后，执行 prog.tcl
D:/pango/PDS_2022.2-SP6.1/bin/cdt_cfg.exe -file C:/pv/run/run-001/prog.tcl -ip 127.0.0.1 -port 65420
```

注意：PDS 的 `cdt_cfg` 在脚本执行完后会挂在 `Fail to connect to server` 不退出，属正常现象，看 `prog_trace.txt` 里的 `PROGRAM_DONE` 即可；脚本与位流的路径必须是**纯 ASCII**，中文目录会导致 Tcl 打不开文件（日志中显示为 `???1`）。
