# v23 —— 5.2 分 / 120 MHz 目标：结论、可动杠杆与本轮执行计划

> 本文件是"先计划、后执行"的那份计划。所有数字都标了出处；**判据先写死，跑完照着核**。

## 0. 先把目标拆成三项独立指标

赛题口径（`docs/contest/`、skill `pango-riscv-contest` §3）：

| # | 指标 | 公式 | 当前交付 | 备注 |
|---|---|---|---|---|
| 1 | 执行效率 | `CoreMark/MHz = 1e6 / (ticks per iteration)` | **5.2484**（190,535 拍/迭代） | 与频率**无关**：提频不涨这一项 |
| 2 | 最高时钟 | 在各自时序约束下 `report_timing` 通过 | **50 MHz**（20.000 ns，布线 19.355） | 独立一项 |
| 3 | 资源效率 | `CoreMark / LUT` | **0.3056 /kLUT**（5.2484 / 17,174） | 面积越小越高 |

"5.2 分、120 MHz"= 指标 1 ≥ 5.2 **且** 指标 2 = 120 MHz。

## 1. 结论先行：这两项在本微架构上互斥（四条独立证据，均为实测/定标）

1. **静态 ILP 上界**（`tools/ilp_bound.py`，用实测 IPC 1.7525 校准，k=1.097）：
   CoreMark 指令流的 ILP 上限是 **IPC 2.504**（4 发射 + 4 访存端口，零流水线代价）。
   ⇒ 每迭代最少 **142,033 拍**（7.04 CoreMark/MHz），这是天花板。
2. **每加一级访存流水线的真实代价 = 34,757 拍/迭代**（探针实测 `load_use_1` = 695,148/20 迭代）。
   ⇒ 142,033 + 34,757 = 176,790（5.656，勉强还在 5.2 以上）；
   再加一级 = 211,547（**4.727，破线**）。
3. **120 MHz 需要几级**：本设计布线后 19.355 ns，其中 **Logic 3.685 ns / Route 16.470 ns**；
   120 MHz 预算是 8.333 ns ⇒ 需要 `S = 20.1 / 8.333 = 2.41` 级。
   ⇒ 至少 2 级。与第 2 条相乘，**即使做到 4 发射 + 4 访存端口，分数也只剩 4.73**。
4. **摆放地板实测**：`--freq 120 --place-only` 摆放后最差路径 **14.07 ns（slack −5.77）**，
   即这条网表的"摆放地板"≈ 70 MHz。60 MHz 约束摆 15.50、50 MHz 摆 18.32。
   ⇒ 120 MHz 不是"再调调参数"的事，必须动结构（切 2 级），而切级要花拍数，见第 2 条。

**所以"5.2 且 120 MHz"不是本轮能不能做到的问题，是被 ILP 上界和切级代价联合关死的问题。**
本文件不再重复论证，只做两件事：

* **A 线（守 5.2，抬指标 2 与指标 3）**：在不花一拍的前提下抬频率、压面积。
* **B 线（120 MHz 的真实路径）**：写成可执行的工程清单，标注工量与前置条件，不假装本轮能交付。

## 2. A 线的可动杠杆（按"每拍收益 / 风险"排序）

### 2.1 面积构成（本轮第一次拿到完整的层次面积表，来自 `p50cut2/synthesize/pangoriscv_top.snr`）

| 层次 | LUT | FF | LUTRAM | DRM | APM |
|---|---:|---:|---:|---:|---:|
| 总计 | 17,152 | 8,780 | 2,274 | 12 | 10 |
| `core` | 14,774 | 7,267 | 2,274 | 0 | 8 |
| ├ `cpu`（核本体+胶合） | **7,330** | 5,064 | 0 | 0 | 8 |
| │ ├ `u_bp`（BTB/预测器） | **1,089** | 1,664 | 0 | 0 | 0 |
| │ ├ `u_regs`（寄存器堆+读端口） | **1,137** | 992 | 0 | 0 | 0 |
| │ ├ `u_csr` | 442 | 289 | 0 | 0 | 0 |
| │ ├ `u_alu` / `u_alu_h` | 360 / 212 | 0 | 0 | 0 | 0 |
| │ └ `u_div` | 211 | 272 | 0 | 0 | 0 |
| ├ `data_cache` | 2,574 | 518 | **1,102** | 0 | 0 |
| ├ `instruction_cache` | 2,700 | 542 | **1,172** | 0 | 0 |
| ├ `ifu` | 1,906 | 1,038 | 0 | 0 | 0 |
| └ `lsu` | 259 | 105 | 0 | 0 | 0 |
| `data_ram`（16 KiB） | 188 | 180 | 0 | **4** | 0 |
| `program_ram`（32 KiB） | 134 | 109 | 0 | **8** | 0 |
| `fabric`（AXI 互联） | 729 | 144 | 0 | 0 | 2 |
| 外设（uart/spi/timer/gpio/irq） | 1,189 | 1,005 | 0 | 0 | 0 |

**两条新结论**（都推翻了旧记录）：

1. **16 KiB 数据 RAM 早就进 BRAM 了**（`data_ram` 4 DRM / 188 LUT）。
   `area-budget.csv` 里 M2 "blocked，2,048 LUTRAM"的条目已过时——
   所以"把 data_ram 搬进 BRAM 省 2,048 LUT"这条路**不存在**，别再走。
2. **2,274 LUTRAM 全部是两级 Cache 的阵列**（I$ 1,172 + D$ 1,102），
   而且**是被复制过的**：DRM 只有一个读口，而 RTL 每 bank 要 2 个异步读口，
   映射器只能把阵列复制一份（M5/M6 已记录）。
   ⇒ 这 2,274 LUT（占 13%）与"双 lane 同拍访存"是绑死的，
   换成 BRAM 就等于砍掉一个读口 = 加一级访存流水 = 18% 拍数（见 §1-2）。**不能动。**

⇒ 面积真正可动的是 `cpu` 的 7,330 LUT（其中 `u_bp` 1,089 + `u_regs` 1,137 = 2,226 是可讨论的），
和 `fabric` 729 + 外设 1,189。但它们都不是"免费的"：动 `u_bp` 会掉拍数，动外设会掉功能。

### 2.2 频率：唯一"零拍"的一步是 52 MHz

| 目标 | 周期 | 缺口（相对交付 19.355） | 历史结果 |
|---|---:|---:|---|
| 50 MHz | 20.000 | 已达成（+0.645） | 交付 `p48r50e` |
| 51 MHz | 19.608 | 0.253 ns | `p49r51` 布到 20.815 ✗ |
| **52 MHz** | **19.231** | **0.124 ns** | `p50r52` 20.222、`p52qual2` 发散 ✗ |
| 55 MHz | 18.181 | 1.174 ns | 最好 19.324（`p55max2`，另一棵树）✗ |

**52 MHz 是唯一"只差一点点"的一档**，而且不花一个拍（RTL 不动、镜像不变、分数不变）。
失败的三次都用了**默认布线配方**或**只加 `-enable_route_constraint_iterate`**（后者在 52 MHz 下直接发散：
`p52qual2` 到第 680 轮还有 1,259 根未布通）。

### 2.3 布线质量的六个未用选项（`help pnr` 全表 + 二进制里逐个确认存在）

| 选项 | 语义 | 对症 |
|---|---|---|
| `-dc_duplication TRUE` | 复制驱动单元 | 打 `mem_from_h` fanout=126（0.861 ns）、`rr_rs1[4]` fanout=39（1.051 ns） |
| `-slack_prior_in_global_router TRUE` | 全局布线按 slack 优先 | 关键网线先占短通道 |
| `-refineplacement_cluster TRUE` | 摆放后按连接关系重聚类 | 缩短物理距离（12 段路径 82% 是线延时） |
| `-optimize_routing_recovery TRUE` | 布线期 recovery 回修 | 布线后回修最差路径 |

（`p55max2` 用 `-enable_route_constraint_iterate` 拿到全族最好的 19.324 ns，
但它在 52 MHz 下会发散，**本轮不用**。）

## 3. 本轮执行阶段与判据（gate 先写死）

### 阶段 0 —— 收枝（已完成）

* 目标：只有一个 `main`，其余分支全部删除；`main` 上同时有
  ① 拍数最优的 RTL（cut-2，`LUT 17,021`，ticks 与交付**逐位相同**）
  ② 最新文档（plan v22）③ 上板一键脚本 `board_verify.ps1`。
* 判据：`git branch` 只有 `main`；`git status` 干净；RTL 综合面积 ≤ 17,021 LUT。

### 阶段 1 —— 仿真回归（守 5.2 的唯一门槛）

* 判据（全部必须）：
  1. CoreMark 20 迭代 `Total ticks == 3,810,700`（逐位相同）
  2. 五项 CRC：`0xe714 / 0x1fd7 / 0x8e3a / 0x4983` + seedcrc
  3. ISA e2e **21/21**
* 不通过 ⇒ 立即回退 RTL，不得进实现。

### 阶段 2 —— 52 MHz 满实现（`p58r52`）

* 配置：cut-2 RTL + PLL `27*52/27`（VCO 1404）+ 约束 `--freq 52`（19.231 ns）
  + §2.3 的四个选项（**不加** `-enable_route_constraint_iterate`）
  + 镜像 `hw_i2900_52b`（2900 迭代，2900×190,535÷52e6 = 10.63 s ≥ 10 s）
* 判据：

  | # | 判据 | 阈值 |
  |---|---|---|
  | 1 | `Unrouted nets` | 0 |
  | 2 | `Design Summary` | `All Constraints Met` |
  | 3 | setup WNS / 失败端点 | ≥ 0 / 0 |
  | 4 | hold WHS / 失败端点 | ≥ 0 / 0 |
  | 5 | LUT | ≤ 18,000 |
  | 6 | 位流里有程序 | `Loading memory data from file`×2、`Cannot open specified data file`×0 |

* 通过 ⇒ 三项变成 **5.2484 / 52 MHz / 0.3083**（频率 +4%，面积 +0.9%，拍数不变）。
* 不通过 ⇒ 交付保持 50 MHz；本阶段结论降级为"布线地板的又一次抽样"，
  并按阶段 2b 退守 50 MHz 同配方（只换频率，判断选项本身是否有害）。

### 阶段 2b（仅当 2 失败）—— 50 MHz 同配方

* 目的：把"失败原因是 52 MHz 约束"和"失败原因是新选项"分开。
* 判据同阶段 2（周期 20.000）。通过 ⇒ 新交付为 50 MHz / 17,021 LUT / 0.3083。

### 阶段 3 —— 上板实测（唯一有效的指标 2 证据）

* 一键：`firmware/code/tools/board_verify.ps1 -Sbit <位流> -FreqMhz <f> -Iterations <n>`
  它先做**下载线预检**（把"线没插/端口不对/板子没电"三种 `No devices detected` 分开），
  再**先开串口后烧写**（CoreMark 报告只发一次，配置后 ~10.7 s）。
* 判据：
  1. `cfg_scan_chain` 报 `PG2L100H` 且 `done bit: 1`
  2. 串口收到完整报告，**五项 CRC 全对** + `Correct operation validated`
  3. `iterations / ticks * 1e6` 与仿真分数一致（±0.05%）
  4. `ticks / 频率 ≥ 10 s`
* 失败原因分类（`board_verify.ps1` 已实现）：退出码 3 = 下载线未枚举；4 = 报告不完整/CRC 错；5 = 串口打不开。

## 4. B 线：120 MHz 的真实工程清单（本轮不交付，写清前置与工量）

按 §1，唯一能同时满足"120 MHz 且 ≥5.2"的结构是：

```
4 发射 + 16 B/拍取指 + 4 个独立访存端口 + 2 级访存流水
⇒ 142,033 + 1×34,757 = 176,790 拍/迭代 = 5.656（1 级）
⇒ 142,033 + 2×34,757 = 211,547 拍/迭代 = 4.727（2 级，破线）
```

即：**2 级访存流水时，只有把"零级代价"的每迭代拍数压到 150,000 以下
（= IPC 3.0 以上）才可能守住 5.2，而 CoreMark 的 ILP 上限只有 2.504。**
所以 B 线在数学上就不存在，除非换基准或换算法（不允许）。

可以交付的中间形态（按指标 2 优先，放弃指标 1）：

| 形态 | 频率 | 分数 | 需要的结构 |
|---|---|---|---|
| 现交付 | 50 MHz | 5.25 | — |
| 1 级访存流水 | ~70 MHz（摆放地板） | ~4.7 | D$ 输出寄存 + 地址在 ID 算好 |
| 2 级访存流水 | ~100–120 MHz | ~4.4 | 再加一级；访存端口要真并发 |

工量估计：1 级 ≈ 3~5 天（含 ISA 21 项回归 + 上板），2 级再加 3~5 天。
**这不是一次会话能完成的事，也不该被说成"再试试就行"。**

## 5. 本轮不做什么（避免重复踩坑）

| 不做 | 原因（已实测） |
|---|---|
| 换 `pnr -seed` | 静默 no-op，seed 3 与 seed 7 摆放逐位相同 |
| 重跑同一棵网表 | 同一网表的摆放是确定性的，重跑结果相同 |
| 加 `-place_worst_slack` | 要 +8 ns 反而让摆放从 16.93 退到 17.18 |
| 两步流程（紧约束摆放 + 松约束布线） | 摆出来是拥塞布局：60 MHz 摆 15.45，布线吃 4.7 ns 到 20.204 |
| floorplan / 区域约束 | 横带/竖带/紧凑方块三种形状全部负优化 |
| 把 Cache 阵列搬 BRAM | 复制是为了第二个读口；砍读口 = 加一级访存 = 18% 拍数 |
| `lane0-load → lane1` 旁路 | 仿真 +0.66% 分，但两棵不同网表都吃 3.9~4.8 ns 摆放 |
| `ls/sl/ss` store buffer | 配对 100% 成功，ticks 只动 20 拍（store 仍占同一端口） |
