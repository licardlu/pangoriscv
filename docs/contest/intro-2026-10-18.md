# pangoriscv 作品简介

RV32IM 处理器 + 片上系统，紫光同创 PG2L100H。本页只讲**优化到什么程度**和**改了什么**。

## 一、优化程度

| 指标 | 优化前 | 优化后 | 变化 |
|---|---|---|---|
| 综合效率（CoreMark/MHz） | 1.3054 | **1.8622** | **+42.7%** |
| 每迭代周期数 | 766,039 | 536,987 | **−29.9%** |
| 每周期完成指令数（IPC） | 0.376 | 0.536 | +42.6% |
| 逻辑单元（LUT） | 12,572 | 13,059 | +3.9% |
| 单位资源产出（CoreMark/kLUT） | 0.1038 | **0.1426** | **+37.3%** |
| 时钟约束 | 27 MHz 零失败 | 27 MHz、50 MHz **均零失败** | — |

**一句话**：速度提升 42.7%，面积只增加 3.9%，所以"单位资源产出的效率"也涨了 37.3%。

提升分三步完成，每步都用同一份镜像做过对照：

| 步骤 | 做法 | 贡献 |
|---|---|---|
| 第一步 | 优化访存写路径（写内存不再死等总线确认） | **+9.9%**（1.3054 → 1.4342） |
| 第二步 | 拓宽取指令通道（一次可等两条指令） | **+17.2%**（1.4342 → 1.6815） |
| 第三步（本版） | 取内存不再空等一拍（见下） | **+10.8%**（1.6815 → 1.8622） |

因为不断变快，迭代数必须跟着重算（赛题要求单次运行不少于 10 秒），
本版是 **576 次迭代、实测 11.46 秒**，五项校验值全部正确。

## 二、修改点（本版）

本版只动**一个文件**（`lsu_axi.v`，访存单元），端口一个没变：

**取内存原来要空等一拍，现在不用了**

访存单元原来的流程是：先收下地址 → **存进寄存器** → 下一拍才去问缓存。
中间那一拍纯粹是"先把地址存好再发问"，不干任何实事。

现在改成：收下地址的**同一拍就把请求发出去**，缓存当拍收下就直接进入等待结果的状态，
跳过那个多余的 `REQUEST` 状态。

> 缓存此刻正忙（比如上一笔写还在等总线确认）时，请求发不出去，就自动退回原来的
> `REQUEST` 状态再等一拍——**功能与原来逐位等价，只是常见路径少了一拍**。

**验证手段配套补充**

- 跑分测试台新增按访存状态逐步计数的探针（`LSU_PATH`），先量出"这一拍占了多少"再动手
- 新增"同一份镜像、两个版本"的跑分对比工具，以及只跑到资源映射的资源对比脚本
  （保证"性能涨了多少、面积涨了多少"是同一流程量出来的）

## 三、效果验证

| 检查 | 结果 |
|---|---|
| 访存单元白等的 `REQUEST` 拍数 | **−73.5%**（1,852,431 → 490,318 拍） |
| 访存占用执行单元的拍数 | **−1,265,115 拍** |
| 整体周期 | **−8.39%**；跑分 ticks **−9.71%** |
| 取指饥饿 / 缓存缺失 / 分支预测失败 | **未变差** ← 证明收益确实来自访存路径 |
| 触发器数量 | **零增量**（纯组合逻辑改动，只多 41 个 LUT） |
| 跑分五项校验值 | 与优化前**逐项一致** |
| 指令集功能测试 | **15 项全过** |
| 其他回归 | 单元、中断/复位、访存单元、数据引擎、缓存等**全部通过** |

## 四、口径说明

- 以上跑分数据来自**周期精确的 RTL 仿真**，不是板上实测（目前没有物理开发板）。
  固件按 27 MHz 把周期数换算成秒，所以在 27 MHz 板卡上即为 11.46 秒。
- 时钟频率一栏的 27 MHz 是**板载晶振的交付约束**；50 MHz 是**过约束压力测试**，
  证明设计的时序余量，不等同于板上实测最高频率。两者口径分开，不混称。
- 位流、资源报告、时序报告出自**同一份实现**，可互相校对。
