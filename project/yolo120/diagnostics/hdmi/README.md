# HDMI 黑屏独立诊断

`hdmi_startup_top.v` 持续产生 1280×720、74.25 MHz、约 60 Hz 的八段彩条。
它不读取摄像头、DDR 或 YOLO，目的是把显示链路从推理链路中独立出来。
必须接开发板 **HDMI OUT**。屏幕 USB 接电脑只提供其自身供电/触控连接；
本设计的视频信号通过 FPGA 的 HDMI OUT 连接到屏幕 HDMI 输入。

COM34 为 115200 8N1，新诊断每 10 ms 一行，例如：

```text
HDMI720 L=1 R=1 I=1 RD=00 A=0502
```

L 为视频 PLL 锁定，R 为 HDMI 芯片复位已释放，I 为原配 MS7210
初始化序列结束；RD 为最近一次 I²C 读取值，A 为当前寄存器地址。
I=0、A=0003 表示尚未通过驱动的 0x5A 写入/读回检查，应检查板卡控制链路。
I=1 只表示初始化状态，不能据此宣布外接屏幕已亮或已显示摄像头画面。

初始化后的诊断依次读取 16 个状态/配置寄存器，每地址停留至少 20 ms。
`A` 与 `RD` 来自同一次已完成读取；不会在 I²C 忙时切换地址，也不新增寄存器写入。
`0x0502` 的 bit 0 可辅助判断连接状态，`0x051d` 的 bit 4 是 CTS 稳定状态；
这些位不能代替屏幕出图确认。其他地址用于核对静音、PLL/输出驱动及输入模式。
寄存器名称和位含义参考公开 [MS7210 Linux 驱动](https://github.com/avmwww/ms7210-linux-driver/tree/d7632336b5369c3241256108e336310d018f8259)
的 `ms7210.h`、`ms7210_detect` 和 `ms7210_hdmi_tx_shell_timing_stable`。
没有把外部驱动代码复制进设计。

HDMI AVI 信息帧现与实际 720p60 时序一致：RGB、BT.709、16:9、CEA VIC 4。
原表的 4:3 与未指定 VIC 已修正，校验和同步更新为 B3；这是格式一致性和兼容性
修正，不能据此认定黑屏已经解决。`hdmi_avi_tb.sv` 驱动真实初始化控制器，
核对实际发出的 14 字节 AVI 数据、头部、校验和和完整初始化；
`check.py` 同时检查完整彩条帧、UART 波形与只读状态扫描。

构建：`<python> project/yolo120/diagnostics/hdmi/build.py --name hdmi-startup-001`。
每次使用新名称，禁止覆盖实现记录。构建会保留最终多角 STA 与位流哈希；
下载使用现有 JTAG SRAM 工具，不写 Flash。YOLO 正式构建与此诊断互不覆盖。
