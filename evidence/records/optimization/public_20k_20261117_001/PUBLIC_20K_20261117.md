# 扩大公开检测数据续训（2026-11-17）

用户要求自行寻找垃圾分类项目的数据集，争取约 2 万张并继续训练，提高电池、玻璃、手与背景的区分。本轮工作限定为数据与离线训练/评估；模型结构和部署策略保持可比，板卡不自动更新。

## 数据冻结

有效输入是 `build/public_20k_20261117_001/dataset_004`，训练为 `runs/expanded_clean_004`，训练前设置和通过标准在 `training_plan_final.json`。独立训练图按文件 SHA 为 **7,904**；其中旧清洗白名单 2,834、新图 5,070。另留 **712** 张新来源 dev，旧 **1,929** 张 val 原样保留；test 图片/标签不读取。

新来源数量：Drinking 3,626、bbox 派生版金属/玻璃/生物垃圾 1,106、箱体投放实拍 333、电池检测 5。参考项目、原始规模、标注类型、弃用原因及许可证声明见 [数据研究报告](PUBLIC_DATASET_RESEARCH_20261117.md)。更多下载不等于更多可入训图片：白底分类数据、漏框、同源近重复、广告包装印刷食物、纸杯政策冲突都可能伤害实际识别。

数据白名单继承最新 `continuation_023_dataset_001`，未重引旧 stage4 曾清理拒绝的 1,169 行。按旧 source identity、SHA、RGB像素SHA、pHash≤6 排除历史重合；旧 test 仅用已有元数据，21 条历史 test 缺 pHash 的图不打开补算。新来源按序列 block / 捕获组隔离 dev，不能据此保证每一件实物完全独立。

源标注经格式、坐标、标签类序和实际标签文件校验、分层人工抽检、palm 与原模型嫌疑手排除。不是全部逐图人工 gold；手筛可能漏检。实际标签审计通过 8,345 个非回放别名行，每个图/标签路径存在，标签解析与 manifest 框逐值一致。按文件 SHA 旧样本本身有不同路径重复，因此非别名行数量仍大于独立图片数。

为了防止新增瓶罐淹没原电池/手等类，每轮 **12,662** 次采样，包括 **4,317** 个显式回放 hardlink 别名；独立图仍为 7,904。draw 主类数量为可回收 6,224、有害 2,613、手 1,456、其他 1,206、厨余 1,163。这些是主类采样数，不是各类所有框的数量。

## 准备异常及修正记录

第一次 `expanded_clean_001` 在首轮完成前发现 YOLO 标签 cache 按路径做字典，合并 train.txt 的重复路径，使旧样本 replay 实际没有生效。立即中止并标记 `aborted_invalid_replay`，不产生可交付候选。新准备器用不同路径的 hardlink 回放，保留原图 SHA 和 `replay_of`。第二次准备器对 Windows 路径未先转 POSIX，解析标签路径失败；保留不完整 dataset_002，训练 `expanded_clean_002` 因缺 data.yaml 启动即失败，没有训练。修正后 dataset_003 的实际 loader 确认为 792 个 batch。

扩展抽查箱体源时又看到两张石块的同一物体被同时标为有害与其他。对新来源全部框做不同类 IoU≥0.70 冲突排查，查出正是两张；中止尚未完成第一轮的 `expanded_clean_003`，明确标为无效。只在新 dataset_004 中排除这两张，从原 stage4 重新启动 `expanded_clean_004`。各失败目录和日志原样保留，没有原地换图继续训练或交付。

## 固定训练与判定

原 stage4 checkpoint SHA：`a4a0b1b04f83af1d114813e0512dd2c2fa5e7306fae16759824f136b3133021a`。CPU4线程、batch16、320方形、10轮，AdamW，freeze4与该部分BN，lr0/bias warmup均0.0001、seed20261111、既有增强；不使用已经失败的额外 hard-negative loss。按上游原 val fitness 选择 best，不以新 publicdev 挑轮次、不扫阈值。

训练完成后，对 best 做固定方形320、single-label、conf0.25、NMS0.45/max32 的旧 val 与新 dev 推理，并通过 continuation_023 实际 C 策略回放。旧 val 冻结浮点要求：主体正确类别且IoU≥0.5 至少1457/1793、空手背景误选至多8/136、电池至少54/60、公开玻璃至少231/242，且至少一项严格改善；新dev主体正确数和背景误选不能退化。原val是已反复开发的验证集，不能表述为独立最终泛化成绩。

只有浮点门槛通过才量化：固定回放原160张有序train校准，identity SHA `f9e83b5deb2db0100958165d646f2d30156a60ab97cff91a53947f60c95d9532`。软件Q15旧val门槛：主体≥1455、误选≤8、电池≥55、玻璃≥232且至少一项改善；通过后仍需新域与部署材料复核，不自动上板。任何门槛失败保留原权重，不把更低损失或总mAP当作现场识别提升。

评估队列已启动在本轮同一目录，状态为 `evaluation_004_state.json`，等待有效训练完成后执行；非调度自动化、不访问板卡。原部署 blob SHA `7a0765a6f275f3c06d838f924d73542783ca55e131509aa1b546efc98bd65728` 在队列启动时核对并在每个评估步骤及退出时再次核对。
