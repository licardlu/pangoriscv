## 1. 一句话现状

**分数已经拿到 5.2165（仿真，CRC 全对），比交付基线 5.213 略高；45 MHz 的摆放也
干净通过（WNS +1.462 ns、TNS = 0）。但 45 MHz 的详细布线三次都没收敛——
这不是面积或算力问题，是**在这个利用率上布线收敛本身是抽签**。**
**120 MHz 还需要两步结构性改动，且顺序不能反（见 §6）。**

## 4. 关键实测数据（后续所有决策都该基于这些，别再重新推导）

### 4.1 计时区间内的真实周期账（每迭代 190,395 拍）

**方法铁律**：`Total ticks` 只覆盖计时区间。必须用 **1 迭代 vs 20 迭代相减**
才能得到纯迭代账。不剥离会把启动期 UART 轮询（122k 次 miss，约 100 万拍）
当成最大瓶颈。脚本：`--define RV32_PROF` 跑 `sim1_O2` 与 `sim20_O2` 两份镜像相减。

| 桶 | 拍/迭代 | 占比 |
|---|---|---|
| `pair`（理想双发射） | 124,262 | 65.3% |
| **`single`（丢一个槽）** | **42,149** | **22.1%** |
| `memwait` | 10,390 | 5.5% |
| `starve` | 8,641 | 4.5% |
| `redir` | 4,945 | 2.6% |
| `divwait` | 8 | — |

`single` 明细：`nopair` 12,436 / **`l1mem` 12,256** / `l1ctrl` 10,257（其中约 6,600
其实是 load-use，见 mistakes-log §52）/ `mduse` 3,576 / `l1notok` 1,706 /
`alone` 1,240 / `lduse` 679。

### 4.2 关键路径逐跳（`p15nx45/report_timing/pangoriscv_top.rtr`，45 MHz 布线后 24.60 ns）

| 段 | 内容 | 耗时 |
|---|---|---|
| A | 译码/转发 mux → **ALU** → ALU 输出 mux | **8.67 ns** |
| B | AGU 进位链 | 1.43 ns |
| C | D-cache 请求（P16 已摘除） | 2.61 ns |
| D | `br_miss` → `redirect_pc` | 1.44 ns |
| E | **I$ tag 读出 + way 选择** | **4.00 ns** |
| F | IFU 队列写使能 | 1.20 ns |

**单元延迟 3.84 ns，网络延迟 20.2 ns（84%）**，28 跳，平均 0.72 ns/跳。

### 4.3 被数据否掉的四个假设（别再试）

1. **RAS 没用**：`ret` 37,228 次，但 jalr 误预测只有 7,556 → 收益 ≤0.3%。
2. **BTB 扩容饱和**：64→256 只省 812 拍/迭代，却要 +8,000 LUT。
3. **`memwait` 不是 21%**，计时区间内只有 5.5%。
4. **floorplan/区域约束**：横带、竖带、紧凑方块三种形状全部负优化（已三次证伪）。

### 4.4 布线是抽签（最重要的一条）

同器件、同参数、同 seed 7、面积只差 24 LUT（0.13%）：

| 构建 | 约束 | LUT | 结果 |
|---|---|---|---|
| p13 | 36 MHz | ~18,400 | **收敛 285 轮**（就是现在的交付位流）|
| p15nx45 | 45 MHz | 18,157 | **收敛 575 轮** |
| p16r45c | 45 MHz | 18,957 | 不收敛 |
| p17r45 | 45 MHz | 18,181 | 不收敛（震荡 1.25k~1.7k）|
| p17r45s3 | 45 MHz | 18,181 | 不收敛（震荡 1.27k~1.38k，跑到 279 轮停）|

⇒ **27% 利用率下，"能否收敛"不是面积/算力的确定函数，是摆放噪声。**
`MEMORY.md` 里"靠换 seed 抽签"是正确经验，但每次要 1.5 h。
**想摆脱抽签必须把面积压到拐点以下**（经验：≤18,000 LUT 成功率高，≥18,950 为 0）。

**算力已排除**：布线期 `pds_shell` 稳定 1.1~1.5 核（18 逻辑核），整机 CPU 26.5%，
GPU 波动来自桌面合成，NPU 无计数器。监控脚本 `tools/watch_pnr.ps1`。

## 5. 下一步（按优先级，第一条最要紧）

### 5.1 先给当前 RTL 出一个能收敛的位流

**分数与频率无关**，所以频率选低一点不损失分数，只影响"最高时钟频率"那一项。

```bash
cd pangoriscv/firmware/code
# 1) 36 MHz 约束（历史 2/2 收敛）——最稳
python tools/run_pds_flow.py --tag p17r36 --freq 36 --mode full --seed 7 \
  --pnr-extra "-plc_decongestion 1 -share_router_control_signal TRUE" \
  --image build/native_software/coremark/performance/hw_i2700_36
#    （镜像需先按 36 MHz 重建：tools/build_native_software.py coremark
#      --iterations 2300 --mode performance --cpu-mhz 36 ...）
# 2) 上板抓 UART
cd pangoriscv/evidence/records/bottleneck_audit/board
powershell tools\flash_and_capture.ps1 -Bit <sbit> -Port COM34 -Seconds 90
```
**注意**：PLL 参数在 `rtl/soc/pangoriscv_top.v`（`STATIC_RATIOF`/`STATIC_RATIO0`），
当前是 `50/30` = 45 MHz，**改频率必须同时改 PLL**。45.000 = 27×50/30；
40.000 = 27×40/27；36.000 = 27×56/42。

判据：上板 `Total ticks` ≈ 3,833,976（±0.1%），CRC 五项 `0x4983 / 0xe714 / 0x1fd7 /
0x8e3a / 0x54414c55`。

### 5.2 想上 45 MHz：继续抽签，但要先省面积

- 直接换 seed 重跑（`--seed 3/11/21`），每次 1.5 h 抽一次；
- 或先压面积到 ≤18,000 LUT 再跑，成功率会明显上升。
  **可省的候选**（未验证，需自己量）：I$ 的 `succ0/succ1` 跨行配对侧阵列（53×64×2 bit）、
  fetch 队列 DEPTH 8→4、BTB 32→16（会掉分）。

### 5.3 上板验证注意

- 串口 **COM34**，115200；烧录脚本必须先开串口再配置 FPGA（原因见脚本头注释）。
- 镜像迭代数要满足 ≥10 s：45 MHz 用 2700 迭代，36 MHz 用 2300 迭代。
- 旧的 6 个 `vsimk` 僵尸进程杀不掉，会占 `.sim_runs` 句柄；**重启后可清**。

## 6. 120 MHz：定量结论与唯一可行顺序

```
现状                      190,129 拍/迭代    5.2165
+ 双端口 D$               −12,256            → 177,873   5.62
− 第 1 刀（寄存重定向）    +4,945            → 182,818   5.47   约 80 MHz
− 第 2 刀（ALU/AGU 分级）  +5,000（估）      → 187,818   5.32   约 110~120 MHz
```
- 5.2 的预算上限是 **192,307 拍/迭代**，当前余量只有 **2,178（1.15%）**；
- **每切一刀 = +4,945 拍**（重定向次数实测 4,945/迭代）；
- **所以必须先做双端口 D$**（把 `l1mem` 的 12,256 拍拿回来），否则第一刀就掉到 5.126；
- 双端口 D$ 的判据：`Total ticks ≤ 3,620,000`（≥5.52）、ISA ≥20/21、**LUT ≤ 20,000**。

**为什么 120 MHz 必须切两刀**：24.60 ns / 28 跳，84% 是布线；8.333 ns 只能容 ≤11 跳。
A 段（ALU 8.67 ns）和 E 段（I$ 4.00 ns）各自都超过 8.333 ns 的一半，必须各自成级。

### 6.1 第一刀怎么切（已调研清楚，未实施）

`rtl/core/ifu_axi.v`：
```verilog
wire [31:0] fetch_ptr = redirect_valid ? redirect_pc :
                        (transparent ? fetch_pc : next_pc_q);
```
去掉 `redirect_valid ? redirect_pc` 这一项（连同 `if(redirect_valid&&issue)` 那块
“在重定向当拍就发请求”的逻辑一起改成下一拍由 `transparent` 发出），
重定向就退出 I$ 地址路径。**代价恰好是可预测的 +1 拍/重定向 = +4,945 拍/迭代。**

### 6.2 第二刀

ALU 结果打一拍，AGU 与 D$ 地址放到下一级。代价主要是 load-use +1 拍，需实测。

## 8. 本轮方法论教训（已写进 `docs/lessons/mistakes-log.md` §52–53）

1. **互斥分桶的 `else if` 顺序会把重叠原因错标成单一原因**
   —— 估收益要看**独立**（非互斥）计数器，互斥桶只用来校验加总。
   这次因此把 3,610 高估成 10,257，差 2.8 倍。
2. **TB 的周期性 `$display` 会冲掉 UART 报告里的 `Total ticks`**（那行就是分数）。
   已把 `PROGRESS`/`LIVE` 包进 `` `ifdef TB_PROGRESS ``，默认关闭。
   注意 `` `ifdef `` 必须包住整个 `if(...) begin ... end`。
