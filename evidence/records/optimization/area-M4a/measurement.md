# area-M4a：取指队列 DEPTH 16→8 —— 实测 LUT −1,107 / FF −1,306

日期：2026-10-21
阶段：`module-area-plan.md` 的 **M4a**
性质：**参数改动**（`ifu_axi` 的 `DEPTH` 默认值 16 → 8），无逻辑改动

---

## 1. 做了什么

`rtl/core/ifu_axi.v`：

```verilog
parameter integer DEPTH=8     // was 16
```

队列每个条目 = 5 个 32 位数组（`q_pc/q_inst/q_pred/q_inst_hi/q_pred_hi`）
+ `q_cause[4:0]` + `q_pair/q_fault` ≈ 167 位；8 条目可省 8×167 ≈ 1,336 FF。

**为什么 8 是"已测配置"**：单元测试从一开始就用 `ifu_axi #(.DEPTH(8))`
（`tb/unit/tb_ifu_axi.sv`、`tb/axi/tb_ifu_axi_engine.sv`），所以 8 是回归覆盖过的深度；
预取本来就受 `count + 2*ocnt + 2 <= DEPTH` 约束，变浅只缩短预取跑道。

## 6. 与 M4b 的关系（计划更正）

原计划 M4b 要删 `q_pred_hi`（估计 −512 FF）。**这个假设是错的**：
`q_pred_hi` 存的是 BTB 第三个查表口对**配对第二条（PC+4）**的预测目标，
不是"PC+4 可派生"的常量——配对第二条若本身是控制转移，它的下一 PC 只能来自 BTB。
要删它必须在消费端再加一个 BTB 查表口（约 +100 LUT），净收益只有约 −400 站点，
属于功能重构而非 FF 裁剪。**本步先跳过**，并在 D1 的 §11 记为"已评估、暂不做"。
