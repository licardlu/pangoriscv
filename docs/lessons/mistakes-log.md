# 可复用的排错经验

## FPGA配置和实时画面正常，但CP210x串口持续零字节回复

现象：JTAG program/即时及5秒状态通过，用户确认实时摄像头和心跳正常，固件只读状态命令仍反复收到0字节；模型尚未开始写入。

查什么：先核对正确COM口、115200/8N1、关闭硬件流控、端口无其他程序占用；把JTAG配置成功与CPU串口/模型CRC分别记录。画面实时且心跳持续时，不能只凭串口无回复就断言DDR未初始化。

原因：USB串口链路或驱动会话可能未恢复，仅对FPGA重新配置或开发板电源重启不一定重建电脑端USB会话；这不是已证明的模型或RTL故障。

怎么办：先做有界只读状态探测，尚未收到有效回复不得盲目开始模型写入或重放写命令。仅重启指定CP210x设备若被Windows拒绝访问，应明确说明并请用户拔插对应电脑端USB串口线，保持板电源/JTAG。恢复后先验证协议回复，再用新证据目录完成配套模型CRC/数值/自动模式；不把旧的成功记录当本次验收。本次用户重插后cmd8恢复372字节回复，可作为此处理路径的证据，不能泛化为所有零回复都由USB引起。

## 修改训练入口源码后，新增损失没有执行但训练仍完成

现象：训练正常生成checkpoint，新增约束的计数却为0；仅看磁盘源码能找到调用，不能证明运行时用到了它。

查什么：检查修改源码与Python import的先后顺序，确认已经导入的函数是否仍是旧代码；检查真实训练batch计数及非零匹配/损失，而非仅确认辅助类已实例化。

原因：模块导入后函数已编译到内存，之后重写同名源码不会改变正在执行的函数；只修改磁盘文件会留下“代码看似接好、约束实际未用”的假通过。

怎么办：所有受控源码补丁必须在首次import前完成，记录补丁哈希。先用真实train/val小样本验证新增路径被训练batch调用，验证不调用、checkpoint可独立加载且不携带教师；正式训练在约束启用但计数为0时立即失败。无效试跑保留并标记作废，不作为效果证据。

## 增加内部定位类后，手框明明重合却报告全部TP=0

现象：预测图能看到手框，但评估报告TP为0；或给真实手框的oracle关联比肉眼结果更差。

查什么：分别核对模型类别与标注数据类别。nc=1手分支的hand为0，四桶加手模型为4；再检查混合标注行是否按位置而非类别取手框。

原因：检测匹配同时比较类别和IoU，不同的内部编号会使所有重合框匹配失败。混合图里第一行可能是物品，用它作为oracle手会进一步污染关联结论。

怎么办：只在指标副本中将预测手与真值手都归一化为同一指标类，业务原始类别保持；按data.yaml中的hand编号筛选标注，不假定行次序。用分支/联合同几何、物品行在手前、空框三个用例回归。在新证据目录重评并标记旧指标作废，不覆盖原始报告。手框召回、误手、主体定位及桶一致分开报告。

## 增加模型类别后，固件链接报预留堆栈不足

现象：四类能链接，增加内部定位类后触发`Less than 8 KiB CPU stack remains`；程序二进制虽小于64 KiB，仍不能证明可运行。

查什么：同轮链接map的text/data/BSS、`_bss_end`与`_stack_top`，解码Top-K缓存是否按类别数增加；同时查检测头宽度、运行时硬编码校验、编译类别宏及模型映射是否一致。

原因：程序、静态工作区和堆栈共用片上RAM。新增类别扩大解码缓存；分别分配取图行、算子scratch与解码缓存会浪费实际从不并行使用的内存。

怎么办：保持原最小堆栈断言，不通过删检查或缩Top-K掩盖问题。先证明阶段严格顺序及回调不重入，再用真实union成员共享临时缓存，保留跨阶段的结果与配置；禁止用不兼容结构指针强转。重跑真实CPU算术/解码，先污染工作区检查无旧值依赖，核对实际RISC-V map和固件/模型/ROM身份。软件内存优化不能代替最终物理资源与板上验证。

## 复用映射/放置后，PDS汇总资源为NA但布线已完成

现象：复用mapped/placed ADF的实现最终STA通过，`multiseed_summary.csv`的Device Map资源字段却为NA，面积门禁无法解析。

查什么：同轮`place_route/*.prr`的Device Utilization Summary和布线日志；区分Device Map阶段与最终布线阶段，不能填旧映射值冒充当前资源。

原因：复用数据库没有在本轮重做Device Map，因此摘要没有对应阶段统计；hold修复也可能增加最终逻辑。PDS将CLMA和CLMS的FF/LUT分两行，仅读第一行会低估总量。

怎么办：保留原始summary，从同轮最终`.prr`提取独立资源CSV，FF/LUT对两种资源池求和，并检查字段完整及器件容量后执行应用预算门禁。保存原`.prr`作为CSV来源；资源门禁与最终多角STA都通过才生成位流。

## PDS 粗布线结束后，详细布线长期在几千条未完成连接附近反复

现象：工具继续消耗 CPU，`Unrouted nets` 在多轮中变化很小，单轮耗时逐渐增加；粗布线到零不等于详细布线完成。

查什么：区分日志中的 global/detailed routing 阶段；按连续多轮趋势而非单次数字判断。核对实际子进程命令和 `.pds`：TRUE 默认选项可能被省略，显式写 TRUE 并不意味着切换策略。检查 RAM/DSP 占用及工具手册中的宏模块放置和拥塞参数。

原因：布局密度、硬核资源放置与连接走向都影响布线收敛；LUT 总量未超限不代表布局可布通。PG2L100H 不支持多线程布线选项，不能用该选项解决耗时。

怎么办：保留原轮日志及映射输入哈希，在新目录做有依据的物理实现参数实验。PDS 手册建议资源占用超过70%时布局扩散系数在0～4内选择；`early_block_placement Global` 按距离优先放置宏块，拥塞图需显式开启。调整这些选项不能代替最终多角时序验收；未完成布线不得生成或下载候选位流。

同一010放置下，pin代价600候选在后期反而增加未布线连接；恢复默认300的011候选完成布线并通过最终STA。因此不能假定提高拥塞惩罚必然更快。复用已验证放置时应保存放置ADF哈希，继续在新目录实施。PDS此路径的成功文字是 `has been routed successfully`，普通全流程是 `has been placed and routed successfully`；应精确区分这两种正常路径，并同时要求最终STA与routed ADF，不能因匹配文字不同而跳过门禁。

## JTAG 报下载成功，随后四路输出都不动

现象：下载日志曾有 `program: 1`、DONE=1，但现场所有按键和舵机都不响应；手动关上的盖子不能证明 FPGA 已输出关闭脉冲。

查什么：读取**当前** `cfg_read_device_property -mode 3`，检查 DONE、gouten、glogen、grsn、gwen；需要时将 `cfg_verify` 回读比较与状态读数分开记录。不能把旧下载日志当作当前配置仍有效的证据。

原因：SRAM 配置可能已不在运行状态，接口仍可扫描到器件 ID。本次实际观察到状态00180c80（DONE/输出/时钟均未使能），与目标位流回读不一致；配置失效由什么触发尚未复现，不能直接归因于方向掩码、接线或终止下载进程。

怎么办：重新下载已通过最终 STA 的同一 SHA 位流，立即和5秒后读取状态，正常 `cfg_disconnect` 后再退出客户端；未配置、延时失效或断开失败不得报告下载验收通过。仿真、配置激活和实物动作分别记录。本次重新下载后状态连续为081ffca0，用户随后确认四路按键均能开盖、停5秒并自动关盖；不得据此声称已经完成掉电冷启动测试。SRAM掉电会丢失，未经用户明确要求不改烧Flash。

## 舵机上电开盖、答题时关盖，或渐变关闭前启动下一轮

现象：部分桶开关相反；或移植渐变后，界面/语音在舵机还没关好时进入下一轮；连续快速答题偶尔卡在等待动作。

查什么：检查**实际构建顶层**传入的方向掩码、四路物理顺序，逐路测关闭/打开脉宽；检查 open_state 是否覆盖开、停、关全过程，及闭合后 100 ms 重装期间单周期触发是否丢失。

原因：500/1500 us 的名义舵机角度不能证明机构盖子方向；端点脉宽交换与电平反相不同，旧 STM32 颜色方向表也可能与当前机械安装不一致。历史快照和活动构建入口可能传不同掩码。将 STM32 持续指令改成 FPGA 单周期请求时，直接丢弃重装期间请求会使答题状态机等不到动作反馈。

怎么办：以用户逐路实测开关状态校准输出，不能仅凭变量名/PWM 标称角度声称实物关闭。当前用户确认四路 500 us 均为开、1500 us 均为关，故两处活动顶层均使用 1111；不再套用旧 STM32 的 1011 重排表。保持高有效 20 ms PWM，仅交换端点，切勿反相整个电平。脉宽只在帧边界改变；到达打开端点后再计保持时间，完成关闭后再报告空闲。忙时请求不排队，关闭后重装期间的新请求需锁存；测试覆盖四路真实校准后的启动脉宽和完整开关过程，仿真通过仍需实物复验。

## Tcl 内已 cd 到 ROM 目录，综合仍提示找不到镜像

现象：PDS Tcl 打印的工作目录正确，但子进程报 `Cannot open specified data file`；工程文件和 compile/synthesize 产物却落在启动 pds_shell 时的目录。

查什么：核对 **pds_shell 进程启动目录**、生成的项目路径，以及所有 `$readmemh/$readmemb` 的实际加载记录。`C: Verilog-3001` 也必须判为构建失败。

原因：PDS 已在 Tcl 执行前确定项目目录，后续 Tcl `cd` 不保证修改综合子进程的工作目录；仅在 Tcl 内切目录不能确保程序和语音 ROM 加载。

怎么办：在启动 pds_shell **之前**将宿主进程切到含 firmware_lane0..7.bin 的 `yolo/sources`（或保持相同相对布局的冻结副本），再传入脚本绝对路径。缺镜像的整轮作废，用新目录重跑；不能用这轮面积或位流作为有效整机证据。

PDS还有一轮项目预解析：以 `source 另一个入口.tcl` 包装完整流程时，它可能在实际项目打开前先报目录错误或 `Unsupported file format when synplify is not specified`，随后又执行真实流程。不要屏蔽这些错误交付。构建器应把入口正文展开到单一Tcl（显式设置包根目录），使预解析可见 `compile -system_verilog`，同时在Tcl解释器及宿主进程均设置sources工作目录；真实阶段继续要求所有镜像加载与最终时序通过。

## PDS 区域约束文件已加载，但布局没有执行区域命令

现象：`add_constraint` 成功，映射日志却有 `Pcf file ... has been covered`；
PNR 日志中没有 `def_region` / `def_inst_region` 执行记录。

查什么：比较准备时物理约束哈希与映射后的 PCF 内容，检查 PNR 是否实际执行命令。

原因：`dev_map` 会向已注册的 PCF 导出物理引脚约束，覆盖先前写入的区域命令。

怎么办：保留独立的区域输入，在 `dev_map` 后追加到活动 PCF，再启动 PNR。
门禁同时检查只读输入哈希、活动 PCF 内容和每条命令执行成功；加载文件不算约束生效。

映射还会展开层级：报告路径含 CPU 前缀，不代表前缀本身仍是可约束实例。
`def_inst_region` 不匹配通配符，也不递归约束已消失的层级。应从同次映射 DB
导出实际叶单元名后逐个绑定。PDS 即使报 `PhysicalConstraintEditor-0023` 仍可能
打印该命令 `successfully`，因此必须同时拒绝 `E:` 错误行。

## PDS 显示约束通过，但有时钟域根本没有分析

现象：最终摘要可能显示已约束路径通过，compile/STA 日志却有
`Clock pin ... has no clock`、`Clock source ... need a clock constraint`，
或 `Nothing implicitly matched` / clock group 被忽略。

查什么：最终报告 Clock Summary 以及快慢角 Setup/Hold 的实际端点；
比对 RTL 中所有分频寄存器用作时钟的逻辑。不能仅看最后一行成功摘要。

原因：PLL 自动推导不一定覆盖普通寄存器产生的分频时钟；约束使用信号名时，
该名字也未必是工具中的时钟名。例如摄像头 SCCB 的 `clock_20k` 是 /2500 寄存器分频。

怎么办：根据 RTL 的真实分频比添加 generated clock，并确认目标实际匹配；
同一 PLL 的输出要保留正确相位/占空比。发布检查必须要求关键时钟有非零约束端点。
完整重新实现后用最终多角报告验收，中间 `after_hold_fix` 快照不作最终依据。

PDS 2022.2-SP6.1 还会拒绝周期 ≥100000 ns 的时钟。若真实慢速分频超过该范围，
可用更短的整数分频作保守分析模型，并明确区分物理分频和分析分频；必须确认
没有依赖不同慢钟精确相位的数据路径，不能把分析分频改小后声称 RTL 时钟也改变了。

## Windows 原生 GCC 退出却没有错误输出

现象：Python 能启动 `gcc.exe`，编译返回非零但 stdout/stderr 均为空；
或加入 PATH 后链接器称找不到实际存在的 CRT/库文件。

查什么：子进程退出码、GCC bin 目录是否在子进程 PATH；安装路径是否包含中文。

原因：编译器子程序缺少 DLL 搜索目录时可能无法输出诊断；部分 MinGW 工具在中文
安装路径下会出现路径编码不一致，导致链接器无法定位自己的 CRT/库。

怎么办：只给编译子进程的 PATH 前置显式编译器 bin 目录，始终保存日志和退出码；
路径编码问题改用已经安装在纯英文路径下的编译器。不要把编译失败当成用例跳过。

若日志明确是 `Cannot create temporary file ... Permission denied`，还要检查默认
TMP/TEMP是否被解析到不可写的用户短路径。为该构建创建独立的可写temp子目录，
仅在编译/size/objcopy子进程环境中设置TMP和TEMP，不改用户全局环境。构建失败后
先修复并在新目录编译成功，再运行依赖新ROM的源码一致性检查。

## 重建训练集时把已经审查排除的歧义标注又带回

现象：新准备器通过了train/val分组与SHA隔离检查，却重新纳入旧审查已排除的冲突类别或歧义图片。

查什么：比较新train的来源路径/像素SHA/实物组与最新审阅后manifest的白名单、既有排除review；隔离门禁只证明不串split，并不证明标签已清理。

原因：从最早原始manifest重建，遗漏后续人工清洗决策；换了JPEG编码或文件名后，只比较准备图字节SHA也可能漏过同一来源。

怎么办：继承最新审阅后train白名单，并按原始来源/实物组核对永久排除记录，准备时立即拒绝重新引入。发现已训练后保留该轮身份和失败说明，不原地换数据继续训练，不交付该轮模型；修正准备器后用新目录构建，val/test保持原边界。
