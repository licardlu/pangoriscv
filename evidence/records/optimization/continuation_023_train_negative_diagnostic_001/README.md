# 空手训练拟合诊断与下一轮依据

本诊断没有训练、改标注、改阈值或操作板卡。它只打开既定stage4训练集的无垃圾标注照片，检查保留权重与已拒绝的保守续训权重。它不衡量泛化，不是Q15或真实摄像头成绩。

## 本轮实际结果

数据为287张唯一train图片：新增空手46、Hagrid147、个人空手94。按图片SHA去重，忽略441条重复采样；不把另37张确有背景电池的个人图当负样本。每张图片及标签均核对manifest SHA，未打开val/test文件。固定320输入、单标签解码、置信度0.25、NMS IoU0.45、最多32框，再经当前实际C主体选择器。

| 权重 | 检测出垃圾的训练图片 | 最终误选的训练图片 | 检测到手的训练图片 |
| --- | ---: | ---: | ---: |
| 保留stage4 | 8/287 | 6/287 | 287/287 |
| 已拒绝的保守续训 | 7/287 | 5/287 | 287/287 |

两者有5张相同误选；保守续训只少了1张低分衣物边缘。stage4误选6张的联系表已逐格复看：C0332与N0189是手指局部误作有害垃圾，其余4张Hagrid是衣物/人物边缘。训练图本身也出现残余误检，不能仅解释为没见过场景；同时，这6张不足以证明整体训练欠拟合。train与既有val的来源比例不同，不能直接用6/287对比8/136估算泛化差距。

`train_negative_fit_001`因上游默认用户配置目录不可写而未推理；`002`发现新增图manifest不含宽高，校验中止。修复为本轮独立配置目录，宽高字段存在时核对、否则使用解码实测尺寸。只有`003/result.json`完成，两次失败不计通过；未改上游模型源码。

## 对后续训练的约束

1. 不用6→5的训练拟合差异替换模型。统一校准的完整开发val仍支持stage4，保守续训有物品正确数更低；仍保留原checkpoint和160图校准。
2. 后续实验应针对“手指局部/衣物边缘被当垃圾”的具体错误，而不是把所有手框内候选直接删除；真实手持电池也位于手框内。距离门控也无法排除近处的手。
3. 若制作局部困难负样本，只能从train原图派生，继承原split/拍摄组，逐张确认裁剪内无真垃圾；手的可见部分与无手背景分别标注。必须保留真实电池/玻璃正样本，不能靠空标签覆盖真物，也不能把val错误照片移到train。
4. 首先审查现有训练损失和手/物anchor分配，确认新增约束真正执行、没有惩罚真实手持物；有可检验的假设才启动一轮受控训练。保持校准、解码和开发val身份固定，失败模型不进入候选。
5. 下一轮仍需独立现场空手/空背景、多姿态电池与玻璃照片验证。现有照片中同场景重复较多，重复采样不等于场景多样性。
