## 1. D6：单发射到底是谁造成的（`--tag d6why`）

先量后改。加了一组只读探针（`tb/integration/tb_coremark_uart.sv` 的 D6 块），
全部 `if(rst_n && !sw_done)` 门控到计分窗口。

```
WIN_ACCEPT pair=2399560 single=494108 refused_pair=779461
           [lduse=163143 mduse=186372 memmem=256088 alone=22740 l1bad=151118] mispred=88088
WIN_NOPAIR off=43602/27257/24917/31197/48178/15866/109655/193436
           byp=228697 queued=265411 cnt<=1=494108 cnt>1=0
WIN_MEMMEM ll=197924 ls=40624 sl=19020 ss=7608
WIN_L1BAD  mul=115086 div=0 jalr=35946 csr=6 ctl_msa=0 ill=0 misc=244
WIN_NOISSUE mem=1720 div=11 trap=0 redir=0 hold=0 other=142478
```

四条结论，每条都直接决定"做不做"：

1. **`cnt<=1=494,108 / cnt>1=0`** —— 没有一个单发射来自"队列里只有一条"以外的情形，
   也就是说**加深度、加预取都没用**。队列不是不够深，是供给速率就那么多
   （每拍最多一次握手，平均 1.87 条/握手）。
2. **`off[6]+off[7] = 303,091（61%）`** —— 单发射集中在行尾两格。
   `hit_pair=(word_off!=7)` 在 offset 7 一律拒绝成对（跨 32 B 行）。
   `off[6]=109,655` 是 lane0 是被预测跳转的分支，第二格根本不可能是 pc+4。
   两者都是**结构性的 1 拍**，只有"跨行成对"能救，而跨行成对要给 I$ 加第二个
   读端口（库是 LUTRAM，等于把 2 KB 阵列再复制一份，约 +1,800 LUTRAM），
   **破面积门禁，不做**。
3. **`WIN_MEMMEM ll=197,924（77%）`** —— 访存拒收的大头是两条 load 抢一个读口。
   要修就得给 lane1 一条"在 M1 发"的延后通路，而这条通路需要
   (a) 一个能被冻结的 M1/M2/WB 级联（现在只有 `hold_m1`，语义是"插气泡"不是"冻结"），
   (b) 第三条寄存器堆写口（延后完成的 load 要在 WB 之后写回）。
   见 §3，判决是**不做**。
4. **`WIN_L1BAD mul=115,086`** —— 车道 1 是乘法就必然拒收。这条**能做且便宜**，
   见 §2。

## 2. R9a：车道 1 自己的乘法器（`01ba45e`）

老代码里 `lane1_ok` 排掉了 `dec_mul_h`，注释理由是
"乘法的四级 DSP 级联（9.0 ns）串进 lane1 的加法器，最差路径 26.6 ns"。
**路径那半句是对的，治法那半句是错的**：拒收配对并不能把级联从 lane1 的操作数
组合锥里删掉——综合读不到 `pair_ok`。于是路径还在，拍子白花。

两条级联各自喂自己那一路的 EX/M1 寄存器，天然并联：

```verilog
    wire lane1_mul_ok = dec_mul_h;                 // div 仍然拒收：迭代式，第二个单元 = 第二个状态机
    wire lane1_ok = lane1_alu || lane1_ctrl || lane1_mem || lane1_mul_ok;
    ...
    wire [31:0] mul_y_h;
    rv32_mul u_mul_h(.op(rr_md_op_h), .a(fwd1_h), .b(fwd2_h), .y(mul_y_h));
    wire [31:0] ex_value_h_w = rr_mul_h ? mul_y_h : alu_y_h;
```

新增 4 个流水字节（`id_mul_h/id_md_op_h/rr_mul_h/rr_md_op_h`）+ 4 个 APM（6 → 10）。

读数是**两处**收益，不是一处：

| 项 | 前 | 后 |
|---|---:|---:|
| `l1bad mul` | 115,086 | **0** |
| `mduse` | 186,372 | **72,211** |
| `refused_pair` | 779,461 | 550,214 |
| `pair` | 2,399,560 | 2,514,647 |

`mduse` 掉了 11.4 万是**流的重排**：lane1 乘法不再拒收之后，整条指令流的对齐变了，
"lane0 乘、lane1 读它"那种包跟着少了一大半。这解释了为什么
"消掉 22.9 万次拒收"只换来 10.9 万拍：**每次拒收的净代价约 0.48 拍**，
不是 1 拍——被拆开的那条会在下一拍重新和它的后一条凑对。

**这个 0.48 是后面所有估算的分母**，以前按 1:1 估会系统性高估一倍。

## 3. 判决：`memmem` 不做（附理由，避免下一个人重走）

能做的最小版本是"lane1 的访存挪到 M1 发"：
lane0 命中时 D$ 当拍给数据（P10），lane1 在 M1 发、当拍拿数据、写 `m_value_h`，
包不用停。听着很美，但有三道坎：

1. **需要真正的冻结级联**。现在 `hold_m1 = trap_wait`，M2 的写法是
   `m_valid <= hold_m1 ? 0 : ...`，即"插气泡"。l1 的访存 miss 时要冻住 M1+M2+WB
   三级、同时不许 EX 前进——这是新机制，而 `hold_ex` 那条链已经因为
   "`mem_wait` 依赖 `mem_accept` 依赖 `hold`"死锁过一次（教训 40 那一类）。
2. **需要第三条写口**。延后完成的 load 在包已经过了 WB 之后才回来，写回要落在
   寄存器堆的第三个写口上，或者把包吊在 M2（那就没有收益了）。
3. **`ll` 占了 77%，而它非要第二个读口**。就算 1、2 都解决，
   `(load,store)` 那 40,624 条能省的是 0.48×4 万 ≈ 2 万拍。

**判据（写在这里，下次别再算一遍）**：
一条"延后一级执行"的改动，只要它需要**冻结一个当前只会插气泡的级**，或者需要
**新增一个写端口**，它就不属于"一个模块一次提交"的范围，收益上限还得打 0.48 折。

## 4. 频率侧（另见 `evidence/records/timing/`）

`0842e48` 把 `perf_regs` 的 8 个 64 b 计数器、11 个 32 b 计数器和 `csr_native`
的 `mcycle/minstret` 从"一个 64 深进位链"改成"四个 16 b 加法器 + 寄存器进位"。

`report_timing` 26.65 ns）里，三条最差路径有两条终结在
`soc/perf_inst/cnt[2][56]`（30.20 ns）——一个没人读的计数器。
