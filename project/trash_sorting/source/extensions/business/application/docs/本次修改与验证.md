# 本次修改与验证

> 本文记录上一轮修改。当前白色分屏、三句新提示音和最新集成边界以《白色分屏与提示语音.md》为准；上一轮源文件大小、哈希和截图路径仅作历史记录。

## 最新约定

- 无目标时固定显示引导框；有目标时显示 YOLO 框。新预 PnR 基线的引导框位于 1280×720 画面中央，边界为 x=480..799、y=200..519。
- 正确答案 +100；同一轮重复作答不重复加分；错误和超时不加分。积分保存在本次运行的内存中，复位归零，没有重新引入二维码、账户或持久化账本。
- 正确答案直接请求播放资产 ID 5，即 `MUSIC0.WAV`；无需扣分。音乐来自项目合成脚本的原创短旋律，名称为《晨光小径》（MORNING PATH），5.76 秒，48 kHz、16 位 PCM、单声道。
- I²S 发送器输出 `audio_bclk`、`audio_lrclk`、`audio_data`，需要外接 I²S 功放后驱动扬声器。普通模拟有源音箱还需要 DAC。音频时钟要求 12.288 MHz。未改引脚约束、未执行布局布线、未烧录。

## 源码集成边界

`yolo/` 沿用用户新给的 YOLO 工程；其 `sources/049_video_ai_frontend.v` 已修改识别框逻辑，`tb/tb_bbox_osd.v` 验证固定引导框、有效目标框和空结果恢复。

原始 ZIP 中的 `sources/049_video_ai_frontend.v` 为 10072 字节，SHA-256 `eaeff61a63a41bb50ea551be84ce588b3ad2e580ca7932ec8f956a15e6c1a69d`；本次修改后为 11207 字节，SHA-256 `e14923fde244be7b4d1256ef483c38c28254bce7fe0bc55de33cdd9067c47edb`。交付的 checksums.json 和 source_manifest.json 已更新为修改后文件的哈希，不能用它们证明和原始 ZIP 完全相同。

`extensions/business/application/` 是应用扩展源码。`app.c` 处理答题、会话积分和音乐请求，`platform.c` 包含 SD 音频预载、I²S MMIO 播放和界面状态提交，`ui_rgb.sv` 绘制积分和音频面板。驱动实际启动后才置播放标志；就绪状态取决于音频资产加载结果。

**应用扩展还没有接入新版 YOLO 的板级顶层。** 新 YOLO 顶层目前没有这些按键、应用 MMIO、音频时钟与音频输出接口，现有的通用 application_soc 属于另一套 CPU/总线接法。本包不应当被视为可直接编译烧录的完整板级集成工程。`platform.c` 是待接入的参考驱动，依赖原应用平台定义；不能单独放入新版 YOLO 软件目录编译。

包内源快照原有的 `program.hex` 和 `firmware_lane*.bin` 没有由本次 C 修改重建；本次也没有新增可烧录位流。为了遵守“先不要布线”的要求，没有进行 PnR 或更改 FDC。
