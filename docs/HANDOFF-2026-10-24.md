## 2. 本轮做成的两件事

### 2.1 切② CSR 读口解耦（第三次做法，零 CPI）

三处改动缺一不可：
1. `csr_native` 拆 `addr`（提交写）/ `raddr`（取值，接 **M2**）/ `iaddr`（合法性，接 ID）；
2. `wb_value = w_csr ? w_csr_old : w_value`，且 `w_csr_old <= csr_rdata`；
3. **`serial_q` 改成 `id_accept && (dec_serial || id_serial)`** —— 原来用"已经在 ID 那条"
   （`id_serial`），紧跟串行指令的那条会在屏障升起前漏进 ID 一拍，于是它正好在前一条
   提交的同一拍读 M2。而 `csr_new`（RMW 基值）与 `rd` 必须是同一个采样。**这是前两次
   （plan v19 §12）失败的真因。**

### 2.2 P57 lane-1 乘法器去链

55 MHz 实跑暴露：切② 之后最差路径变成
`rr_inst → alu_b → ALU(4级) → fwd1_h → u_mul_h 4×APM → prod → ex_value_h`（21.852 ns，DSP 8.8 ns）。
`packet_md_use` 只禁了反方向。**只加配对禁止无效**（综合读不到 `pair_ok`），必须给 lane-1
乘法器一套不含 `lane0_raw` 的操作数（`fwd1_hn`/`fwd2_hn`）。
代价：**ticks −160、LUT +184**。

## 3. 频率：为什么停在 50 MHz（三次满流程的实测对照）

| 网表 | 约束 | 摆放 | 布线后 | WNS |
|---|---|---|---|---|
| `p48r50e` 交付（无 ②/无 P57）| 50 MHz | +1.683 | **19.355** | **+0.645** ✓ |
| `p50r55` ② | 55 MHz | +1.256 | 19.776 | −1.595 ✗ |
| `p50r52` ②+P57 | 52 MHz | **+1.903** | 20.222 | −0.991 ✗ |

**关键事实**：更小、更快的同族网表在 52/55 MHz 上布出来的绝对值（19.8~20.2 ns）
**不如**交付版在 50 MHz 的 19.355 ns。这就是 lesson 9/85 的"布线抽签"：
27% 利用率下 ±1 ns 由摆放抽签决定，**网表更优不保证布线更优**（网表一扰动摆放就整锅换）。
摆放 → 布线还要再吃 **1.0~2.9 ns**，而且这个差额本身也在抽签。

证据目录：`evidence/records/optimization/p50r55-cut2-fail/`、
`p50r52-cut2-p57-fail/`（都含 `report_timing.rtr` 与 `multiseed_summary.csv`）。

## 4. 120 MHz 的判定（三条独立证据，别再重新论证）

1. **CPI 预算**：切一级流水 ⇒ 分支晚一级解决 ⇒ **每迭代 +4,945 拍**（重定向次数），
   5.2 分只剩 **1,772 拍**。加宽到 3 发射才买得起，而 3 发射的 +面积把 LUT 顶到 20k+，
   越过 18k 的布线门槛（lesson 9）。
2. **访存不可分**：探针实测 `load_use_1` = **695,148 / 20 迭代 ≈ 34,800 拍/迭代**
   （见 lesson 93）。任何"给访存加一级/复制读口"的方案都要付 18% 拍数（5.25 → 4.44）。
   **这个核的性能正是建立在"访存单拍 + 同拍旁路零 load-use 停顿"上的。**
3. **实测地板**：120 MHz 约束下摆放后仍差 **5.77 ns**（路径 14.07 ns）；
   55 MHz 网表 TNS −537.963 / 2,222 个失败端点、**平均只差 0.24 ns**
   ⇒ fmax 由一整片近临界路径决定，砍掉一条最差路径抬不动它。

⇒ **"5.2 分 + 120 MHz"在本微架构 + PG2L100H 上不可同时成立。** 这是测量结论，不是估算。

## 6. 下一轮该做什么（按性价比，都已排除过其他选项）

1. **切⑥ 的"可综合写法"**（最高优先）：52 MHz 网表的最差路径尾巴正是它要切的那一段
   （store 命中在 accept 拍写阵列，写使能由 `mem_from_h → LSU → w_strb` 组合决定）。
   功能实现已验证（ticks/CRC/ISA 全对），卡在 PDS `tech-mapping phase 2` 40+ min 不结束。
   可试的方向：把延迟写**并入现有 FSM 的 `case` 结构**（而不是写在 `case` 之前），
   或把 store→load 转发比较移到 way 选择之前。判据：`Synthesize Process Cpu Time` 不超过
   基线 3 倍（lesson 90）。
2. **寄存器堆组合读预采样**（唯一对"一整片路径"同时生效的零拍改动，值 1.5~2 ns）：
   `rr_d0/rr_d1/rr_d0_h/rr_d1_h` 在 RR/EX 沿采样，EX 内加 `w_value` 作为第三级旁路。
   风险：`lane0_raw` 的同包语义必须保住（ISA 17/18 是判据，历史上有一次尝试因此失败）。
3. **不要再做的**：换 seed（静默 no-op）、floorplan/区域约束（三形状全负）、
   给访存加级、加宽到 3/4 发射（面积顶穿 18k）、`ll`、`ls/sl/ss` store buffer。

每次满流程约 **6~9 小时**（合成 3 min + 摆放 ~10 min + 布线 5~9 h），
所以一档只跑一次、档位按 `place_only` 的 slack ≥ +2.5 ns 挑。
