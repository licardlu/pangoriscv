# 冲刺目标：5.2 CoreMark/MHz，120 MHz

状态：激进实验路线；当前只做架构规划，不以反复跑基线代替设计工作。

## 目标与已知差距

当前可靠交付是 E2：PG2L100H 上 27 MHz，1152 次迭代、298,780,717 ticks、11.066 s、五项 CRC 全对，板测 3.8557 CoreMark/MHz。目标 5.2 要把每次迭代从约 259,358 cycles 降至不超过约 192,308 cycles，即约 25.9% 的周期下降。120 MHz 只提高绝对吞吐，不会改变归一化的 CoreMark/MHz；两项必须分别实现和举证。

当前 20 次迭代分析窗口是 5,212,477 cycles。主要配对阻塞分类为 RAW 720,997、lane1 memory 664,135、lane0 branch 444,391、WAW 190,096、非相邻 140,300；重定向平均恢复约 3.5 拍。posted-store 队列满造成的拒绝只有 12,310 次。结论：不要先继续加深 store FIFO；主攻双发射空槽与分支恢复。20 次运行只作内部诊断，不作竞赛成绩。

## 主线 A：直接提高每周期退休数

当前瓶颈不是取指 miss，也不是 store 缓冲深度，而是双发射的组合配对规则。目标平均退休率至少约 1.5 条/周期，同时保持严格程序序退休。

1. **lane0 ALU + lane1 load/store 配对**：lane1 memory 是最大的单项配对阻塞。扩展第二执行槽的数据操作路径，让一个独立整数操作与一个访存操作同拍发射；每组最多一个访存，沿用现有单 LSU/数据 Cache，先不引入第二个 AXI master。保持 load/store 对应的异常 PC、地址、写掩码及顺序语义。待 LSU 等待时用有效位冻结或缓冲两槽结果，避免重复发请求。
2. **lane0 branch + lane1 整数操作配对**：lane1 只做无外部副作用的整数运算，分支解析前暂存结果；预测正确才按序提交，预测错误则丢弃 lane1 结果并冲刷。禁止分支未决时让年轻 store、MMIO 或 CSR 产生可见副作用。
3. **收紧 RAW/WAW 限制**：复用已有 EX-EX 前递；允许能由旁路正确满足的相邻依赖。lane0 load 结果未返回、异常、CSR 写冲突等情况继续保守停顿。WAW 仅在能保证 lane1 的较新结果最终写入、并且两条退休记录正确时放行。
4. **减少分支恢复拍数**：把分支比较与目标计算前移到独立级，预测失败时只冲刷最年轻的有效槽；保留 BTB 训练与退休一致性。以 3.5 拍为基准，把实测平均恢复降到 1–2 拍。

先修改配对/退休相关 RTL，不先做 AXI 多 outstanding 重构：现有 profiling 表明 store-queue 满冲突远小于配对阻塞。按单模块提交，更新对应模块合同和面积账本。先争取约 4.5，再用剩余的配对空洞与分支惩罚冲到 5.2；任何阶段都不靠改 CoreMark 工作负载或错误的计分口径。

## 主线 B：让关键路径缩短到 8.33 ns

120 MHz 的周期是 8.333 ns。E2 在 27 MHz 收敛的 setup slack 为 +7.816 ns；现有三级顺序核不能靠换 seed 或提高约束直接跨到 120 MHz。需要实际流水化，而非单纯增加时钟约束。

1. 把当前长组合路径拆成约 5–6 级：取指请求/返回、译码与寄存器读、执行/分支比较、访存地址与请求、Cache/总线返回、按序写回。以寄存器/Cache RAM 输出和 EX-EX 前递/ALU 路径作为首要切分点。
2. 为新流水级补齐 valid/kill/hold 语义。每条指令带 PC、序号、异常信息和目的寄存器；分支冲刷只杀年轻指令；访存请求只能握手一次；写回与退休按程序序进行。对长延迟 load 和除法用 scoreboard 阻止错误消费者，而不是把整条前端无条件停死。
3. 在当前 PG2L100H 板上以 27 MHz 晶振输入产生 120 MHz 核心时钟，增加 PLL 锁定后的复位释放，并把 UART 分频改为实际核心时钟。FDC 使用 PLL 输出的 generated clock，完整约束输入/输出与跨时钟路径；不使用 false path 或虚报板载频率。
4. 频率交付门槛是 120 MHz PLL 输出下 setup/hold 均无失败端点、布线收敛可复现。频率要由板上 PLL 锁定和 120 MHz CoreMark 实际运行证明；PDS slack 推算值只作为时序证据，不能叫板测最高频率。

## 工作纪律与交付口径

- 实验在 `exp/score-5.2-120mhz` 分支进行；E2 位流与主分支作为回退点。
- 不继续重复跑 20 次诊断基线，不做无假设的 seed 扫描。先完成一段连贯的 RTL 修改；验证安排在明确的实现节点，不用测试循环替代架构推进。
- 一个提交只改一个 RTL 模块；每次同步 `module-area-plan.md` 与 `area-budget.csv`。新增模块先补齐 11 字段合同。若设计需要突破当前资源预算，先更新预算和记录理由。
- 最终 120 MHz 镜像建议至少 7,000 次迭代，给运行时间留余量；按 `iterations / total_ticks × 1e6` 算 CoreMark/MHz，且实际时间至少 10 s、五项 CRC 全对。
- 同一实现目录保存 program/data 镜像哈希、PDS 日志、`multiseed_summary.csv`、`report_timing.rtr`、资源、位流 SHA256 和板载串口原文；性能计数/I​​LA 使用分析构建，交付构建默认关闭 `PERF_ENABLE`。

## 主要风险

最大的正确性风险是分支年轻指令与访存/异常的精确提交；最大的时序风险是双发射旁路路径重新变成长路径；最大的物理风险是 RAM 推断和 hold 余量。若配对扩展令时序变差，先保留吞吐改进，再通过流水切分解决频率，不回退到只调约束。若某模块实现不可控，单独回退该提交，保留已验证的 E2 交付。
