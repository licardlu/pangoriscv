# p66r52ret —— 综合 retiming 在 52 MHz：综合更好、布线最差

**日期**：2026-10-24 16:00–16:40
**树**：cut-2（`docs/patches/cut2-csr-read-split.patch`）
**约束**：52 MHz（19.230769 ns）　**镜像**：`hw_i2900_52b`
**综合**：`synthesize -ads -selected_syn_tool_opt 2 -retiming`
**pnr**：`-dc_duplication TRUE -slack_prior_in_global_router TRUE -refineplacement_cluster TRUE`

## 结果

| 阶段 | 值 | 对比（`p58r52`，同树同约束、无 retiming） |
|---|---|---|
| 综合 WNS | **+1.577 ns** | +0.092 ns（**好 1.485 ns**） |
| LUT / FF | 17,084 / **8,779** | 17,027 / 8,597（+57 LUT / **+182 FF**） |
| 摆放 slack | +1,294 ps | +1,894 ps |
| 布线收敛 | 364 轮 | 186 轮 |
| **布线后 WNS** | **−4.519 ns（到位 23.750 ns）** | **−0.195 ns（19.426）** |

## 结论

`-retiming` 把 182 个寄存器搬来搬去之后，综合器对路径的估计好了 1.485 ns，
**布线后却差了 4.32 ns** —— 本族里最差的一次。

这是 lesson 97 的极端版：**综合 WNS 与布线后结果之间没有可用相关性**，
而且**越是"聪明的"综合变换，越容易把网表捏成布线器讨厌的形状**。

⇒ 综合侧不要动（保持 `-selected_syn_tool_opt 2`，不加 retiming / pipelining）。
`-fanout_guide` 未单独验证（时间不够），但它与 retiming 属同一类"改网表形状"的旋钮，
按本条的证据，预期同样是抽签而非改善。
