## 0. 三条必须先纠正的事实

### 0.1 45 MHz 从来没有"时序通过"过——那是**摆放**值

`p17` 报告写"45 MHz 的摆放也干净通过（WNS +1.462 ns、TNS = 0）"，交接文档据此
得出"布线不收敛是本轮唯一障碍"。**布线后实测（`build/p15nx45/report_timing/pangoriscv_top.rtr`，
45 MHz 约束，S1 已回退，是唯一一次详细布线收敛的样本）：**

```
Requested 45.0005 MHz   Estimated 40.6537 MHz
Setup(Slow) WNS -2.376 ns   TNS -2538.854 ns   Failing endpoints 4077 / 66481
Hold(Slow)  WHS -0.064 ns   Failing endpoints 5
Data arrival 26.668 ns   Logic 4.233 ns (17.6%)   Route 19.787 ns (82.4%)   30 逻辑级
```

⇒ **当前 RTL 的真实上限是 40.65 MHz（24.6 ns），不是 45。** 36 MHz 位流有效是因为
27.78 ns > 24.6 ns。`plan v12` 的"45 MHz 台阶"从未达成，v12 的 A 段判据是拿摆放值判的。

**这条纠正的意义**：把"布线能不能收敛"当成主障碍，会去做 seed 抽签；真正的障碍是
**组合路径长度**。抽签抽一百次也变不出 8.333 ns。

### 0.2 关键路径里 53% 的延迟集中在 7 根网上

`p15nx45.rtr` 逐跳拆开（Route 19.787 ns / 30 级）：

| # | 网名 | 扇出 | 延迟 |
|---|---|---|---|
| 1 | `redirect_pc[27]` | **5** | **2.338 ns** |
| 2 | `ifu/q_pc[4][31:0]_and`（队列写使能） | **64** | **1.833 ns** |
| 3 | `rr_inst[21]` | **136** | **1.626 ns** |
| 4 | `_N96270` | **1** | **1.319 ns** |
| 5 | `_N4525`（ALU 内部） | 4 | 1.258 ns |
| 6 | `ifu/N1266`（`local_push` 上游） | **99** | **1.111 ns** |
| 7 | `alu_b[1]` | **79** | **1.063 ns** |
| — | 其余 23 根合计 | — | 9.24 ns |

**7 根网 = 10.55 ns = 布线延迟的 53%。** 其中扇出 1 的网要 1.319 ns（跨 78 列），
扇出 5 的网要 2.338 ns —— 这不是"逻辑深"，是**摆放把相关逻辑摊开了**。
一根扇出 1 的线能要 1.3 ns，说明单元之间的距离占了延迟的绝对多数。

⇒ 把扇出压下来、把相关逻辑聚在一起，**这条路径能省掉 8~10 ns，而且一分 CPI 都不用付**。

### 0.3 120 MHz 的 PLL 是**可达**的，文件里"不可达"的结论错了

`pangoriscv_top.v` 与 `pango_native_120mhz.fdc` 都写着"120 需要 F/M = 40/9，
VCO 1080 或 2160，均非法"。**这个推导漏掉了输出分频器 O 是自由的，且支持 0.125 粒度**
（`ipm2l_pll/ui.tcl`：`STATIC_RATIO0` 可取小数，VCO 1330~2133）：

```
27 × 58 / 13 = 120.4615 MHz      VCO = 1566 MHz（合法）  PFD = 27 MHz（合法）
```

⇒ 120 MHz 档位用 **F=58 / O=13 = 120.46 MHz**，约束按 8.3014 ns 写。
（另：F=60/O=13.5 正好 120.000，但 `STATIC_RATIO0` 是整数参数，需走小数寄存器，
先用 58/13 这条整数路径。）

## 1. 三个杠杆的定量账

| 杠杆 | 现状 | 潜力 | CPI 代价 | 面积代价 |
|---|---|---|---|---|
| **L1 物理**（扇出 + 聚类） | Route 19.79 ns，0.66 ns/跳 | 7 根病态网 → 0.3 ns/根，省 ~8 ns ⇒ **64 MHz** | **0** | 0（复制反而省布线） |
| **L2 流水**（切段） | 24.6 ns | 每切一刀 ≈ ÷2（局部化后） | −5,000 拍/刀 | +200~400 LUT/刀 |
| **L3 CPI 储备** | 190,129 拍/迭代；5.2 上限 192,307，余量 2,178（1.15%） | 双端口 D$ 回收 12,256 拍 | **+12,256** | +~1,400 站点 |

### 1.1 为什么必须"先 L1 后 L2"

内存账（每迭代拍数，`RV32_PROF` 实测）：

```
当前            190,129   5.2165
先切一刀        +5,000 → 195,129   5.083   ✗ 已经掉出 5.2
先做双端口 D$    −12,256 → 177,873  5.62
再切一刀        +5,000 → 182,818   5.47   @ 约 64→90 MHz
再切一刀        +5,000 → 187,818   5.32   @ 90→120 MHz
```

⇒ **120 MHz 至少要两刀，两刀要 10,000 拍，所以双端口 D$ 是硬门槛。**
而 L1 不花拍子：如果能靠物理优化把 24.6 ns 打到 15 ns，就只要一刀（+5,000），
双端口 D$ 之后余量还有 9,000 —— 这才是 120 MHz 能落地的组合。

### 1.2 L1 具体怎么做（本轮新增的、从未在布线构建里试过的工具选项）

`pnr` 的完整选项表（`puts [help pnr]` 导出）里有 8 个从未用过的物理优化开关。
历史所有构建只用了 `-plc_decongestion` 和 `-share_router_control_signal`。

| 选项 | 作用 | 对 7 根病态网的意义 |
|---|---|---|
| `-dc_duplication TRUE` | Design Cells Duplication | 直接打扇出 136 / 99 / 79 / 64 四根网 |
| `-refineplacement_cluster TRUE` + `-refineplacement_mode/iteration` | 摆放后按连通性聚类 | 打"扇出 5 却要 2.3 ns"的纯距离问题 |
| `-logic_optimize_enable TRUE` | 摆放后逻辑优化 | 顺带重综合宽 mux / 复制驱动 |
| `-slack_prior_in_global_router TRUE` + `-slack_weight` | 全局布线按时序加权 | 关键网优先短路径 |
| `-max_ctrl_chain_length` | CE/RS 串接上限 | 队列写使能那条扇出 64 的 CE |
| `-route_constraint_iterate` + `-route_constraint_slack` | 迭代放宽/收紧布线约束 | 正面解决"布线不收敛" |
| `-pin_cost_increasing_speed` | 引脚代价随速度增加 | 拥塞点让路 |
| `-congest_overlap_limit` | 拥塞模式迭代上限 | 震荡时提前退出 |

**这一批选项是零 CPI、零面积的纯物理杠杆，必须先榨干，再谈改流水线。**

### 1.3 L1 的次级杠杆（如果工具选项不够）

1. **`data_ram` 进 BRAM**（M2 的未完成项）：2,048 LUTRAM（占全设计 54%）→ 0，LUT −约 1,000。
   机理：现被推断成 4 × (4096×8) 的 `GTP_RAM64X1DP`，读是**寄存器读**，本可进 DRM；
   历史三次用 `syn_ramstyle` 无效，改为**直接实例化 `GTP_DRM36K_E1`**（与 `GTP_PPLL` 同样的做法）。
   收益不只是面积：3,790 个 LUTRAM 必须落在 CLM 列里，是 `redirect_pc → tag_q` 这类
   跨列长线的成因之一。
2. **高扇出寄存器在 RTL 层手工复制**（`rr_inst` / `alu_b` / `ifu` 队列写使能按消费方拆份）。
3. **`ifu` 队列写使能改成本地生成**（每项一个浅逻辑，而不是一个扇出 64 的全局 CE）。

## 2. 阶段计划与判据

> 每阶段结束都要过闸；不过就回退，不留半成品。每阶段独立可上板。

### S0 事实校准（已完成）
- 用 `p15nx45.rtr` 把"真实 Fmax = 40.65 MHz"钉进文档（本文件 §0.1）。
- 导出 `pnr` 全选项表（本文件 §1.2）。
- 纠正 PLL 可达性结论（§0.3）。

### S1 物理优化筛选（进行中）
1. `pnr -place_only` @ 45 MHz，4 组并行（基线 / +duplication / +duplication+cluster / 再+logic_optimize）。
2. **闸门**：摆放 WNS 相对基线改善 ≥ 2.0 ns；否则说明工具选项无效，转 §1.3 的 RTL 手段。
3. 最优组合跑**满流程 @ 45 MHz**（不是摆放）。
4. **闸门**：详细布线 Unrouted → 0 **且** 布线后 WNS ≥ 0。这是本项目第一次真正意义上的
   "45 MHz 时序通过"。
5. 出位流 → 上板 → `Total ticks` 与仿真逐位一致（3,833,976 ± 0.1%）、五项 CRC 全对。
   **落点：5.2165 @ 45 MHz（频率 +25%，分数不变）**

### S2 继续压物理（目标 55~65 MHz）
- S1 的物理选项 + `-slack_prior_in_global_router` + `-route_constraint_iterate`。
- 若 LUT 超 18,500 或布线时间恶化，先做 `data_ram → BRAM`（§1.3 第 1 条）。
- **闸门**：布线后 WNS ≥ 0 @ 18.2 ns（55 MHz）→ 出位流上板。

### S3 双端口 D$（CPI 银行）
- 目标：`l1mem` 的 12,256 拍/迭代回收 ≥ 80%。
- 做法：D$ 增加第二个访问口（数据阵列 +1 份副本，tag 按路复制，两个独立 hit 通路），
  两条 lane 各自一个请求口；store 仍走 posted STQ，load 走新口。
- **闸门**：ticks ≤ 3,590,000（≥5.57）、ISA ≥20/21、LUT ≤ 19,500。

### S4 切第一刀（重定向寄存）
- `ifu_axi` 的 `fetch_ptr` 去掉 `redirect_valid ? redirect_pc` 项，重定向下一拍由 `transparent` 发出。
- **闸门**：ticks ≤ 3,750,000（≥5.33）；布线后 WNS ≥ 0 @ 12.5 ns（80 MHz）。

### S5 切第二刀（ALU / AGU 分级）
- ALU 结果打一拍进 EX2；分支比较留 EX1（独立比较器），使这一刀**不加重定向代价**。
- **闸门**：布线后 WNS ≥ 0 @ 8.3014 ns；上板 120.46 MHz。

### S6 定版
- 出位流、`multiseed_summary.csv`、`report_timing.rtr`、位流 SHA 进证据目录；
  上板抓 `Total ticks` + 五项 CRC；ILA 波形；更新 `bitstream/README.md` 与面积账。

## 3. 判据的"红线"（防止自欺）

1. **只认布线后 `.rtr`**。`Worst slack after placement` 一律标注为"摆放值"，不得用于结论。
2. **分数只由 `Total ticks` 反推**（`Iterations×1e6/Total ticks`），不用 `Total time`。
3. **频率必须是同一份位流的**：约束值、`.rtr` 的 WNS≥0、板上 ticks 三者对齐。
4. **位流里必须有程序**：综合日志出现 `Loading memory data from file`，否则不出位流（第一铁律）。
5. 一次构建目录只跑一次实现；证据目录与位流 SHA 一一对应。
6. 每改一处 RTL，先跑 `run_coremark_sim.py`（2.5 min，判 `crcfinal 0x4983`）+ `run_isa_e2e.py`（20/21）。

### 6.1 已交付并上板实测

```

Total ticks 434,442,833 / 2300 iterations / seedcrc 0xe9f5
crclist 0xe714  crcmatrix 0x1fd7  crcstate 0x8e3a  crcfinal 0x988c

```

### 6.2 让布线收敛的唯一有效手段：把 `data_ram` 从分布式 RAM 挪进块 RAM

`data_ram` 原来被拆成 4×(4096×8)、每片 512 个 `GTP_RAM64X1DP`，**2,048 个 LUTRAM
= 全设计的 54%**。同模块的 `program_ram` 却是 `GTP_DRM36K_E1`——两者唯一差别是
`WRITE_ENABLE`：ROM 实例的写路径被综合删掉，映射器就认；数据实例的写留在响应
状态机的 `case` 里、读在另一个 always 块，映射器认不出简单双口结构。

改成"读写在同一个 always 块 + 两个地址都来自寄存器 + 字节使能展开 + 数组加
`syn_ramstyle=block_ram` + `s_rdata` 直接取已寄存的阵列输出"，得到 `GTP_DRM36K_E1`×4。
**`Total ticks` 逐位不变**，LUTRAM −2,048、LUT −2,189。

### 6.3 布线结果对比（同一台机器）

| 构建 | LUT | 约束 | 详细布线 |
|---|---|---|---|
| p18r39 | 18,181 | 39 MHz | 停 3,618@119，斜率归零 |
| P19c | 15,971 | 45 MHz | 340~385 震荡 400 轮，未收敛 |
| **P20b** | **15,992** | **39 MHz** | **0 @ 212 轮，收敛** |

⇒ **面积是可布线性的唯一确定函数**，不是 seed、不是 floorplan。18.2k LUT 时代
的一切"抽签"结论，本质都是"面积在拐点之上"。

### 6.4 切断重定向环路：实测代价 4,798 拍/迭代，**不可交付**

`ifu_axi` 里 `fetch_ptr` 去掉 `redirect_valid?redirect_pc:`，请求改由下一拍的
`transparent` 发出（补丁 `docs/patches/redirect-cut.patch`）。这是唯一能把
25.43 ns 的环路真正打断的改动。

| 配置 | Total ticks (20 it) | 分数 |
|---|---|---|
| BTB64（交付） | 3,776,288 | **5.2963** |
| + 重定向切断 | 3,872,252 | **5.1650** ✗ |

代价 = +4,798 拍/迭代，而误预测只有 2,298/迭代 ⇒ **约 2.09 拍/次**，不是模型估的
1 拍。原因是老旧响应未吞完时 `transparent` 为假，请求要再等一拍。

⇒ **5.2 的预算装不下这一刀**。要切它，必须先有双端口 D$（−12,256 拍）垫底。
**这就是 120 MHz 唯一的前置条件，没有捷径。**

### 6.5 修正"每刀 +3,441 拍"（§5.3 又说错了一次）

§5.3 用"误预测次数"估每刀代价（3,441 @ BTB32 / 2,355 @ BTB64），实测是
**4,798 @ BTB64**。原因见 6.4：切在取指请求发出点上，除误预测本身，还要多付
一次"等老旧响应"的拍。**以后估刀价，必须实测，不许从计数器推。**

### 7.3 新的关键路径换了地方

`P23b` 的最差路径：
```
Startpoint : soc/core/cpu/ex_valid
Endpoint   : soc/core/data_cache/data_mem_16_15/ram64x1d/WE
Logic 3.527 ns (17.2%) / Route 16.947 ns (82.8%)
最大单网  : soc/core/data_cache/_N11365  fanout=64  2.028 ns
```
⇒ 重定向闭环已被切断，**现在卡在 D$ 数据阵列的写使能（store 合并写）**。
下一步要提频率，得分两条：
1. 把 `data_mem` 的写使能寄存一拍（或按 bank 本地生成，消掉 fanout-64 的 2.03 ns）；
2. D$ 4KB 让地址译码变宽（`data_mem_16_*` 切片），可以考虑改成按 way 分块的写口。

### 7.4 还没解决的两件事
