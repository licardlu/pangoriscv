# Plan v15 —— 唯一可行路线：3 发射 + 存储器独立成级（目标 120 MHz @ ≥5.2）

> 结论前置：**2 发射这条路已经走到尽头**（48 MHz / 5.2447，已上板）。
> 本文件给出唯一在算术上成立的另一条路，以及它每个阶段的判定门（go/no-go）。
> 现有交付 `bitstream/pangoriscv_board48_i2700_5p245.sbit` 保持不动，作为保底。

---

## 1. 为什么必须换发射宽度（实测，不是判断）

计分窗口（20 迭代，交付 RTL）测试台自报：

```
SCORE_WINDOW cycles=3,830,610 retires=5,782,458 no_retire=531,147
```

| 量 | 每迭代 | 含义 |
|---|---|---|
| 周期 | 191,530 | |
| 退休指令 | 289,123 | |
| **死周期**（一条都没退休）| **26,557（13.9%）** | 依赖/访存/取指停顿，**加宽发射也救不了** |
| 非死周期 | 164,973 | |
| **非死周期利用率** | **1.753 / 2.0（87.6%）** | 2 发射的余量只剩 12.4% |

⇒ 2 发射最多再挤出约 12%（≈20,000 拍），而那需要把配对率提到接近 100%，
  物理上做不到（mem+mem 被 D$ 单端口禁止）。
⇒ **想再往前，只能增加每周期的发射数。**

## 2. 3 发射需要达到多少（这条决定成败）

`分数 = 20e6 / (每迭代拍数 × 20)`，5.2 要求每迭代 ≤ 192,307 拍。

| 3 发射下非死周期利用率 | 每迭代拍数 | 分数 | 距 5.2 的余量（可用于加深流水）|
|---|---|---|---|
| 1.75（不进步）| 191,770 | 5.21 | +537（没用）|
| 2.00 | 171,119 | 5.84 | **+21,188** |
| **2.20** | **157,977** | **6.33** | **+34,330** |
| 2.40 | 147,025 | 6.80 | +45,282 |

**目标：非死周期利用率 ≥ 2.2/3（73%）**，此时余量 34,330 拍，
足够支付"把 D$ 访问独立成一级"的 29,850 拍（29,850 = 每次 load/store +1 拍）。

⇒ 这是**唯一**能同时满足 5.2 与 120 MHz 的算式：
   `20.58 ns 切成 2 段`（每段 ~10.3 ns）+ `3 发射腾出的 34k 拍预算`。
   若切 3 段（8.3 ns 才真正达标）则需要 ≥2 级，预算需 30k~60k，仍在可达区间上沿。

## 3. 需要改什么（按依赖顺序）

| # | 模块 | 现状 | 目标 | 难度 |
|---|---|---|---|---|
| 1 | 取指带宽 | 每请求 1 个 pair（64 bit）| **每拍 3 条（96 bit）** | 高：I$ 已有 even/odd 两个 bank，可一拍读两个 bank；但要新增"跨 pair 取 1.5 个"的对齐路径 |
| 2 | 译码/派发 | 2 lane | 3 lane，**第 3 lane 先只允许 ALU/branch（不许访存）** | 中：decode 复制一份，配对规则扩成三元组 |
| 3 | 寄存器堆 | 2R2W | **4R2W**（lane2 与 lane0 复用 rs1 端口时退化为 3R）| 中：regfile 用 LUTRAM，加读口 = 复制阵列 |
| 4 | 旁路网络 | 2 路 | 3 路 | 中：是当前关键路径 ① 的主体，加宽会变慢 → 必须与第 7 项同时做 |
| 5 | 退休/异常 | 2 宽有序 | 3 宽有序 + 前缀提交 | 高：异常/陷阱的"只提交较老前缀"逻辑要推广到 3 个 |
| 6 | 配对规则 | `!(lane0_mem && lane1_mem)` | 至多 1 个访存/包 | 低 |
| 7 | **流水深度** | ID+EX+AGU+D$ 一拍 | **D$ 访问独立成级（M2）**，加 store 提交寄存器与 load-after-store 旁路 | 高：D$ 的 store 合并在接受拍完成，延后一拍必须补旁路/停顿 |

**注意**：#4（旁路）与 #7（流水）必须一起做——单独加宽发射会把
当前 20.58 ns 的关键路径推得更长，反而降低频率。

## 4. 分阶段执行与判定门

| 阶段 | 内容 | 成本 | **GO 判据** | 不过怎么办 |
|---|---|---|---|---|
| **S0** | 给 TB 加退休 trace，离线做 3 发射调度，得到 ILP 上界 | 2~3 h，纯仿真 | 上界 ≥ **2.2**/非死周期 | 直接放弃 3 发射，本项目止于 48 MHz |
| **S1** | I$ 一拍送 3 条（issue 仍 2 宽）| 4~6 h | 取指不再是死周期的首位来源（死周期 ≤ 20%）| 先把 I$ 加宽/加 bank |
| **S2** | 3 lane 派发 + 3R regfile + 3 路旁路（**不切流水**）| 2~3 天 | 每迭代 ≤ **170,000** 拍（分数 ≥5.84），CRC/ISA 全过 | 回退到 2 宽 |
| **S3** | D$ 访问独立成级 + store 提交寄存器 + 旁路 | 2~3 天 | 每迭代 ≤ **192,307** 拍，且 CRC/ISA 全过 | 回退 S2 |
| **S4** | 约束 120 MHz（PLL 27×58/13=120.46，`.fdc` 8.3014 ns）| 每次 1.5~4 h | 布线 0 未布通 + WNS ≥0 + 失败端点 0 | 逐级降到 100/90/80 MHz |
| **S5** | 上板：≥10 s、五项 CRC、`Correct operation validated` | 10 min | 全部满足 | 不交付 |

**每一步都必须先用 `python tools/run_coremark_sim.py` 读 `Total ticks`（不是 runner 的 cycles，
见 mistakes-log §58），并跑 `run_isa_e2e.py`（应保持 20/21，case 21 基线即红）。**

## 5. 风险清单（按概率×影响排序）

1. **取指带宽**：3 条/拍要求 I$ 一拍出 96 bit。I$ 现在是 even/odd 两个 bank，
   若两个 bank 正好对应相邻两个 pair，则一拍读两 bank 可行；但 PC 未对齐到 32 bit
   边界时要跨 pair 拼装 → 可能引入 +1 拍，直接吃掉一半收益。**这是最大的未知。**
2. **旁路变慢**：3 路旁路会让关键路径段 ①（现 7.33 ns）变长；若不切流水，频率反降。
3. **面积**：3 宽派发 + 3R regfile 预计 +2,500~4,000 LUT。当前 17.1k，
   会到 20k 以上 ⇒ **密度上去了，布线又成问题**（§70）。可能需要同时把 D$ 降到 2 KB。
4. **ISA 正确性**：3 宽前缀提交的异常语义是最容易出错的地方（§26 的老坑）。

## 8. S0 判定结果（2026-10-23，实测）——结论：**NO-GO for 120 MHz，但存在 ~97 MHz 的前沿**

### 8.1 配对失败原因分解（`--define RV32_DEBUG` 的 PAIRGAP，全程 5,693,904 拍）

```
pair=2,896,669  no_pair=506,441  l1_notok=34,472(mem=0)
l0_alone=22,840  pkt_lduse=404,502  fault=0  nostall=1,524,574
```

| 桶 | 全程 | 每迭代 | 3 发射能否回收 |
|---|---|---|---|
| `pkt_lduse`（lane0 load 挡住 lane1）| 404,502 | 20,225 | **能**（lane2 可放无关指令）|
| `no_pair`（奇地址单条）| 506,441 | 25,322 | 部分（需 96 bit 取指窗口）|
| `l0_alone`（控制指令独占）| 22,840 | 1,142 | 能 |
| `nostall`（前端无指令）| 1,524,574 | 76,229 | **不能**（I$ 缺失/队列空）|

计分窗口内死周期只占 **13.9%**（26,557/迭代），所以窗口内的账与全程不同。

### 8.2 修正一处我自己的错误：加一级流水的代价不是"每条指令 +1 拍"

上一轮我把 ID/EX 分开算成 **+351,000 拍**（1 拍 × 289,123 条指令）——**这在流水线里是错的**。
加一级只增加**延迟**，不增加吞吐；真实代价是：

```
误预测 +1 拍            : 2,314 拍/迭代
load-use 可能加深 1 拍   : 36,041 拍/迭代（load 总次数）
⇒ 一级 ≈ 38,355 拍/迭代（若旁路做得好、load-use 不加深，则只有 2,314）
```

### 8.3 三种情景的最终账

| 方案 | 每迭代拍数 | 分数 | 周期 | 频率 |
|---|---|---|---|---|
| 现状（2 发射 @ 48 MHz）| 190,535 | **5.2447** | 20.581 ns | **48 MHz（已上板）** |
| 3 发射（2.2/拍）+ 1 级（D$ 独立）| 196,332 | 5.09 | 10.29 ns | ~97 MHz |
| 3 发射（2.2/拍）+ 1 级、且 load-use 不加深 | 160,291 | **6.24** | 10.29 ns | ~97 MHz |
| 3 发射 + 2 级（8.3 ns 所需）| 234,687 | **4.26** | 8.30 ns | **120 MHz** |

### 8.4 S0 结论

> **3 发射能把频率前沿推到约 97 MHz，但推不到 120 MHz。**
> 要到 8.30 ns 必须把 20.58 ns 切成 3 段（两级），而每级的真实代价 32k~38k 拍，
> 3 发射腾出的 34k 预算只够付**一级**。
> 若强行切两级：分数 4.26 —— **120 MHz 与 ≥5.2 不能同时成立，这一结论在修正代价模型后依然成立。**

**因此本计划的执行判据是：**
- 若目标调整为"**约 97 MHz 且分数 ≥5.1**" → 走 S1~S5，GO。
- 若目标坚持"**120 MHz 且分数 ≥5.2**" → **NO-GO**，任何实现都无法同时满足。
